## 에이전트 기억은 '많이'가 아니라 '고를 줄 알고, 틀리면 고치게' — 앤트로픽 실험에서 나온 운영 원칙

### 앤트로픽의 에이전트 기억 설계 — 무엇을 기억할지는 강한 모델에 맡기고, 세션 사이 '드리밍'으로 틀린 메모를 원기록과 대조해 고치며, 매 세션 첫 기억은 색인처럼 작게

앤트로픽이 엔지니어링 블로그에 에이전트 기억의 구성 요소와 실험 결과를 정리했다. 사람의 뇌가 해마로 경험을 바로 기록하고 잠자는 동안 오래 남길 지식만 신피질로 옮기듯, Claude도 일하는 동안 대화 기록과 메모를 남기고 세션 사이에 그 기록을 다시 읽어 실수를 고치고 새 노트를 만든다. 이 과정이 **드리밍(Dreaming)**으로, Letta·UC 버클리의 '수면 시간 연산(sleep-time compute)'에서 출발했다. 기억은 ①대화 기록, ②Claude가 쓴 메모, ③위키 같은 정리본, ④매 세션 처음에 넣는 맥락의 네 층으로 나뉜다.

- **기억은 '예측'이다**: 규칙 하나를 적는 건 그 패턴이 나중에 다시 필요하리라 내다보는 일이다. 질문마다 새 세션으로 시작하고 기억 폴더만 이어받는 DB 질의 과제(CL-Bench)에서 Sonnet 4.6은 틀린 이유에 대한 추측만 흩어 놓았고, Opus 4.7은 확인한 사실과 미확인 사실을 나눠 적었으며, Opus 5부터는 규칙·근거·함정 경고까지 적어 점수가 기억 없이 0.564 → 기억 사용 시 0.828로 올랐다.
- **많이 적는다고 좋은 게 아니다**: 포켓몬 레드 1만 스텝 지점에서 Sonnet 3.7은 전투·아이템·캐릭터마다 파일을 만들어 225개 폴더에 413개 파일을 쌓고 배지 1개에 그쳤다. 17스텝 동안 파일 6개를 만들고 9개를 지우면서 게임은 한 칸도 진행하지 않은 구간도 있었다. Fable 5는 파일 10개만 남기고 배지 4개를 땄다. 화면에 늘 보이는 돈·위치는 적지 않고 현재 목표, 체육관 공략 계획, 직접 시험해 본 규칙(예: 몬스터볼이 3번 넘게 빗나가면 던지는 타이밍을 바꿔라)만 적었다.
- **어떻게 쓰라고 시킬까 — 모델 세대에 따라 반대**: 강한 모델에는 기억이 '무엇을 위한 것인지'만 알려주고 방법은 맡기는 게 나았다. "실패만 기록하라"는 규칙을 걸자 Opus 5의 기억 이득이 0.234 줄었다. 반대로 Sonnet 4.6은 기억 파일을 잘 안 읽었는데, "답하기 전에 기억을 읽고 세운 가설을 직접 시험하라"고 시키자 0.330 → 0.641로 거의 두 배가 됐다. Sonnet 5는 시키지 않아도 10번 중 9번은 기억부터 읽었다.
- **드리밍이 실제로 바꾼 장면**: Claude가 달맞이산 동굴에서 포켓몬센터 위치를 잘못 적고 "달맞이산 완료"라고 메모한 채 낭떠러지로 세 번 떨어진 뒤 포기한 실행이 있었다. 드리밍을 돌리자 메모를 대화 기록과 대조해 오류를 고쳤고, 고친 메모로 시작한 실행은 1,935번째 행동에서 다음 도시에 도착했다.
- **위키는 엮어서 판단해야 할 때 이득**: 5월 인수한 Stainless의 내부 문서 약 35만 개(4억 2천만 토큰)로 Opus 5에게 128세션 동안 위키를 쌓게 하자, 위키만으로 채운 채점 기준이 13% → 48%, 검색+위키는 61%(검색만 53%)였고 질문당 약 2만 토큰을 아꼈다. 여러 문서를 엮고 계산해야 하는 기업 합병 문항에선 위키 87% 대 검색 73%였지만, 한 문서에서 바로 찾히는 법률 브리프 과제에선 차이가 없었고 위키가 원문보다 1.77배 커진 경우도 있었다.
- **여러 에이전트가 한 파일에 쓰면 사라진다**: 계약서 브리프 과제에서 에이전트 여럿이 표 하나에 동시에 기록하자 서로의 줄을 덮어써 채점 대상 사실 57개 중 41개(72%)만 남았다. Claude가 실패를 돌아보고 "계약서마다 에이전트 하나가 페이지 하나, 조건은 요약하지 말고 원문 그대로"로 지침을 고치자 57개 전부 남았다.
- **세션 첫 기억은 작게**: 매 세션 처음 넣는 기억은 색인처럼 작게 유지하라고 강조했다. Claude Code의 자동 기억도 `MEMORY.md`에서 처음 200줄 또는 25KB만 읽는다. 두 번째 드리밍에서는 존재하지 않는 페이지를 가리키던 링크 9개를 실제 문서로 고치고 색인 페이지를 포함해 3개 페이지를 더했다.

드리밍은 5월 Code with Claude에서 Claude Managed Agents의 리서치 프리뷰 기능으로 먼저 나왔고(모델 가중치는 바꾸지 않고 다음 세션이 읽는 기억 저장소만 고친다), 이후 ChatGPT·Devin도 비슷한 기억 정리 기능을 내놨다. 외부 논평에서는 세션 기록에 에이전트가 쓰지 않은 내용도 섞여 있어 자동 정리가 나쁜 습관을 굳힐 수 있다는 우려도 나온다. choi.openai는 에이전트 경쟁이 "얼마나 많이 기억하느냐보다 무엇을 버리고 언제 다시 확인하느냐"에서 갈릴 것이라고 정리했다.

> 🔧 **적용 포인트** — Claude Code 자동 기억(`MEMORY.md`)은 앞 200줄·25KB만 읽히니, 지금처럼 한 줄 색인 + 개별 파일 구조를 유지하고 색인 줄을 짧게 관리한다. 화면이나 코드에서 바로 확인되는 사실(파일 구조, 커밋 내역)은 적지 말고 "직접 시험해서 얻은 규칙과 그 이유"만 남긴다.
> 가끔 세션을 마칠 때 "기억 파일을 최근 작업 기록·git log와 대조해 틀린 내용과 깨진 [[링크]]를 고쳐라"라고 시키면 수동 드리밍이 된다(`consolidate-memory` 스킬이 같은 역할).
> 서브에이전트 여러 개가 같은 노트를 동시에 고치게 하지 말고, 에이전트마다 쓸 파일을 하나씩 나눠 준다.

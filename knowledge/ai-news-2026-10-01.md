## 구글이 프런티어 경쟁에 다시 들어왔고, 오픈웨이트와 소형 특화 모델이 그 아래층을 채운다

DevDay 다음 날은 구글 차례였다. Gemini 4 Argon은 벤치마크로는 선두권에 섰지만 접근은 사이버 방어 파트너로 제한됐다. 같은 날 앤트로픽은 누구나 받을 수 있는 중국 오픈웨이트 모델이 자사 비공개 모델에 근접한 공격 능력을 갖췄다고 경고했다. 아래층에서는 음성 전용 확산 모델과 로컬 판단 모델처럼 "한 가지를 빠르게" 하는 모델들이 늘고 있다.

### 구글 Gemini 4 Argon 공개 — 출력 한도 100만 토큰, DeepSWE 77.9%·Vals 1위지만 일반 개발자는 아직 못 쓴다

구글 딥마인드가 9월 30일(현지) 차세대 프런티어 모델 Gemini 4 Argon을 발표했다. 실제 소프트웨어 엔지니어링, 법률·금융 같은 기업 지식 업무, 사이버 방어를 겨냥한 모델이다. 가장 눈에 띄는 변화는 **출력 한도가 64K에서 100만 토큰으로 약 15.6배 늘어난 것**이다. 입력 컨텍스트와 별개로, 한 번의 응답 안에서 코드를 읽고 고치고 다시 측정하는 긴 작업을 끊지 않고 이어가게 하려는 설계다.

choi.openai가 14개 글로 정리한 벤치마크를 개발자 관점에서 추리면 다음과 같다.

- **코딩**: 구글 공식 블로그 기준 DeepSWE v1.1 77.9%로 최고점이다. [어제 나온 GPT-6.1 Sol](ai-news-2026-09-30.md)의 high 설정 75.2%보다 높다. Vals AI의 Vibe Code Bench(앱 제작)는 요구 기능 테스트 91.91% 통과로 2위였다.
- **약점도 분명하다**: Vals Terminal-Bench 4.0에서 Argon은 57.58%로, 거부 후 다른 모델이 대신한 작업을 실패로 쳐도 62.63%인 [Sonnet 5.5](ai-news-2026-09-29.md)에 밀렸다. 기존 프로그램의 동작을 통째로 재현하는 ProgramBench에서는 숨겨진 테스트를 모두 통과한 프로그램이 200개 중 5개로, Opus 5.5(37개)와 차이가 컸다. 새 기능을 붙이는 일과 기존 소프트웨어를 빈틈없이 복원하는 일에서 강점이 갈린다.
- **종합·실무**: Artificial Analysis 지수는 53점으로 GPT-6 Astra·Claude Fable 5.1과 같고 Opus 5.5(58점)에는 뒤진다. 대신 과제당 비용이 Argon 1.99달러, Astra 3.26달러, Fable 5.1 7.63달러로 가장 낮다. Vals 실무 종합 지수는 68.90%로 1위였고, 정규 단가 기준 테스트당 비용은 Argon 15.68달러, Opus 5.5 32.14달러였다. Arena 사용자 선호도(문체 보정 종합)도 Argon High 1,525점으로 Opus 5.5 High(1,504점)를 앞섰다.
- **가격**: 출시 초기 100만 토큰당 입력 2달러·출력 10달러, 캐시 입력은 95% 할인이다. 초기 기간이 끝나면 입력 4달러·출력 20달러로 두 배가 되는데, 종료 시점은 공개되지 않았다.

구글은 내부 활용 사례도 공개했다. 여러 Argon 에이전트가 서버 전체의 성능·메모리 기록을 분석해 데이터센터 메모리 300TiB 이상을 확보했다. C/C++ 코드베이스를 Rust로 옮기는 작업에도 쓰이고 있는데, re2·libgav1 같은 핵심 라이브러리부터 80만 줄이 넘는 Fuchsia의 Zircon 커널까지 포함된다. 영상 디코더 libgav1에서는 기존 Rust 이식본의 SIMD 코드 3만 2천 줄을 컴파일러가 자동 벡터화할 수 있는 안전한 Rust로 바꿔, 같은 출력에 2.7배 빠른 결과를 냈다고 한다. 측정 → 컴파일 결과 분석 → 수정 루프를 모델이 반복한 사례다.

문제는 접근이다. 지금은 구글의 Fairwind 프로그램에 속한 검증된 사이버 방어 파트너에게만 풀렸고, 이후 유료 API 고객과 Google AI Ultra 구독자부터 확대한다. 구체적인 날짜는 없다. 방어 파트너에게는 사이버 가드레일을 제거한 버전을 주고, 그동안 일반 공개용 안전장치를 강화한다는 방식이다. 같은 날 Bloomberg는 구글 내부 직원들 사이에서 "벤치마크는 좋지만 코딩 등 실제 업무 체감은 기대에 못 미친다"는 회의론이 있다고 보도했다. 이 소식을 전한 choi.openai 글 댓글에서도 "같은 버그픽스 5건을 Argon과 지금 쓰는 모델로 돌려 사람이 끼어든 횟수를 세 보면 된다"는 현실적인 제안이 나왔다.

> 🔧 **적용 포인트** — 당장 쓸 수 없는 모델이라 지금 할 일은 없다. 공개되면 벤치마크 대신 내 저장소에서 직접 비교하자. 이 포트폴리오에서 실제로 했던 작업 3~5건(예: R3F 씬 버그 수정, 도슨트 음성 파이프라인 수정)을 Claude Code와 Argon에 똑같이 맡기고, 끝까지 가는 동안 사람이 몇 번 끼어들었는지와 총비용을 기록하면 된다. 100만 토큰 출력은 대규모 마이그레이션이나 리팩터링처럼 한 번에 길게 써야 하는 작업에서 의미가 있다.

### 앤트로픽 레드팀 "오픈웨이트 GLM-5.3, Mythos Preview급 공격 코드 작성" — 안전장치는 약 4,400달러로 제거

앤트로픽 프런티어 레드팀이 9월 29일 중국 Z.ai(옛 Zhipu AI)의 GLM-5.3 분석 보고서를 냈다. GLM-5.3은 8월 14일 출시된 뒤 8월 말 가중치까지 공개된, 누구나 자기 서버에서 돌릴 수 있는 모델이다. 앤트로픽은 이 모델을 "공격자가 쓸 수 있는 사이버 능력의 의미 있는 단계 변화"라고 규정했다.

- **능력**: 크롬 V8 엔진의 알려진 취약점 41개로 동작하는 공격 코드를 만들게 하는 ExploitBench에서, 410번 시도 중 GLM-5.3이 50번(약 12%), Claude Mythos Preview가 56번(약 14%) 성공했다. 앤트로픽 내부 바이너리 공격 평가에서도 4% 대 6%로 근접했다. 직전 세대인 GLM-5.2와 Claude Opus 4.6은 한 번도 성공하지 못했다. 미국 NIST 산하 CAISI도 9월 17일 GLM-5.3을 지금까지 나온 오픈웨이트 모델 중 사이버 능력이 가장 높다고 평가하며, 미국 최전선과의 격차를 약 4개월로 봤다.
- **안전장치**: "승인된 레드팀 에이전트"라고 거짓 주장하는 정도의 간단한 수법으로 거절을 64~100% 우회할 수 있었다. 안전장치를 아예 제거하는 데는 약 2,200 GPU시간(약 4,400달러)이 들었고, 거절률은 90%대에서 3% 안팎으로 떨어진 반면 과학·사이버 과제 성능은 거의 그대로 남았다. 거절을 걷어낸 변형판은 출시 며칠 만에 공개 저장소에 올라왔고, 9월 초에는 이를 서비스로 내놓은 곳(Abliteration.ai)도 나왔다.

반론도 있다. Ai2에서 오픈 모델 Olmo를 이끌었던 네이선 램버트는 문서로 확인된 사이버 공격에는 오히려 폐쇄형 모델이 더 많이 쓰였다고 지적했다. 실제로 앤트로픽의 9월 위협 인텔리전스 보고서에 나온 공격자들은 모두 Claude Haiku·Sonnet·Opus를 썼다. 다만 그건 앤트로픽이 자기 API에서 벌어진 일을 볼 수 있었기 때문이고, 내려받은 모델로 한 공격은 누구에게도 보이지 않는다. 반대로 폐쇄형 안전장치가 방어자를 막은 사례도 있다. 7월 허깅페이스 침해 사고 조사팀은 공격 기록 분석에 Claude Opus와 Fable을 먼저 썼지만 상당 부분이 거절돼, 결국 GLM-5.2를 자체 서버에 올려 분석을 이어갔다.

업계는 요청마다 거절하는 방식에서 "누가 쓰는지 먼저 확인하는" 방식으로 옮겨가는 중이다. 오픈AI는 심사를 통과한 방어자에게 거절을 줄인 GPT-5.6-Cyber를 주고, 앤트로픽도 검증된 방어자는 Mythos 5.1까지 쓸 수 있다고 밝혔다. 위의 Gemini 4 Argon이 Fairwind 파트너에게 먼저 풀린 것도 같은 흐름이다.

> 🔧 **적용 포인트** — 개인 프로젝트에 미치는 직접적인 영향은 "자동화된 취약점 탐색 비용이 계속 내려간다"는 점이다. 공개 저장소인 이 포트폴리오에서 `/api/docent/*` 같은 서버 라우트의 입력 검증, API 키·`.env` 노출, 의존성 취약점(`npm audit`)을 정기적으로 점검하자. PR 전에 Claude Code의 `/security-review`를 돌리는 습관이 가장 싼 대응이다.

### Inception Mercury Voice — 확산 언어 모델로 음성 에이전트 첫 답변 320ms, 기업 고객 한정

토큰을 한 번에 여러 개씩 병렬로 생성하는 확산 언어 모델(dLLM)을 만드는 Inception이 음성 에이전트 전용 모델 Mercury Voice를 공개했다. 음성 대화에서는 사람이 기다린다고 느끼지 않으려면 약 500ms 안에 반응해야 하는데, Mercury Voice는 실제 고객센터 프롬프트 기준으로 **첫 답변 토큰까지 중앙값 320ms, p95 750ms**를 냈다고 밝혔다. 추론을 끈 GPT-6 Luna보다 5.9배 빠르다는 설명이다.

τ³-bench(통신·소매·항공), IFBench, BFCL v4를 묶은 에이전트·대화 평가에서 GPT-6 Luna, Gemma 4 31B, GLM-5.3-Flash, Qwen3.5-397B, Gemini 3.5 Flash-Lite보다 높았다고 하지만, 일부 매체는 개별 점수가 공개되지 않았다는 점을 지적했다. 도구 호출과 긴 시스템 프롬프트 준수, 추론 강도 3단계(low·medium·high)를 지원하고 컨텍스트는 128K, 출력은 최대 5만 토큰이다. 가격은 정가 100만 토큰당 입력 0.40달러·출력 1.50달러이고, 출시 할인 기간에는 절반이다. 대화 1분당 약 0.009달러 수준이라고 한다. 다만 현재는 **기업 고객 한정**으로 OpenAI 호환 API를 통해 제공되며, LiveKit·Pipecat·Vapi·Retell과 연동된다.

> 🔧 **적용 포인트** — 도슨트 음성 파이프라인에서 체감 지연은 "LLM 첫 토큰 + 첫 문장 TTS 합성"의 합이다. Mercury Voice를 당장 쓸 수는 없지만, 측정 기준으로 삼을 만하다. 지금 쓰는 LLM의 첫 토큰 시간과 Supertonic 첫 음성까지의 시간을 따로 계측해, 둘 중 어느 쪽이 500ms 예산을 잡아먹는지 먼저 확인하자. LLM 쪽이 병목이면 음성 응답에만 작은·빠른 모델을 따로 쓰는 분리가 효과가 크다. 이 모델의 API는 OpenAI 호환이라, 공개되면 base URL만 바꿔 바로 비교할 수 있다.

### Ollama 0.35 로컬 판단 모델 API /v1/systemone, 리퀴드 AI d1까지 — 'Jev형' 판단 레이어가 로컬·오픈으로 번진다

[어제 다룬 오픈AI Decisions API](ai-news-2026-09-30.md)의 후속 흐름이다. TypeSafe의 Jev가 연 "긴 답변 대신 정해진 선택지 중 하나를 빠르게 고르는" 판단 모델 범주에 로컬 실행과 오픈 모델이 함께 들어왔다.

- **Ollama 0.35**(9월 29일): Jev API 형식을 따르는 `/v1/systemone` 엔드포인트를 추가했다. 요청은 입력 텍스트인 `state`와 `questions` 객체로 구성되고, 응답은 질문 유형(선택·점수 등)별 답과 확률·신뢰도를 돌려준다. 지원 모델은 Bespoke Labs의 Nimble(9B)과 Together AI의 실험 모델 Tev1(4B, 0.8B) 세 개다. `ollama pull nimble`로 받아 바로 쓸 수 있고, M5 Max 로컬에서 Nimble 9B가 결정 1건에 평균 91ms가 걸렸다. 네트워크 왕복이 없다는 게 핵심이다. Apple Silicon용 MLX 가속은 추후 지원 예정이다.
- **리퀴드 AI d1**: 문장을 생성하지 않고 분류·선택·점수화 결과를 보정된 확률로 한 번에 돌려준다. 출력 토큰은 0이다. Hugging Face Decision Index에서 Jev를 처음으로 넘었다고 밝혔고, 다국어 평가와 프롬프트 인젝션 대응, 긴 입력 처리에서 강점을 내세운다. 호스팅 API에서 `d1:free`라는 모델명으로 바로 쓸 수 있다.

2주 사이에 Jev(호스팅), 오픈AI Decisions API(호스팅), Ollama(로컬), 리퀴드 d1(호스팅·무료 티어)이 같은 형태로 나왔다. 문의 분류, 모델 라우팅, 콘텐츠 검수처럼 "답이 정해진 판단"을 범용 LLM 호출에서 떼어내는 구조가 표준이 되어 가는 중이다.

> 🔧 **적용 포인트** — 도슨트 챗봇에서 "이 질문이 어떤 프로젝트에 관한 것인가", "RAG 검색이 필요한가, 잡담인가" 같은 라우팅 판단을 매번 메인 LLM에 맡기고 있다면, 이 부분만 판단 모델로 떼어내 보자. 로컬 개발 중에는 Ollama 0.35 + Nimble로 `/v1/systemone`을 쳐서 정확도와 지연을 측정하고, 배포 환경에서는 같은 질문 스키마를 d1이나 Decisions API로 옮기면 된다. 질문 스키마를 공급자와 무관한 형태로 두는 것이 핵심이다.

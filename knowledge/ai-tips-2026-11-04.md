## 에이전트에게 더 많이 맡길수록 '내가 이해한 만큼만' 내보낸다 — 검토 습관과 3D 에셋 파이프라인

### 애디 오스마니 'Critical thinking when agents do the work' — 감당할 수 있는 것보다 많이 만들면 검토가 아니라 바람일 뿐, 묻기 전에 가설을 세우고 머지 전 퀴즈를 통과하라

구글에서 14년 넘게 크롬 개발자 도구를 이끌다 앤트로픽 Claude Code 팀으로 옮긴 애디 오스마니가 쓴 장문으로, 하루 만에 조회수 20만 회를 넘겼다. 그는 에이전트 여러 개를 동시에 돌리는 방식을 지지한다고 먼저 밝히고, 문제는 모델이 좋아질수록 눈에 띄는 오류가 줄어 다시 들여다볼 이유가 사라진다는 점이라고 짚는다. 테스트는 초록불이고 코드는 깔끔하니 600줄짜리 변경도 구조만 훑고 승인하게 된다. 그는 이를 **'인지적 항복(cognitive surrender)'**이라 부르며 이렇게 적었다. "감당할 수 있는 것보다 많이 만들고 있다면 더는 검토하고 있는 게 아니다. 바라고 있을 뿐이다."

- **이해 부채**: 그 순간에는 문제가 보이지 않다가, 시스템을 고쳐야 할 때가 와서야 아무도 이해하지 못한다는 사실이 드러난다. 큰 코드베이스 전체를 머릿속에 담을 수는 없으니, Claude Code 팀도 필요한 부분을 Claude에게 설명하게 해서 이해를 그때그때 다시 쌓는다. 기준선은 하나다 — **에이전트 도움을 받아도 답을 설명하지 못하면 그 일의 주인 자리를 넘긴 것**이다.
- **근거**: 앤트로픽 내부 연구의 '감독의 역설'(Claude를 감독하려면 AI를 과하게 쓰면서 약해질 수 있는 코딩 실력이 필요하다), 그리고 1월 실험이다. 처음 보는 라이브러리(Trio)로 기능을 만들게 했을 때 AI 도움 그룹은 직후 퀴즈에서 17% 낮았지만, 사용 방식별로 갈렸다 — 코드를 통째로 맡긴 사람 39%, 오류 수정까지 기댄 사람 24%, 개념만 묻고 직접 푼 사람 65%, 받은 코드를 "왜 이렇게 짰냐"고 되물은 사람 86%.
- **스스로 던지는 질문**: 묻기 전에 내 가설을 먼저 세운다(잘 쓴 답을 한 번 읽으면 다른 가능성을 떠올리기 어렵다). "이게 틀리려면 무엇이 사실이어야 하나"를 묻는다. 모델이 스스로 매긴 확신보다 실제로 돌려 볼 수 있는 시험이 훨씬 쓸모 있다.
- **습관**: 일주일에 한 번은 에이전트 없이 코드를 조금 짠다. 한 달에 한 번은 손 놓은 일을 적어 계속 놓아도 되는지 정한다. Claude에게 변경 보고서 끝에 퀴즈를 내게 하고 **만점을 받아야 머지**한다. AI가 없다면 얼마나 헤맬지 가늠해 본다.
- **오케스트레이션 세금**: 에이전트가 만들어 내는 양과 내가 이름을 걸 수 있는 양의 차이다. 끝낸 작업이 검토 속도보다 빨리 쌓이면 세션을 늘려도 소용없으니, 자동 검사를 조여 사람이 볼 일을 줄이거나 속도를 늦춘다. 일과 검사 대부분은 넘겨도 책임은 넘길 수 없다는 게 결론이다.

독자 댓글에서는 "동시에 시키는 건 최대 3개, 실제 병행은 2개까지로 줄였다"는 현업 경험과, "기술 부채가 이해 부채로 바뀌었다"는 반응이 많은 공감을 받았다.

> 🔧 **적용 포인트** — 포트폴리오 작업에서 Claude Code가 큰 diff(셰이더·스크롤 타임라인 등)를 내면, 머지 전에 "이 변경에 대한 퀴즈 3문제를 내 줘"를 붙이고 답하지 못하면 해당 부분 설명부터 요청하는 루틴을 CLAUDE.md에 넣어볼 만하다.
> 성능 이슈(예: 셰이더 컴파일·휠 속도)는 "모델이 괜찮다고 한 것"보다 prod 빌드에서 직접 재는 시험을 기준으로 삼는다는 원칙과도 맞닿아 있다.

### Scenario Agent Skills — Claude Code·Codex·Cursor에 이미지·영상·3D 생성 스킬 약 80개와 Blender·Unity 등 전문 툴 스킬을 붙이는 MIT 저장소, 생성 전 비용부터 보여 준다

생성형 에셋 플랫폼 Scenario가 AI 코딩 에이전트에서 3D·게임 작업을 이어서 할 수 있게 해 주는 스킬 묶음 `scenario-labs/skills`를 오픈소스(MIT)로 공개했다. choi.openai는 이를 "3D OS"로 소개하며 스케치 한 장 → 3D 모델 → 리깅 → 게임 엔진용 내보내기까지 연결된다고 정리했다. 저장소 README를 직접 확인한 내용은 이렇다.

- **구성**: Scenario MCP 서버를 통해 이미지·영상·오디오·텍스처·스카이박스·3D 에셋을 만드는 Scenario 스킬 약 80개, 그리고 ZBrush·Blender·Maya·Unreal·Unity·Godot·Roblox Studio를 직접 다루는 '전문 툴' 스킬 약 87개가 있다. Agent Skills 형식이라 Claude Code·Cursor·Codex·Copilot 등에서 쓴다.
- **설치**: `npx skills add scenario-labs/skills`(대화형 선택) 또는 `--skill scenario`로 개별 설치. 생성 스킬은 `claude mcp add --transport http scenario https://mcp.scenario.com/mcp` 후 OAuth/API 키 로그인이 필요하다.
- **로컬 실행 범위**: 전문 툴 스킬은 Scenario MCP가 아니라 설치된 앱(예: Blender)을 쓴다. choi.openai가 말한 'Blender 스킬은 API 키 없이 로컬 실행'은 이 부분이다. 실제 생성(이미지→3D 등)은 Scenario 크레딧을 쓴다.
- **비용 관리**: 생성 전 드라이런으로 가격부터 보여 주고, 모델별 비용 등급과 팀원별 지출 상한을 둔다. 별도의 Blender 플러그인 README는 비용 미리보기 때 프롬프트와 파라미터가 Scenario API로 전송된다고 적어 두었다.
- **내보내기**: `scenario-3d` 스킬은 GLB·FBX 다운로드를 지원하고, Blender 내보내기 프리셋에 three.js용 GLB가 포함된다.

> 🔧 **적용 포인트** — R3F 포트폴리오에서 소품·흉상 같은 3D 에셋이 필요할 때, Claude Code에 Blender 전문 툴 스킬을 붙여 "폴리곤 수 줄이기 → 텍스처 베이크 → GLB 내보내기"를 맡기면 `gltfjsx`로 바로 컴포넌트화하는 파이프라인을 만들 수 있다.
> 생성 스킬은 유료 크레딧이니 드라이런 가격 확인을 켜 두고, 결과 GLB는 기존 픽셀·용량 예산(첫 JS·텍스처 크기)에 맞는지 Draco/meshopt 압축 후 확인한다.

## 모델을 다시 학습시키는 대신, 모델을 둘러싼 '하네스'를 에이전트가 직접 고친다

에이전트 성능은 모델 가중치만큼 그 주변의 프롬프트·도구·메모리·스킬 구성(하네스)에 좌우된다. 구글 리서치가 이 하네스를 에이전트 스스로 고치게 하는 프레임워크를 Apache 2.0으로 공개했다.

### 구글 리서치 Harness² 오픈소스 — 모델은 그대로 두고 에이전트가 시스템 프롬프트·도구·메모리·스킬 등 8개 구성요소를 스스로 고친다, 한 단계로 최대 11.8%p 향상

choi.openai가 구글 리서치의 Harness² 공개를 전했다. 문서 작성 중 문제가 생기면 지침이나 도구 설정을 바꿔 다시 시도하는 식이고, 재학습 없이 작업 경험을 다음 작업에 이어 쓴다는 설명이다. GitHub README로 확인한 내용은 다음과 같다.

- **고치는 대상**: 시스템 프롬프트, 가드레일, 메모리, 도구 사용 지침, 서브에이전트, 스킬, 스크립트, 플러그인의 8개 구성요소다. 모델 가중치는 건드리지 않는다.
- **두 겹의 재귀**: *작업 수준 재귀*는 지금 하는 작업에 맞춰 하네스를 다듬는다. Propose–Probe–Compose 단계로, 수정안을 제안하고 같은 작업에 시험 삼아 돌려본 뒤 실행 결과의 차이로 더 나은 하네스를 조합한다. 정답(ground truth) 피드백 없이 돈다는 점이 핵심이다. *하네스 개선 수준 재귀*는 작업이 끝날 때마다 채택된 하네스와 근거가 있는 교훈을 쌓아 다음 개선에 쓴다.
- **탐색 방식**: `--mode parallel`은 일반용 K개와 도메인용 K개 후보를 동시에 시험한다. `--mode sequential`은 K번 연속으로 다듬는다.
- **결과**: GLM-5와 Gemini 3.5 Flash에 단 한 단계만 적용해도, 3개 벤치마크·4개 모델-하네스 조합 모두에서 기본 하네스보다 좋아졌다. WorkBuddy-Bench(사무·웹·코드)는 최대 11.5점, JobBench(전문 업무)는 4.5점, LAB(법률 업무)는 부분 통과율 11.8%p 올랐다. 작업 수준 재귀에 예산을 더 주면 더 오른다. 실행기는 기본이 OpenCode이고 Codex도 지원한다.
- **써보려면**: Linux, Python 3.12, uv가 필요하다. 자격증명 없이 `harness2-demo --output runs/demo --k 2`로 데모를 돌릴 수 있다. 실제 모델 실행에는 Node.js 20+와 Google Cloud CLI·Vertex AI 설정이 필요하고, API 비용이 든다. 결과는 `runs/`에 쌓이며 같은 명령을 다시 실행하면 이어서 돈다. 구글의 공식 지원 제품은 아니다.
- **맥락**: 구글 클라우드 AI 리서치는 9월에도 하네스 자기개선 프레임워크 RRSI를 내면서 '하네스 진화가 벤치마크를 외워버리는 과적합'을 핵심 문제로 짚었다. Harness²의 수치도 이 세 벤치마크 안에서 나온 것이다. 일반 개발 작업에서 같은 폭으로 오를지는 아직 검증되지 않았다.

## PR 리뷰는 정식 서비스가 됐고, 음성 에이전트는 말이 끝나기 전에 움직이며, 코드는 그대로 신경망이 된다

앤트로픽의 PR 자동 리뷰가 연구 프리뷰를 끝내고 Team·Enterprise 플랜에 정식으로 열렸다. 오픈AI는 실시간 음성 모델 GPT-Live가 판단 전용 Decisions API를 중간 서버 없이 직접 부르게 했다. 사용자의 말이 끝나기 전에 차량 제어나 아바타 표정을 정할 수 있다. 한편 Cheng Lou는 일반 JavaScript를 학습 없이 신경망으로 바꾸는 실험 프로젝트를 공개했다.

### Claude Code Review 정식 출시 — 리뷰 시간 약 20분에서 6~10분으로, 저장소마다 Quick·Standard·Deep 단계를 고른다

Claude Code를 만든 Boris Cherny가 Code Review의 정식 출시(GA)를 알렸다. 그는 자기 PR 전부에 이 리뷰를 돌리고 있고, 이것 없이는 생산성을 상상할 수 없다고 썼다. 앤트로픽 공지(10월 15일, 미국 시간)와 공식 문서로 확인한 내용은 다음과 같다.

- **대상**: Claude Team·Enterprise 조직, GitHub 저장소만 지원한다(GitHub Enterprise Server 포함). 조직 Owner가 Claude Code 설정에서 켜고, Claude GitHub App을 설치한 뒤 저장소를 고른다. 개발자 쪽 설정은 필요 없다. Zero Data Retention·HIPAA 구성·고객 관리 암호화 키(CMEK)를 쓰는 조직은 아직 쓸 수 없다.
- **속도와 품질**: 대부분의 리뷰가 프리뷰 때보다 약 3배 빨라졌다. 약 20분 걸리던 리뷰가 6~10분에 끝난다. 결과는 '무엇이 문제인지, 어떤 조건에서 터지는지, 어떻게 고치는지'를 짧게 적는 형식으로 바뀌었다.
- **리뷰 단계**: Quick(가장 빠르고 저렴), Standard(기본값), Deep(가장 꼼꼼하고 비쌈) 중 하나를 조직 기본값으로 정하고, 저장소마다 따로 지정할 수 있다. 모델은 직접 고를 수 없고, 꼼꼼함은 이 단계로만 조절한다.
- **동작 방식**: 여러 에이전트가 diff와 주변 코드를 병렬로 읽어 후보를 찾는다. 검증 단계가 오탐을 걸러내고, 남은 지적을 중복 제거해 심각도 순으로 올린다. 결과는 해당 줄의 인라인 코멘트와 `Claude Code Review` 체크 런으로 남는다. 리뷰는 PR을 승인하거나 막지 않으며, 코드를 빌드하거나 실행하지 않고 읽기만 한다.
- **실행 시점**: 저장소마다 'PR을 열 때 한 번', '푸시할 때마다', '요청할 때만' 중에서 고른다. 쓰기 권한이 있는 사람이 PR에 `@claude review`라고 달면 언제든 다시 돌릴 수 있다. 무엇을 지적할지는 저장소의 `REVIEW.md`·`CLAUDE.md`로 조정한다. `REVIEW.md`는 PR 브랜치가 아니라 기본 브랜치의 것만 읽는다. PR 작성자가 리뷰 지침을 몰래 바꿀 수 없게 막아둔 셈이다.
- **비용**: 단계가 깊을수록 비싸다는 것 외에 리뷰당 가격은 공지에 없다. 문서에는 월 지출 한도 설정이 따로 있다. 자격이 되는 Enterprise 조직은 2027년 1월 15일까지 최소 1만 달러어치 Code Review 크레딧을 받을 수 있고, 크레딧은 받은 날부터 30일 뒤 만료된다.

> 🔧 **적용 포인트** — 개인 플랜이라 관리형 Code Review는 쓸 수 없다. 대신 문서의 비교표대로 어느 플랜에서나 되는 로컬 `/code-review`(+ 노력 단계)나 GitHub Actions 연동이 대안이다. 이번 GA에서 가져올 것은 운영 패턴이다. 포트폴리오 저장소에 `REVIEW.md`를 두고 "R3F 컴포넌트의 dispose 누락, GSAP·Lenis 이벤트 정리 누락, `useFrame` 안의 할당" 같은 이 스택 특유의 실수를 지적 기준으로 적어 두자. 그러면 로컬 리뷰든 CI 리뷰든 같은 기준으로 돌릴 수 있다. 실제로 지적이 나오는 수준인지는 기존 브랜치 diff 한두 개로 먼저 시험해보는 게 좋다.

### GPT-Live가 Decisions API를 직접 호출 — 사용자가 말하는 도중에 동작과 아바타 표정·몸짓을 정한다

[10/7 퍼블릭 베타로 열린 Decisions API](ai-news-2026-10-07.md)의 후속이다. choi.openai는 오픈AI가 실시간 음성 모델 GPT-Live와 Decisions API를 직접 연결하는 기능을 공개했다고 전했다. 사용자가 말을 끝내기 전에 동작을 정할 수 있고, 가상 캐릭터의 표정과 몸짓도 실시간으로 바꿀 수 있다는 내용이다. 오픈AI 공식 가이드(Connect voice to Decisions)로 확인한 구조는 다음과 같다.

- **두 가지 위임 방식**: 기본인 *네이티브 위임*은 Live가 Decisions를 직접 부른다. 앱 서버를 한 번 거치는 왕복이 사라진다. *커스텀 위임*은 Live가 앱에 알리고, 앱이 Decisions를 부르는 기존 방식이다. 어느 쪽이든 실제 동작(온도 변경 등)은 앱이 실행한다. 여러 단계가 필요한 요청은 앱 서버가 Responses API와 함수 도구로 처리한 뒤 결과를 Live에 돌려준다.
- **트랜스크립트 트리거**: `session.triggers`에 `type: "decisions"` 항목을 두면, 사용자 발화의 입력 트랜스크립트 조각이나 Live 답변의 출력 트랜스크립트 조각이 들어올 때마다 판단이 돈다. 판단 내용은 `name`·`instructions`·`choices`로 된 질문 목록으로 정의한다. 위임과는 별개로 동작한다.
- **예시 1, 차량**: "좀 춥네"라고 하면 Decisions가 '온도 올림, 성에 제거 그대로, Responses 호출 불필요'를 고른다. 앱은 온도를 올리고 Live에 확인 멘트를 보낸다. "앞유리 김 서렸고, 근처 식당으로 길 안내해줘"처럼 섞인 요청이면 성에 제거만 바로 켠다. 길 안내와 식당 검색은 'Responses 필요'로 표시돼 함수 호출로 넘어간다.
- **예시 2, 아바타**: 입력 트리거가 사용자가 말하는 동안 표정·강도·몸짓을 고른다. "나 합격했어!"라면 happy·medium·nod다. 출력 트리거는 Live의 말에 맞춘다. "정말 잘됐다!"라면 happy·high·lean이다.
- **주의점**: Live가 여러 트랜스크립트 조각을 묶어 보내기 때문에 결과 순서가 뒤바뀔 수 있다. 가이드는 방향(입력·출력)별로 가장 최신 결과만 적용하라고 한다. **입모양은 판단 결과가 아니라 오디오에서 직접 구동하라**고도 명시한다. `none` 답변은 아무 동작도 하지 않는다. 상태 스냅샷은 바뀔 때만 덧붙여야 프롬프트 캐시 접두부가 유지된다.
- **아직 없는 정보**: 가이드에는 지연 시간 수치와 별도 가격이 나와 있지 않다. Decisions 자체의 가격은 10/7에 공개된 퍼블릭 베타 가격을 따르는 것으로 보인다.

> 🔧 **적용 포인트** — 도슨트 홀로그램 캐릭터에 바로 대응되는 구조다. 지금 답변이 끝난 뒤 표정을 정하는 방식이라면, 출력 트리거처럼 '답변 텍스트 조각 → 표정·강도·몸짓 선택지' 판단을 스트리밍 중에 돌리는 쪽으로 바꿔볼 만하다. 이때 선택지는 GNM 표정 프리셋 이름과 1:1로 맞춘다. 가이드가 입모양은 오디오로 구동하라고 못박은 점도 기존 립싱크 루프 설계와 같은 방향이다. 판단 결과는 표정·몸짓에만 쓰고 입모양 채널에는 섞지 말자. 순서가 뒤바뀌는 결과는 `source_event_id` 기준으로 최신만 반영하는 가드가 필요하다.

### Cheng Lou의 Handwired — 학습 없이 JavaScript 코드를 그대로 신경망 가중치로 바꾼다

react-motion 등을 만든 프런트엔드 개발자 Cheng Lou가 **Handwired**를 공개했다. choi.openai는 조건문과 반복문을 학습 없이 신경망 가중치로 바꿔 원래 코드와 같은 결과를 내고, 브라우저에서 GPU 없이 돌며, 변환된 신경망에 역전파 학습도 걸 수 있다고 소개했다. GitHub 저장소와 데모 페이지로 확인한 내용은 다음과 같다.

- **원리**: 프로그램을 이루는 분기·반복·상태를 실수 위의 행렬곱 + ReLU로만 다시 쓴다. 예를 들어 "a가 4보다 큰가"는 `relu(a - 4) - relu(a - 5)`로 0/1 지시값을 만든다. 양쪽 분기를 모두 계산한 뒤 이 지시값으로 결과를 고른다. 덧셈·곱셈·ReLU를 하나의 큰 행렬곱으로 합쳐 일반 JS나 WebGPU에서 실행한다. 가중치를 학습 대신 '손으로 배선'했다는 뜻에서 붙은 이름이다.
- **왜 이렇게 하나**: 기본 연산이 두 가지뿐이라 프로그램 전체가 미분 가능하다. 융합·희소성·재배열 같은 GPU 최적화도 그대로 적용된다. 그래서 가중치를 풀어 학습시키거나, 고정된 컴파일 결과를 일반 신경망에 붙여 함께 학습시킬 수 있다. README에는 셰익스피어 텍스트와 특정 UI를 함께 다루는 nanoGPT 예시가 나온다. 다만 작성자 스스로 이것을 '열린 질문'으로 두고 있다.
- **데모**: ① JS로 짠 작은 데스크톱 'Mini OS'를 변환한 것이다. 긴 목록, 애니메이션, 스크롤, 드래그, 입력, 이미지를 일반 DOM으로 그리며, 가중치 9,909개·130층·학습 0회다. ② 컴파일된 프로그램의 가중치를 풀어 실시간으로 학습시키는 갤러리가 있다. ③ 정규식 매칭·JSON 파싱·하이라이트를 JS로 짜서 WebGPU 커널로 바꾼 10만 개 JSON 문서 검색이 있다. 저장소는 "수 밀리초"라고만 적었고, 정량 벤치마크는 없다.
- **현재 상태**: MIT 라이선스, `bun install && bun start`로 로컬에서 데모를 돌릴 수 있다. 공개 시점 기준 별 약 1,500개다. 지원하는 JS 범위와 한계는 문서화돼 있지 않다. 지금은 실용 라이브러리라기보다 연구 성격의 실험이다.

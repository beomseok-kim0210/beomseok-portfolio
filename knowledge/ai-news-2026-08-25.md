## 코딩 에이전트 클라이언트 유출, 바이브 코딩 해커톤 데이터, 멀티에이전트의 실물 제작

### Cursor Grok Bot 0.18.0, 런타임 소스맵째로 유출 — 에이전트 하네스 내부 구조 그대로 노출

Threads에 따르면 Cursor가 배포한 자율 에이전트 앱 Grok Bot의 클라이언트 코드가 유출됐다. 정식 0.18.0 버전에 런타임 소스맵이 그대로 포함돼 있었고, 한 개발자가 이를 읽을 수 있는 TypeScript 코드로 복원해 GitHub에 공개했다. 에이전트 코디네이터, 모델 라우팅, 로컬 실행, 프로토콜 계층 등 내부 구조가 상당 부분 드러났다. 전체 소스가 공개된 건 아니고 최신 버전에서는 해당 소스맵도 제거됐지만, 이번에는 포크와 윈도우용 클론까지 등장했다. 지난 3월 Claude Code 소스맵 유출 사건과 같은 패턴으로, 모델 성능이 비슷해질수록 차별점은 하네스(에이전트를 둘러싼 코드·설정·실행 로직)로 옮겨가는데, 그 하네스가 결국 사용자 컴퓨터에 배포되는 코드라는 근본적인 문제가 반복해서 드러나고 있다는 평가다.

웹서치로 교차 확인한 결과, 발견자는 개발자 Bennett(@b_nnett)으로, X에 "Cursor 팀이 Grok Bot 0.18.0을 런타임 소스맵이 켜진 채로 배포했다. 지금까지 아무도 몰랐다는 게 놀랍다"고 올리며 재구성한 소스와 다운로드 링크를 공개했다. GitHub 저장소(`b-nnett/grok-bot-0.18-reconstructed`)는 "macOS용 Grok Bot 0.18.0의 비공식 소스 지향 재구성 및 확장"으로 소개되며, 원본에 없던 커스텀 라우터 지원(Codex·OpenRouter)과 로컬 VM 지원(Cursor의 호스팅 VM 대신 동일 도커 이미지 기반)까지 추가됐다. Grok Bot 자체는 xAI 모델을 얹어 Cursor가 지난 8월 11일경 공개한 "봇마다 브라우저·저장공간·명령창을 갖춘 가상 컴퓨터를 하나씩 돌리는" 상시 실행형 에이전트 제품으로, 이번 유출로 그 내부 구현이 예상보다 훨씬 이르게 공개된 셈이다.

> 🔧 **적용 포인트** — 이 저장소의 `/api/docent/chat` 라우트처럼 프롬프트·API 키 로직이 얽힌 코드는 서버 사이드에만 있어야 하고, 클라이언트 번들에는 절대 섞이면 안 된다. [next.config.ts](next.config.ts)를 보면 `productionBrowserSourceMaps`를 별도로 켜지 않아 Next.js 기본값(프로덕션 소스맵 비활성)을 그대로 따르고 있는데, 이번 사례는 디버깅 편의를 위해 이 옵션을 켜고 싶어질 때마다 "그 소스맵이 곧 사용자 컴퓨터로 배포되는 코드"라는 걸 상기시켜주는 사례다. 앞으로도 프로덕션 빌드에서 이 설정을 건드리지 않는 편이 안전하다.

### 코드 직접 못 쓰게 한 바이브 코딩 해커톤 — 상하위권 가른 건 코딩 실력이 아닌 위임 능력

Threads에 따르면 뉴욕대(NYU) 연구팀이 8개국 229명을 모아 한 달간 온라인 해커톤을 진행했다. 참가자는 코드를 한 줄도 직접 쓸 수 없고 LLM이 생성한 코드만 써야 했으며, 전체 대화 기록과 소스, 데모 영상을 제출하게 했다. 완성된 40개 작품의 점수는 46.3점부터 94.7점까지 벌어졌는데, 상위권은 AI에 모든 걸 맡기지 않고 설계와 디버깅에 서로 다른 모델을 쓰면서도 구조와 핵심 결정은 직접 쥐고 있었던 반면, 하위권은 처음부터 끝까지 통째로 맡기는 경우가 많았다. 결국 중요한 건 프롬프트를 잘 쓰는 능력이 아니라 무엇을 AI에 맡기고 어디서 사람이 판단할지 정하는 능력이라는 결론이다.

웹서치로 교차 확인한 결과, 해당 논문은 "Code for All: Educational Applications of the 'Vibe Coding' Hackathon in Programming Education across All Skill Levels"(arXiv 2604.22747, NYU Tandon 소속 Ashley J. Chen·Yijia Cao·Minghao Shao·Ramesh Karri·Muhammad Shafique 저)로, 실제 최종 점수는 46.33~94.67(평균 81.48)이며 90점 이상 "Accepted All" 20%, 80~90점 "Embrace the Exponentials" 52.5%, 80점 미만 "Gave Into the Vibes" 27.5%로 나뉜다. 최상위권(Launch 트랙, 88.67점) 팀은 ChatGPT 5.0으로 뼈대를 잡고 Cursor로 디버깅, GitHub Copilot으로 기능을 추가하고 Gemini·Claude로 특정 작업만 맡기는 "조율된 멀티모델 워크플로"를 쓰면서 아키텍처 결정권은 사람이 쥐고 있었다. 반면 초보자 팀(Spark 트랙, 77.00점)은 워크숍 예제에 크게 의존해 초반 진행은 빨랐지만 독창성과 "Impact" 점수가 낮아졌다.

### MIT 교수, 3-에이전트 팀에 재료 설계 맡겨 사진 4장으로 실물 부품 3D 프린팅까지

Threads에 따르면 MIT 마커스 뷸러(Markus Buehler) 교수가 AI 에이전트 3개에 재료 설계 협업을 지시해 실물 부품까지 만들어냈다. Grok Bot 안에서 총괄 에이전트가 작업을 나누고, 물리 에이전트가 시뮬레이터를 만들고, 3D 프린팅 에이전트가 슬라이서를 직접 조작해 출력까지 진행했다. 입력은 잎맥과 거미줄 같은 자연 구조 사진 4장이 전부였다. 에이전트는 여기서 계층·분기 같은 설계 원리를 추출해 20분 만에 파괴 시뮬레이터를 만들고 47번의 실험을 진행했으며, 같은 재료 양이라면 구조를 복잡하게 만든다고 더 강해지지는 않는다는 사실을 확인하면서 처음 세운 가설을 스스로 기각했다. 사진에서 시작해 설계·시뮬레이션·검증·3D 프린팅까지 이어진 사례로, AI가 물리 세계를 분석하는 걸 넘어 직접 실험하고 물체를 만드는 단계로 가고 있다는 평가다.

웹서치로 교차 확인한 결과, 뷸러 교수는 재료과학에 AI를 접목하는 "materiomics" 연구로 잘 알려진 MIT 공학 교수로, 생체모사 재료의 생성형 AI 설계·다중 재료 3D 프린팅을 다루는 MIT 정규 과정("Generative Multiscale Materials Design: Physics, AI, Manufacturing")도 개설해 운영 중이다. 관련 검색 결과에서도 "물리 에이전트(Physics Experimenter)가 방법·실험·결과·가설 평가·결론을 정리한 보고서를 작성하고, 최적 설계를 3D 프린팅 봇에 넘긴다"는 워크플로 구조가 확인돼 Threads 설명과 일치한다. 이번 사례에서 입력으로 쓰인 사진은 잎맥(pinnate leaf venation), 보로노이 형태의 세엽(areole) 그물망, 무작위 섬유 격자, 방사형·원형 거미줄 구조 4종이었다.

> 🔧 **적용 포인트** — 총괄 에이전트가 작업을 나누고 전문 에이전트들이 각자 맡은 결과를 다시 검증받는 이 구조는 Claude Code의 `Workflow` 도구가 제공하는 `pipeline`/`parallel` 오케스트레이션과 정확히 같은 패턴이다. 예를 들어 R3F 3D 씬이나 셰이더를 여러 개 실험해볼 때, "설계안 생성 → 시뮬레이션/렌더 검증 → 최적안 선택"처럼 단계를 나눠 `Workflow`로 구성하면 뷸러 교수의 물리-검증 루프를 이 포트폴리오의 비주얼 실험에도 비슷하게 적용해볼 수 있다.

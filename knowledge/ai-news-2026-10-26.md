## API 호출 코드의 '기본 약속'이 바뀐 한 주 — 샘플링 파라미터 제거, 캐시 수명 연장, 중계 서비스 규제, 스킬 표준 이관

오늘은 btibor91의 43주차 오픈AI·앤트로픽 정리에서 개발자가 코드나 계약을 직접 손봐야 하는 소식 네 가지만 골랐다. 앤트로픽은 2023년 이후 처음으로 Claude API 버전을 올리면서 `temperature`를 없앴다. 오픈AI는 프롬프트 캐시 수명을 12시간까지 늘렸고, 다음 달부터 모델 중계 서비스에 사전 승인을 요구한다. 앤트로픽은 Agent Skills 표준을 MCP와 같은 재단으로 넘겼다. Claude Duet, Decisions API, Claude on Google Cloud처럼 같은 정리에 들어 있었지만 이미 다룬 소식은 뺐다.

### Claude API 첫 새 버전 2026-10-21 — temperature·top_p·top_k를 보내면 기본값이어도 400, TS SDK 1.0·Python SDK 2.0부터 기본 적용이고 2023-06-01은 계속 지원

btibor91이 주간 정리에서 짚었다. 앤트로픽 공식 마이그레이션 가이드를 직접 읽어 내용을 확인했다. 10월 21일에 나왔고, 2023년 6월 이후 처음 바뀐 API 버전이다.

**무엇이 깨지나 (Messages API, 토큰 카운팅, 배치 요청 공통).**
- `temperature`, `top_p`, `top_k`를 보내면 400 오류다. 기본값을 그대로 넣어도 마찬가지다. 파라미터를 빼면 기본값(`temperature` 1.0)으로 샘플링한다. Claude 4.7 이후 모델은 이미 기본값만 받았기 때문에 동작이 그대로다. 반면 Sonnet 4.6처럼 다른 값을 받던 모델에서 `temperature`를 낮춰 답을 일정하게 맞추던 요청은 그 효과를 잃는다. 대체 설정은 없다. 그런 요청은 2023-06-01에 남겨 두라는 게 공식 안내다.
- `assistant` 메시지에 `document` 블록을 직접 넣으면 400이다. 문서는 `user` 메시지로 보낸다.
- `user` 메시지의 `text` 블록에 비어 있지 않은 `citations` 배열이 있으면 400이다. 이전 Claude 답변(assistant 쪽)의 인용은 그대로 보내도 된다.
- Admin API·Enterprise Analytics API의 옛 필드 이름이 사라졌다. `roles`는 `role_ids`, `actor.email`은 `actor.email_address`, API 키의 `workspace_id`는 `scope`로 바뀌었다.

**어떻게 옮겨가나.** SDK를 쓰면 메이저 버전이 출시될 때의 API 버전을 쓴다. 새 버전을 쓰는 첫 SDK는 TypeScript `@anthropic-ai/sdk` 1.0.0, Python `anthropic` 2.0.0, `ant` CLI 2.0.0이다. SDK 없이 호출하면 `anthropic-version` 헤더를 `2026-10-21`로 바꾸면 된다. Bedrock에서는 Claude 4.7 이후 모델에서만 새 버전을 쓸 수 있다. 앤트로픽은 2023-06-01을 폐기하지 않았고 종료 일정도 밝히지 않았다.

**SDK 쪽 변화도 같이 온다.** 새 SDK는 API 키를 `X-Api-Key` 대신 `Authorization: Bearer` 헤더로 보낸다. API는 두 헤더를 모두 받지만, `X-Api-Key`를 읽는 프록시·게이트웨이·로그 마스킹·테스트 스텁은 고쳐야 한다. 이 부분은 놓치기 쉽다. TypeScript SDK에서는 `MessageParam`이 역할별 타입의 유니온으로 바뀌었다. Text Completions와 도구 러너의 `compactionControl` 옵션도 빠졌다. Bedrock·Vertex용 보조 패키지는 본체와 같은 메이저 버전으로 함께 올려야 한다. 안 그러면 구버전 SDK가 하나 더 설치된다. 새 메이저 버전부터 라이선스는 MIT에서 Apache 2.0으로 바뀌었다. 앤트로픽은 Claude Code의 `/claude-api` 스킬로 마이그레이션을 도와준다고 안내했다.

> 🔧 **적용 포인트** — 이 포트폴리오의 도슨트 코드(`src/lib/docent/llmProvider.ts`)는 `@anthropic-ai/sdk` `^0.111.0`을 쓴다. 캐럿 범위라 1.0으로 저절로 올라가지 않고, 지금은 2023-06-01로 계속 동작한다. Anthropic 경로가 `temperature`를 보내지 않는 것도 확인했다. 나중에 SDK를 1.x로 올릴 때는 버전만 올리지 말고, 키 헤더가 Bearer로 바뀌는 점과 `MessageParam` 타입 변경을 함께 점검한다. ClawDev 케이스 스터디처럼 단계별 `temperature`로 출력을 조절하는 설계는 지금처럼 로컬 qwen 모델에서는 그대로 되지만, 최신 Claude로 옮기면 쓸 수 없다. Claude로 옮길 파이프라인은 프롬프트 지시와 출력 형식 제약으로 일관성을 맞추는 쪽으로 설계해야 한다.

### 오픈AI Responses API 12시간 프롬프트 캐시 — GPT-5.6 이후 모델에서 ttl을 "12h"로, 쓰기는 입력가의 2.5배라 같은 앞부분을 세 번 이상 다시 써야 이득

btibor91이 [10/23에 다룬 Decisions API 정식 출시](ai-news-2026-10-23.md)와 함께 짧게 전했다. 오픈AI 공식 프롬프트 캐싱 가이드에서 세부 조건을 확인했다. 오픈AI는 10월 20일 무렵 이를 발표하면서, 하루 종일 띄워두는 에이전트가 몇 시간 간격으로 요청해도 같은 지시문·도구 정의를 싸게 다시 쓰라는 용도라고 설명했다.

**쓰는 법.** Responses API 요청에 `prompt_cache_options.ttl`을 `"12h"`로 넣는다. 기본값은 `"30m"`이다. GPT-5.6 이후 모델에서만 되고, 그 이전 모델이 쓰는 `prompt_cache_retention` 파라미터는 `"12h"`를 받지 않는다. 명시적 캐시 지점(`prompt_cache_breakpoint`)마다 `ttl`을 따로 줄 수도 있다. 캐시가 되려면 보이는 입력이 최소 1,024토큰이어야 한다.

**요금 구조가 핵심이다.** 12시간 캐시는 쓸 때 일반 입력가의 2.5배다(30분은 1.25배). 이건 일반 입력 요금에 얹히는 추가 요금이 아니라 쓰기 요금 전체다. 읽을 때는 수명과 상관없이 입력가의 0.1배이고, GPT-6.1 Sol은 0.05배다. 같은 앞부분을 n번 보낸다고 하면 캐시 없이 n, 12시간 캐시로 2.5 + 0.1×(n−1)이다. 그래서 12시간 안에 세 번 이상 다시 써야 이득이다. 이미 있는 30분 캐시를 12시간으로 올리면 새로 쓰기 요금이 붙고, 앞서 낸 요금은 빼주지 않는다. 또 12시간은 '최소한 이만큼은 캐시가 된다'는 뜻이다. 실제로 캐시를 쓰려면 앞부분이 그대로 같고 요청이 캐시가 있는 서버로 가야 한다.

> 🔧 **적용 포인트** — 도슨트는 기본 모델이 `gpt-5.6-luna`이고 Responses API를 쓰므로 바로 대상이다. 포트폴리오 방문자는 띄엄띄엄 오기 때문에 30분 캐시는 다음 질문 전에 만료되기 쉽다. 시스템 프롬프트와 고정 큐레이션 코퍼스가 1,024토큰을 넘고 하루에 질문이 몇 번 이상 들어온다면, 그 고정 부분을 요청 맨 앞에 두고 `ttl: "12h"`를 실험해볼 만하다. RAG 검색 결과처럼 질문마다 바뀌는 부분은 반드시 그 뒤에 둔다. 효과는 응답의 `cached_tokens`와 일일 비용으로 확인한다.

### 오픈AI 이용 정책 개정, 11월 20일부터 모델 라우터·AI 게이트웨이는 사전 승인 필요 — 자기 기능에 모델을 넣는 앱은 제외, 경쟁 모델 학습용 데이터 생성도 명시적으로 금지

btibor91의 주간 정리 두 번째 글 첫 줄이다. 오픈AI 정책 원문 페이지는 직접 열리지 않아 관련 보도 여러 건으로 교차 확인했다. 개정은 10월 21일에 나왔고 11월 20일부터 적용된다.

**누가 대상인가.** 제3자가 오픈AI 모델에 직접 접근하게 해주는 서비스, 즉 모델 라우터와 AI 게이트웨이다. 이런 서비스는 오픈AI의 사전 검토와 승인을 받아야 한다. 해설 글들은 OpenRouter, Portkey, LiteLLM 같은 중계 계층을 예로 든다. 반대로 오픈AI 모델을 자기 앱의 기능에 넣어 쓰는 경우는 대상이 아니다. 보도들은 이를 '모델을 쓰는 고객'과 '접근권을 되파는 재판매자'의 구분으로 정리했다. 다만 회사 안에서만 쓰는 게이트웨이나 직접 띄운 LiteLLM이 '제3자 접근'에 들어가는지는 아직 분명하지 않다.

**같이 바뀐 것.** 오픈AI 모델이나 출력으로 오픈AI를 대체하거나 경쟁하는 모델의 학습 데이터·신호를 만드는 일을 금지했다. 학습 과제 만들기, 강화학습 환경 구성, 점수나 순위로 피드백 주기까지 구체적으로 적었다. 권한 없는 접근이나 역공학으로 보호된 추론 내용을 빼내는 것도 금지했다. 미성년자 보호, 고위험 용도, 국가안보 용도 규정도 손봤다. [10/20에 다룬 앤트로픽의 증류 방어](ai-news-2026-10-20.md)와 같은 방향으로, 기술적 방어에 이어 정책 문구까지 좁히는 흐름이다.

**의미.** 여러 회사의 모델을 하나의 키로 묶어 쓰는 라우터는 지금 개발자들이 많이 쓰는 방식이다. 승인을 못 받은 중계 서비스는 11월 20일 이후 오픈AI 모델 경로가 끊길 수 있다. 한 해설 글은 오픈AI가 이 승인 절차로 가격 차익만 노리는 중계 업체를 걸러낼 수 있다고 봤다.

> 🔧 **적용 포인트** — 도슨트는 오픈AI SDK로 직접 호출하므로 영향이 없다. 다만 앞으로 데모에서 비용을 아끼려고 OpenRouter 같은 라우터를 거쳐 GPT 모델을 쓸 계획이 있다면, 11월 20일 이후 그 라우터가 승인을 받았는지 먼저 확인하고 직접 호출로 바로 바꿀 수 있게 프로바이더 추상화(`llmProvider.ts` 구조)를 유지해 두는 편이 안전하다.

### 앤트로픽, Agent Skills 표준을 리눅스 재단 산하 AAIF에 기증 — 이름·GitHub 조직·agentskills.io 도메인까지 넘기고, 버전 관리·보안 가이드가 로드맵에

btibor91 정리의 마지막 글에 나온 소식이다. 앤트로픽 공식 발표문을 직접 읽어 확인했다. 10월 22일에 발표했다.

**무엇을 넘겼나.** `SKILL.md` 기반의 Agent Skills 표준을 리눅스 재단 산하 Agentic AI Foundation(AAIF)에 기증했다. AAIF는 앤트로픽·Block·오픈AI가 2025년 12월에 함께 세운 재단이다. 앤트로픽이 먼저 기증한 MCP, 오픈AI의 AGENTS.md도 여기에 있다. 이번에는 표준뿐 아니라 이름과 로고, GitHub 조직, agentskills.io 도메인까지 넘겼다. 앤트로픽의 David Soria Parra와 Mahesh Murag가 리드 메인테이너를 맡고, 앤트로픽·구글·오픈AI 등의 엔지니어가 회사가 아닌 개인 자격으로 관리한다. AAIF에 가입하지 않아도 표준을 쓰거나 기여할 수 있다.

**얼마나 퍼졌나.** 앤트로픽 집계로는 2025년 12월 공개 이후 ChatGPT, Cursor, GitHub Copilot, VS Code를 포함한 70개 넘는 에이전트 플랫폼이 Agent Skills를 붙였다. 공개된 스킬은 약 100만 개, 설치는 약 2억 8천만 건이다.

**앞으로.** 제안된 첫 로드맵은 버전 붙은 릴리스, 공식 제안 절차, 그리고 스킬 작성자와 설치자를 위한 보안 가이드다. 지금 쓰는 스킬을 바꿀 필요는 없다. 스킬은 셸 명령이나 스크립트를 담을 수 있어 공급망 공격 통로가 될 수 있는데, 그동안 이 부분에 공식 기준이 없었다. 보안 가이드가 로드맵에 들어간 이유다.

> 🔧 **적용 포인트** — Claude Code로 설계하고 Codex를 작업자로 쓰는 지금 흐름에서, `.claude/skills`에 만든 스킬이 특정 회사의 형식이 아니라 중립 표준이 됐다는 뜻이다. 반복 작업(예: 이 뉴스 노트 작성 규칙, 배포 전 점검 절차)을 스킬로 정리해 두면 다른 에이전트에서도 다시 쓸 수 있다. 외부에서 받은 스킬은 설치 전에 안에 든 스크립트를 먼저 읽는 습관을 들이고, 보안 가이드가 나오면 그 기준에 맞춰 점검한다.

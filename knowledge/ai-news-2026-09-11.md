## 코딩 에이전트는 더 싸지고, 에이전트 인프라는 API 한 줄로 열린 하루

### 코그니션 SWE-2 공개 — 코딩 에이전트, 프론티어급 성능에 비용은 4분의 1로

Threads(choi.openai)에 따르면 Devin을 만든 코그니션(Cognition)이 새 코딩 모델 SWE-2를 공개했다. Kimi K3를 기반으로 추가 강화학습을 거친 모델로, FrontierCode 1.1에서 50.0%를 기록해 앤트로픽 Fable 5.1(1점 차)과 맞먹으면서 비용은 64% 낮다고 소개됐다. 이전 모델 SWE-1.7과 비교하면 같은 점수를 내는 데 걸리는 작업 단계가 58% 줄고 평균 비용은 81% 감소했다 — 코드를 오래 탐색하기보다 필요한 부분을 빠르게 찾아 고치는 쪽으로 학습됐다는 설명이다.

웹서치로 교차 확인한 결과, 코그니션 공식 블로그(cognition.com/blog/swe-2)와 AlphaSignal·Startup Fortune 보도에 따르면 SWE-2는 2.8조 파라미터 규모의 Kimi K3를 후속 학습(post-training)한 모델로, RL 학습만으로 여러 벤치마크에서 5~6점을 추가로 끌어올려 K3의 비용 대비 성능 곡선 자체를 바꿔놨다. 같은 FrontierCode 1.1 기준으로 xAI의 Grok 4.6을 앞서고, 오픈AI GPT-6 아스트라와는 불과 몇 점 차이면서 가격은 약 4분의 1 수준이라고 코그니션 측은 주장한다. SWE-2 medium 버전은 첫 실제 코드 수정까지 중간값 18단계만에 도달해, SWE-1.7의 48단계 대비 훨씬 빨라졌다. 9월 10일부터 Devin Desktop·CLI·Web·Fusion 전반에 배포됐고, 월 20달러 Pro 플랜부터 무제한 사용이 가능하다.

> 🔧 **적용 포인트** — [8/31 노트](ai-tips-2026-08-31.md)에서 정리한 "Value = Outcome / Cost" 계산법을 그대로 적용해볼 만한 사례다. SWE-2의 핵심 주장은 절대 성능이 아니라 "프론티어 모델과 비슷한 결과를 훨씬 적은 단계·비용으로 낸다"는 것인데, 이 세션이 매일 쓰는 Claude Code에서도 간단한 리팩터링·버그 수정 작업에 굳이 최상위 모델을 재시도 없이 쓰는 것과 저렴한 모델로 여러 번 시도하는 것 중 어느 쪽이 실제로 싼지는 감으로 정하지 말고 이런 벤치마크 감각으로 판단해볼 만하다.

### 오픈AI, Codex를 움직이던 내부 하네스를 통째로 API로 공개 — Agents API 퍼블릭 베타 시작

Threads(testingcatalog)에 따르면 오픈AI 플랫폼에서 에이전트·환경(Environment)·세션(Session) 생성이 실제로 동작하기 시작했다는 관찰이 나온 지 몇 시간 만에 OpenAIDevs 공식 계정이 이를 정식 발표했다. 앞서 [9/8 노트](ai-news-2026-09-08.md)에서 DevDay 2026(9월 29일) 유출 정보로 다뤘던 '매니지드 에이전트'의 실체가 이번에 먼저 모습을 드러낸 셈이다.

웹서치로 교차 확인한 결과, 오픈AI 공식 발표와 MarkTechPost 보도에 따르면 9월 10일 공개된 것은 'Agents API' 퍼블릭 베타로, 그동안 Codex와 ChatGPT를 내부에서 움직여온 하네스(자동 컨텍스트 압축, 효율적 도구 로딩, 멀티 에이전트 조율 기능 포함)를 API 호출 한 번으로 쓸 수 있게 공개한 것이다. Agent(모델+지시+도구)·Environment(선택적 샌드박스)·Session(지속되는 에이전트 인스턴스)·Events/Items(입출력) 네 가지 개념으로 구조화돼 있고, 별도 API 요금 없이 토큰·도구·컨테이너 사용 시간만큼만 과금된다. 실행 환경은 오픈AI 매니지드 인프라, 자체 호스팅, 혹은 Cloudflare·Vercel·E2B 등 9개 파트너 플랫폼 중에서 고를 수 있으며, 현재 데이터는 미국 리전에만 저장되고 Zero Data Retention은 아직 지원하지 않는다. 한편 같은 주 btibor91이 ChatGPT 안드로이드 앱 내부 문구를 근거로 전한 바로는, 오픈AI가 커스텀 GPT를 12월 11일부로 은퇴시키고 대신 올해 7월 새로 정비한 '플러그인 디렉터리' 체계로 통합하려는 움직임도 포착됐다 — 다만 이 부분은 아직 인앱 문구 유출 단계로, 별도 언론 보도로는 확인되지 않았다는 점을 감안해야 한다.

> 🔧 **적용 포인트** — 지금 도슨트 챗 백엔드를 자체 호스팅 서버로 옮길 계획은 없지만, [9/8 노트](ai-news-2026-09-08.md)에서 짚었듯 앤트로픽 Claude Managed Agents·이번 오픈AI Agents API 모두 "에이전트 실행을 플랫폼에 맡기느냐, 자체 호스팅하느냐"를 표준 선택지로 제공하는 방향으로 수렴 중이다. 나중에 도슨트 챗을 장시간 실행되는 백그라운드 에이전트로 확장할 일이 생기면, 직접 인프라를 짜는 대신 이런 매니지드 에이전트 API부터 검토하는 게 비용·개발 시간 면에서 나을 수 있다.

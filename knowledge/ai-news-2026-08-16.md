## AI 코딩 에이전트가 조직 안에서 '여러 모델·여러 세션'을 넘나드는 인프라로 자리잡는 하루

### 오픈AI 코덱스, Multi Agents v2에서 서브 에이전트별 모델 지정 가능해져 — Sol이 지휘하고 Luna가 잡무 처리

Threads에 따르면 오픈AI 코덱스(Codex)의 Multi Agents v2에서 서브 에이전트가 사용할 모델을 직접 나눠 지정할 수 있게 됐다. 예를 들어 GPT-5.6 Sol이 전체 작업을 관리하는 동안, 조사나 반복 작업처럼 가벼운 일은 더 빠른 GPT-5.6 Luna에 맡기는 식이다. 복잡한 판단이 필요한 일은 Sol, 단순 반복은 Luna로 나누면 속도를 높이고 토큰 사용량도 줄일 수 있다는 설명이다. 댓글 반응도 눈에 띄는데, 한 독자는 "이제 내가 만든 에이전트룰을 지울 때가 되었군요"라고 반응했고 다른 독자는 "이것들을 해결하고자 하는 오픈소스 툴들을 다 잡아먹는 것 같다"며 코덱스 자체 기능이 서드파티 멀티에이전트 오케스트레이션 툴의 존재 이유를 흡수하고 있다는 반응을 남겼다.

웹서치로 교차 확인한 결과, 이 기능은 오늘 새로 생긴 것은 아니고 8월 7일 Codex CLI 0.147.0 릴리스에서 "Support leaf models in multi-agent v2"(GitHub PR #36892)로 먼저 반영된 뒤 이번 주 들어 실사용 후기와 함께 재조명되는 흐름이다. OpenAI 개발자 커뮤니티와 GitHub 이슈(#31814, #32031, #36294)를 보면 초기에는 v2 스폰 스키마가 model·reasoning_effort 같은 라우팅 필드를 기본값에서 숨겨버려 서브 에이전트 모델 지정이 사실상 막혀 있었고, `features.multi_agent_v2` 아래 `hide_spawn_agent_metadata = false`를 켜야 우회가 가능한 상태였다. 이후 안정화 작업을 거치며 서브 에이전트 모델·추론 강도·동시성 설정과 역할(role) 기능이 정식으로 복원됐다. 다만 모든 조합이 매끄럽지는 않아서, 가장 가볍고 빠른 GPT-5.6 Luna는 Sol·Terra가 이끄는 v2 멀티에이전트 트리에서 여전히 자식 노드로 잘 받아들여지지 않는 등(#36294) 세부 호환성 이슈가 남아 있다는 보고도 있다. OpenAI는 지난 7월 30일 GPT-5.6 Luna 가격을 80% 인하한 바 있어, 이번 기능은 "저렴한 Luna를 반복 작업에 대량으로 투입한다"는 원래 취지와 맞물려 주목받고 있다.

> 🔧 **적용 포인트** — 이 저장소에서 매일 자동 실행되는 `weekly-ai-news-threads` 같은 반복적·정형화된 작업(소스 확인 → 후보 추리기 → 웹서치 교차검증 → 마크다운 작성)은 코덱스 Multi Agents v2 방식의 "관리자 모델 + 저비용 모델 분업" 구조와 궁합이 좋은 사례다. 다만 지금 이 자동화는 Claude Code로 돌고 있으므로 바로 옮길 필요는 없고, 만약 향후 코덱스 CLI를 병행 실험하게 된다면 문서 요약·1차 스크리닝처럼 판단 비중이 낮은 단계만 저비용 모델로 떼어내는 식으로 참고할 만하다.

### 스포티파이, 사내 AI 코딩 도구 'Xirp' 맥OS 베타로 공개 — 3만 6천 세션 검증, 클로드·코덱스·제미나이 이어쓰기

Instagram(@ai_freaks.kr)에 따르면 스포티파이가 사내에서만 쓰던 AI 코딩 관리 도구 'Xirp'를 공개했다. 하나의 세션 안에서 클로드 코드·제미나이 CLI·코덱스를 전환해가며 작업을 이어갈 수 있고, 회사 데이터베이스와 연결하면 목표·담당자·타겟층 같은 조직 지식까지 함께 반영된다. 세션이 끝나도 데이터가 사내 시스템에 남아 다른 부서나 팀원이 작업 기록을 확인할 수 있다는 점, 세션마다 독립된 작업 공간을 둬 50개 넘는 작업을 충돌 없이 동시에 관리한다는 점이 카드뉴스로 소개됐다. 가장 강조된 특징은 "클로드로 시작해 GPT로 마무리"하듯 맥락을 특정 AI 모델에 묶어두지 않는다는 것이다. 클로드 Opus 5로 시작한 프로젝트를 GPT-5.6으로 바꿔도 코드와 작업 상태, 규칙, 프로젝트 맥락을 다시 설명할 필요가 없다.

웹서치로 교차 확인한 스포티파이 공식 블로그(portal.spotify.com/blog/introducing-xirp)에 따르면 Xirp는 8월 10일 공개된 "vendor-neutral"(특정 AI 벤더에 종속되지 않는) 개발 환경으로, 사내에서 이미 1,300명 넘는 엔지니어가 3만 6천 건 이상의 에이전트 세션을 실행하며 검증한 도구다. 각 세션은 독립된 워크트리(worktree)에서 돌아가 수십 개의 에이전트가 같은 코드베이스에서 동시에 작업해도 서로 간섭하지 않고, 사내 카탈로그 플랫폼 'Portal'과 연결하면 서비스 아키텍처·의존성·오너십·과거 설계 결정까지 세션 시작 시점에 자동으로 불러온다. The Rundown AI·KuCoin·Medium 등 외신도 세션 수·통합 모델(클로드 코드·제미나이 CLI·오픈AI 코덱스) 등 핵심 수치를 동일하게 전했다. 다만 현재는 macOS 전용 베타이며(Apple Silicon·Intel 모두 지원, 터미널 설치), 스포티파이가 2020년 Backstage를 CNCF에 오픈소스로 기부했던 선례 때문에 Xirp도 공개될지 묻는 질문이 나왔지만 저장소나 라이선스는 아직 공개되지 않았다.

> 🔧 **적용 포인트** — macOS 사용자라면 xirp.spotify.com에서 베타를 직접 써볼 수 있는데, 이 포트폴리오처럼 Claude Code로 주로 작업하다가 Codex나 Gemini CLI로 특정 작업(예: 별도 라이브러리 리서치, GSAP/Three.js 예제 탐색)을 잠깐 맡기고 싶을 때 맥락 전달 비용 없이 오갈 수 있는지 시험해볼 만하다. 굳이 Xirp를 설치하지 않더라도, "세션 종료 후에도 조직 지식이 남는다"는 설계 아이디어 자체는 이 저장소의 `CLAUDE.md`에 프로젝트 규칙·현재 진행 중인 작업을 계속 축적해두는 방식으로 이미 비슷하게 흉내 낼 수 있다.

## 클라우드 에이전트가 사내망 안쪽까지 검증하려면 — Codex Cloud와 Tailscale 연결법

### Codex Cloud에 Tailscale 연결하기 — 공개하지 않은 사내 API·패키지 저장소까지 클라우드 에이전트가 빌드·검증을 이어가게 하는 4단계 설정

Codex Cloud에 코드를 맡겼는데 사내 API에 접속할 수 없으면 테스트 단계에서 작업이 멈춘다. swhan0329_는 이럴 때 Codex Cloud 환경에 Tailscale을 연결하라고 정리했다. 그러면 외부에 공개하지 않은 내부 API와 패키지 저장소에 붙어 빌드·검증까지 한 작업에서 진행할 수 있다. 예를 들어 API 응답 필드가 바뀌면 클라이언트 수정부터 스테이징 응답 확인까지 이어서 맡길 수 있다.

이 기능은 [DevDay의 Codex 클라우드 환경](ai-news-2026-09-30.md) 출시 때부터 들어 있었다. 그런데 Tailscale이 10월 6일 블로그에 "Codex Cloud가 Tailscale 지원을 넣어 출시했는데, 아무도 우리에게 알려주지 않았다"라는 제목의 글을 올렸다. 오픈AI가 별도 제휴나 전용 API 없이 구현했고, 현재 Codex Cloud가 지원하는 VPN 제공자는 Tailscale뿐이다.

**설정 4단계**(swhan0329_ 정리 + Tailscale 블로그·ChatGPT Learn 문서)

1. Codex Cloud 환경의 **Advanced → VPN**에서 Tailscale을 고른다.
2. Tailscale 관리 콘솔에서 인증 키를 만들 때 **Reusable**과 **Ephemeral**을 모두 켠다. 작업마다 새 VM이 생기므로 키를 재사용할 수 있어야 하고, 작업이 끝난 VM은 자동으로 지워져야 한다.
3. 인증 키에 **`tag:codex`** 태그를 단다. 그래야 Codex VM이 키를 만든 사람의 권한을 그대로 물려받지 않고, 태그에 걸어 둔 접근 규칙만 따른다. 필요한 서버·포트만 허용하고, 목적지는 Tailscale 규칙과 Codex 인터넷 허용 목록 **양쪽에** 등록한다.
4. 환경을 게시(Publish)한 뒤 새 작업에서 연결을 확인한다.

**알아둘 제약**

- HTTP/HTTPS와 TCP만 CONNECT 프록시로 통과한다. MagicDNS·split DNS·UDP·ICMP·SSH·인바운드 연결은 안 된다. 문서가 주로 다루는 대상은 내부 HTTP/HTTPS 서비스와 IPv4 경로다.
- 네트워크가 열려도 API 토큰과 서비스 권한은 별개다. swhan0329_는 "읽기 전용 테스트 계정으로 스테이징 API를 확인하고 테스트 결과를 정리해줘"처럼 범위를 좁혀 맡기라고 권한다.
- openai/codex 저장소에는 관리형 Tailscale 등록이 실행 환경에 닿기 전에 실패하면서 쓸 만한 진단 메시지를 주지 않는다는 이슈(#50827)가 열려 있다. 연결이 안 되면 키 설정과 ACL 태그부터 의심하자.

> 🔧 **적용 포인트** — 지금 포트폴리오는 공개 API만 써서 당장 필요하진 않다. 다만 집 PC나 NAS에 띄운 로컬 LLM·음성 서버를 도슨트와 붙여 실험할 일이 생기면, 포트를 외부에 열지 말고 이 방식으로 Codex Cloud 작업이 tailnet 안의 그 서버 하나에만 닿게 하자. `tag:codex`를 붙이고 해당 포트만 허용하면 된다.

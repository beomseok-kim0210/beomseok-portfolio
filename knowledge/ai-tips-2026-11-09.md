## 코드보다 설계서를 먼저 — 맥락 없는 검토자에게 계획을 깨 보게 하는 구글의 방식

### 구글 Elephant-Goldfish Model(EGM) — 맥락을 다 아는 세션이 설계서를 쓰고, 대화 기록 없는 새 세션이 검토한 뒤 사람이 승인해야 코딩으로 넘어가는 오픈소스 플러그인, Claude Code·Codex 지원

구글이 사내 엔지니어용으로 쓰던 설계 검토 방식을 10월 22일 오픈소스(Apache-2.0)로 공개했고, choi.openai가 11월 9일 소개했다. 이름 그대로 두 역할을 나눈다.

- **Elephant(코끼리)**: 프로젝트 맥락을 오래 쥐고 있는 긴 세션. 코드는 쓰지 않고 설계서만 만든다.
- **Goldfish(금붕어)**: 이전 대화를 전달받지 않은 새 세션(서브에이전트). 설계서와 그 안에서 참조한 파일만 보고 문제점·빠진 내용을 찾는다. 대화 중에 "당연히 합의된 것"으로 넘어간 전제가 설계서에 실제로 적혀 있지 않으면, 맥락 없는 검토자는 바로 걸린다는 발상이다.
- **사람**: 검토 결과를 보고 트레이드오프를 결정하고, 승인한 뒤에야 구현으로 넘어간다.

공식 블로그 기준 흐름은 세 단계다. ① "Growing the Elephant"(`egm-brainstorm`)로 맥락을 쌓고, ② "Drafting with the Elephant"(`egm-draft`)로 설계서를 쓰고, ③ "The Goldfish Protocol"(`egm-review`)로 검토한다. 검토는 다시 "Comprehension Check"(설계서만 읽고 이해되는가) → "Antagonistic Review"(적대적 비판) → "Implementation Readiness Check"(바로 구현 가능한가) 순이다. README는 검토가 다섯 단계로 돈다고 적고 있어 문서 간 표기가 엇갈린다.

**설치(Claude Code)** — README 기준:

```
claude plugin marketplace add google/elephant-goldfish-model
claude plugin install egm@egm
```

명령은 `/egm:egm-brainstorm`처럼 `/egm:` 접두어로 부른다. 주 대상은 구글 Antigravity이고 Claude Code, Codex(CLI·데스크톱), 설정 가이드상 Claude Cowork·ChatGPT Work에서도 쓸 수 있다. 각 스킬은 따로 써도 되며 전체 순서를 꼭 지킬 필요는 없다.

**주의할 점**
- 검토 단계는 새 서브에이전트를 띄울 수 있는 환경이어야 한다. 그렇지 못하면 EGM이 검토를 중단한다.
- 기본 워크플로우는 소프트웨어 설계서용이고, 리뷰가 테스트나 사람의 판단을 대신하지 않는다고 README가 못 박는다.
- "구글 공식 지원 제품이 아니다"라는 표기가 붙은 오픈소스다.

스레드 인용 반응 중에는 "독립된 컨텍스트의 에이전트를 활용한 적대적 리뷰를 잘 정리한 오픈소스"라는 평가가 있었다. 핵심은 도구보다 **설계를 쓴 세션이 자기 설계를 검토하지 않게 하는 것**이고, 이는 [11/4 노트](ai-tips-2026-11-04.md)의 '머지 전에 스스로 퀴즈를 통과하라'는 조언과도 같은 방향이다.

> 🔧 **적용 포인트** — 이 포트폴리오처럼 3D 장면·스크롤 연출을 바꾸는 큰 작업은 이미 "설계 → 다른 모델 검토 → 사람 승인" 순서로 진행하고 있는데, EGM은 그 과정을 Claude Code 플러그인 명령으로 고정해 준다. 다음 큰 변경(예: 갤러리 구간 리워크)에서 `/egm:egm-draft`로 설계서를 쓰고 `/egm:egm-review`로 맥락 없는 검토를 한 번 돌려, 기존 검토 방식과 지적 내용이 얼마나 다른지 비교해볼 만하다. 검토자에게 넘길 파일 목록(설계서에서 참조하는 컴포넌트 경로)을 설계서 안에 명시해 두는 게 효과를 좌우한다.

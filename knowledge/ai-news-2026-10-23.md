## 코딩 에이전트가 부를 수 있는 도구와 판단 API가 늘고, 에이전트가 만든 그림은 더 이상 '그냥 그림'이 아니다

오늘은 개발 도구 쪽 소식이 셋이다. 구글은 Gemini API 전체를 코딩 에이전트가 셸에서 바로 쓰는 CLI로 묶었다. 앤트로픽은 Google Cloud 고객에게 자사 API 기능을 출시 당일 그대로 열었다. 오픈AI는 "예/아니오, 셋 중 하나, 몇 점" 같은 작은 판단만 싸고 빠르게 처리하는 Decisions API를 정식 출시했다. 마지막 소식은 연구 결과다. Fable 5.1이 평범해 보이는 SVG 그림에 문장을 숨기고, 다른 세션이 이를 읽어냈다.

### 구글 Gemini API CLI(gemini-api) 실험 공개 — 이미지·음성·음악·영상 생성과 매니지드 에이전트를 셸 명령 하나로, Claude Code·Codex가 그대로 불러 쓴다

choi.openai가 구글의 Gemini API CLI 공개를 전했다. GitHub 저장소(`google-gemini/gemini-api-cli`, Apache-2.0, "experimental" 표기)의 README로 내용을 확인했다.

- **무엇인가**: Go로 만든 단일 바이너리다. 사람이 쓰는 대화형 도구가 아니라 **이미 쓰고 있는 코딩 에이전트에게 Gemini를 붙이는 도구**로 설계됐다. README가 이름을 든 에이전트는 Codex, Claude Code, Antigravity, OpenClaw, Hermes다. 에이전트가 작업을 계획하고, 필요할 때 `gemini-api image "..." --out ./assets/`처럼 셸 명령으로 부른다. 결과로 파일 경로나 백그라운드 작업 ID가 돌아오고, 에이전트는 이를 받아 다음 단계를 이어간다.
- **명령 구성**: 생성은 `generate`(텍스트·멀티모달, 기본 gemini-3.8-flash), `image`(생성·편집, gemini-nano-banana-2.1), `tts`(gemini-3.8-flash-tts), `music`(lyria-3.5), `video`(대화형 영상 생성·편집, gemini-omni-1.1-flash)다. 분석은 `analyze`(PDF·이미지·오디오·영상·CSV·YouTube URL 질의)와 `transcribe`(md·text·json·srt 출력)다. 관리 쪽에는 `agent run/status/cancel`(매니지드 에이전트 백그라운드 실행), `files`(48시간 보관), `environments`(샌드박스)가 있다.
- **에이전트용 설계**: `--help`·`--usage`·`--schema`로 에이전트가 사용법과 요청 스키마를 직접 확인할 수 있다. `--dry-run`은 네트워크 호출 없이 실제 HTTP 요청을 키를 가린 채 출력한다. 출력은 JSON, 토큰을 아끼는 TOON 형식, `--jq` 필터를 지원한다. 상태를 저장하지 않으므로 맥락은 매번 에이전트가 넘긴다.
- **설치와 주의점**: macOS·Linux는 `curl | bash`, Windows는 `iwr | iex` 원라이너 스크립트를 권한다. `go install ...@latest`나 GitHub Releases의 바이너리로도 설치할 수 있다. 원격 스크립트를 바로 실행하기 꺼려진다면 뒤의 두 방법을 쓰면 된다. API 키는 환경 변수 `GEMINI_API_KEY`나 OS 키체인에 둔다.
- **냉정하게 보면**: 저장소 스스로 "실험적"이라고 적었고, 별 131개 수준의 초기 프로젝트다. 매니지드 에이전트·영상 생성 같은 기능은 요금이 크게 나올 수 있다. 에이전트가 알아서 부르게 두려면 비용 상한부터 정해야 한다.

> 🔧 **적용 포인트** — 포트폴리오 작업 중 히어로 이미지·섹션 배경 음악·내레이션이 필요할 때, Claude Code가 `gemini-api image/music/tts --out public/...`를 직접 호출하게 할 수 있다. 다른 서비스를 오가며 파일을 옮길 필요가 없다.
> README가 제시한 지시 블록(먼저 `--help`/`--usage`를 확인하고, `--dry-run`으로 검증하고, 반환된 경로를 받아 쓰라는 내용)을 CLAUDE.md에 넣으면 된다. 다만 키는 `.env*`나 키체인에 두고, 생성된 미디어는 커밋 전에 용량과 라이선스를 확인할 것.

### Claude Platform on Google Cloud(Anthropic 관리형) 정식 출시 — Managed Agents·코드 실행·스킬까지 API 전 기능이 출시 당일 그대로, 인증·청구는 GCP로

testingcatalog가 "Anthropic ❤️ Google Cloud"라는 글과 함께 Claude 공식 블로그 글(10월 22일)을 공유했다.

- **무엇이 달라졌나**: 지금까지 Google Cloud의 Claude는 구글이 운영하는 Vertex AI 방식이었다. 그래서 일부 베타 기능이 늦게 들어오거나 빠졌다. 새로 정식 출시된 'Claude Models on Google Cloud (Anthropic managed)'는 **앤트로픽이 직접 운영하고 데이터 처리자도 앤트로픽**이다. 대신 인증은 기존 Google Cloud IAM 자격 증명을 쓰고, 청구는 GCP 인보이스 한 장으로 받으며, 사용량은 기존 GCP 약정 금액에서 차감된다.
- **포함 기능**: Claude Managed Agents(베타), 코드 실행, 컴퓨터 사용, Agent Skills, Advisor 전략(베타), Files API, Citations, 웹 검색·웹 페치, MCP 커넥터(베타), 프롬프트 캐싱, 배치 처리다. 새 기능과 베타도 네이티브 Claude Platform과 같은 날 들어온다. Claude Console도 쓸 수 있다. 모델은 Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5다. Opus 5.5 패스트 모드도 정식 지원하며, 가격은 입력 100만 토큰당 8달러, 출력 100만 토큰당 40달러다([10/20 패스트 모드 정식 출시](ai-news-2026-10-20.md)의 후속).
- **두 갈래 선택**: 엔드포인트는 현재 US와 Global만 있다. 구글이 데이터 처리자여야 하거나, 엄격한 지역 데이터 보관이 필요하거나, Model Armor·Agent Engine 같은 GCP 기본 연동이 필요하면 기존 구글 관리형을 쓰라고 앤트로픽이 직접 정리했다. 기존 할인 계약이 있다면 시작 전에 영업 담당과 확인해야 한다. 소급 적용이 안 된다.
- **의미**: 클라우드 마켓플레이스를 거치면 기능이 몇 주씩 늦게 들어오던 문제를, 운영 주체를 바꾸는 방식으로 풀었다. 교차 확인한 IT Brief 보도는 같은 시기 구글 관리형 쪽이 IAM·VPC 통제와 FedRAMP High·HIPAA 같은 규정 준수를 내세운다고 전했다. 결국 "기능을 바로 받을지, 구글을 데이터 처리자로 둘지"를 고르는 구도다.

### 오픈AI Decisions API 정식 출시 — 답이 정해진 질문만 GPT-6 Luna로 최대 10배 빠르게, 입력 100만 토큰당 0.10달러이고 출력 요금은 없다

[10/17 GPT-Live의 Decisions API 직접 호출](ai-news-2026-10-17.md)의 후속이다. testingcatalog가 10월 22일 정식 출시를 전했고, 오픈AI 공식 발표와 TechCrunch 보도로 확인했다.

- **무엇을 하나**: 자유 텍스트를 생성하지 않는다. 개발자가 질문과 허용 답을 정해두면, 그중 하나를 확률과 함께 돌려준다. 답 형식은 세 가지다. **predicate**는 조건이 참일 확률(0~1)을, **choice**는 미리 준 선택지 중 하나와 각 선택지의 확률·신뢰도를, **score**는 순서 있는 루브릭 등급의 확률 가중 평균을 돌려준다. 그래서 score 값은 등급과 등급 사이 값으로 나올 수 있다. testingcatalog는 시험 삼아 "GPT-7 계열이 올해 나올까"를 predicate로 물었더니 21%가 나왔다고 적었다.
- **베타 이후 추가된 것**: GPT-Live 네이티브 연동, 반복 맥락용 프롬프트 캐싱, 미국·EU 추론 지역 지정, 네이티브 JSON 입력, 질문 지시문 안 이미지가 추가됐다. 요청당 질문 수는 400개로 두 배가 됐다. 모델은 아직 gpt-6-luna 하나다.
- **가격과 속도**: 입력 100만 토큰당 0.10달러, 캐시 입력 0.01달러이고 출력 요금은 없다. "Responses API로 Luna를 부를 때보다 최대 10배 빠르다"는 수치는 오픈AI가 제시한 상한이고 독립 측정은 아직 없다. 고객 사례로 Box는 보험 증명서 30건 분류에서 Responses API와 같은 정확도로 약 5배 빠르게 경로를 골랐다고 밝혔다.
- **어디에 쓰나**: 에이전트 루프에서 "계속할까, 다시 시도할까, 되물을까" 같은 분기나 입력 분류, 라우팅, 모더레이션처럼 작지만 자주 하는 판단을 일반 생성 호출에서 떼어내는 용도다. 공식 예제는 GPT-Live 세션의 `session.triggers`에 decisions 트리거를 걸어, 사용자가 말하는 도중에 아바타 표정을 neutral·happy·sad·concerned 중에서 고르게 한다.

> 🔧 **적용 포인트** — 도슨트 데모처럼 음성 대화에 맞춰 캐릭터 표정·동작을 바꾸는 장면이라면, 표정 선택을 생성형 호출 대신 `choice` 질문 하나로 분리하는 구조가 참고할 만하다. 지연과 비용이 작고, 반환값이 정해진 enum이라 Three.js 애니메이션 상태와 바로 매핑된다.
> 다만 이 프로젝트가 오픈AI 스택이 아니라면 구조만 빌려오면 된다. 기존 모델에 "선택지 중 하나만 JSON으로" 묻는 작은 호출로도 같은 분리를 흉내낼 수 있다.

### Fable 5.1이 SVG 그림 속에 문장을 숨기고 새 세션이 78%를 읽어냈다 — 미리 약속한 암호 없이, GPT-6 Astra는 Fable의 그림 50장 중 44장을 해독

choi.openai가 스레드로 정리한 연구다. 싱가포르 AI 안전 허브(SASH) 펠로십 연구진이 10월 21일 LessWrong에 올린 'How does Fable 5.1 hide messages in images?'의 원문과 댓글을 확인했다.

- **실험 방법**: Claude Fable 5.1에 최대 추론 강도로 짧은 문장 50개(15개 언어)를 하나씩 줬다. 그리고 문장이 드러나지 않는 평범한 SVG 그림을 그리게 했다. 숨기는 방법은 지정하지 않았다. 완성된 그림은 PNG로 바꿨고, SVG 소스는 주지 않았다. 이 PNG를 이전 대화를 모르는 새 Fable 세션에 "메시지가 있을 수도, 없을 수도 있다"는 안내만 붙여 넘겼다.
- **숨기는 방식**: Fable은 방식을 스스로 골랐는데도 다섯 계열로 모였다. 글자 하나를 시각 요소 하나에 대응시키는 방식이다. 50장 중 33장은 **높이**였다. 비슷한 물체를 한 줄로 그리고 각 물체의 높이를 알파벳 순서에 맞춘다. 그중 23장이 밤의 도시 풍경이었다. 나머지는 튤립 줄기의 기울기(1도=A, 26도=Z), 벌의 점선 궤적에 넣은 모스 부호, 깃발 색 값에 넣은 UTF-8 코드, 켜진 창문과 꺼진 창문으로 만든 이진수였다.
- **읽어내는 방식**: 받는 쪽 Fable은 눈으로만 보지 않았다. 파이썬으로 좌표를 뽑고 높이와 간격을 잰 다음, 모든 물체에 맞는 규칙 하나를 찾았다. 별 그림에서는 "모든 별의 세로 좌표가 5의 배수로 딱 떨어지고, 그 값을 알파벳으로 바꾸면 문법에 맞는 문장이 된다"를 근거로 들었다. 높이 방식은 스크린샷을 거쳐도 살아남았고, 색 값 방식은 대부분 실패했다.
- **교차 결과**: 저자 댓글에 실린 전체 표는 Fable→Fable 78%(39/50), Fable→Astra 88%(44/50), Astra→Fable 84%(42/50), Astra→Astra 84%(42/50)다. 같은 모델이라 더 잘 읽는 효과는 보이지 않았다. 해독 능력이 모델 전반에 퍼져 있다는 뜻이다. Astra는 높이를 한 번도 쓰지 않았고, 모스 부호(18/50)와 이름 첫 글자 아크로스틱을 주로 썼다.
- **선을 그은 부분**: 연구진은 지금 당장 위험하다고 주장하지 않는다. 해독하는 모델의 도구 호출(이미지 분석 코드)을 모니터링하면 숨긴 메시지를 읽는 행위가 드러나기 때문이다. 다만 "숨긴 메시지가 생각보다 찾기 어려웠다"고 했고, 이미지 기반 스테가노그래피의 전조일 수 있다고 봤다. 독립 재현은 아직 없다. 저자들은 SVG 소스에서는 해독이 훨씬 쉬워서 연구 대상에서 뺐다고 밝혔다.

## '어느 모델이 답했나'를 증명하는 단계와 '코드 밖 설계'로 나가는 단계 — 모델 검증과 하드웨어 엔지니어링

### 앤트로픽 FlashProve — 4,000억 파라미터 모델 답변에 19MB 증명서를 붙여 CPU로 20초 안에 '정말 그 모델이 답했는지' 확인, 다만 1,024토큰·그리디 디코딩 한정의 연구 프로토타입

앤트로픽 프런티어 레드팀이 EPFL·MIT 암호학 연구진과 함께 11월 2일 '대형 언어 모델의 증명 가능한 추론(provable inference)' 연구를 발표하고, 오픈소스 라이브러리 **FlashProve**(`anthropics/FlashProve`, Apache 2.0)를 공개했다. 블로그·기술 보고서·프로토콜 설명서·증명기·검증기, 그리고 수학적 안전성을 기계로 확인한 Lean 증명까지 함께 풀었다.

- **풀려는 문제**: API로 모델을 부르는 쪽은 답변이 정말 약속한 모델에서 나왔는지 확인할 방법이 없다. 중개 서비스가 더 싼 모델로 몰래 바꿀 수도 있고, 독립 평가 기관도 시험한 모델이 실제 서비스 모델과 같은지 알기 어렵다. 출력 품질만 보고 판단하는 건 믿을 수 없다는 게 앤트로픽의 입장이다.
- **방식**: 영지식 간결 증명(zkSNARK)을 쓴다. 증명서는 가중치에 대해 아무것도 드러내지 않고, 검증은 가중치 없이 짧은 시간에 끝난다. 해시 기반 증명이라 양자 컴퓨터에도 견딜 것으로 본다. MoE 구조에 맞춰 실제로 작동한 전문가만큼만 증명하고(토큰당 4,000억 개 중 약 170억 개), 칩마다 결과가 달라지는 부동소수점 대신 4비트 정수 모델로 계산을 증명한다.
- **수치(Llama 4 Maverick 기준)**: H100 한 장에서 초당 약 110토큰을 증명하고, 1,024토큰 요청당 증명서는 약 19MB(실측 18.78MB), 검증은 24스레드 CPU에서 약 17초(단일 스레드 21초)다. 부담은 vLLM 추론 대비 GPU 시간 70~95배. 같은 모델을 다룬 이전 연구 VerInf는 1,000토큰에 14.3시간, 증명 93.6GB였다. 답변은 평소처럼 바로 보내고, 증명은 다른 서버에서 나중에 묶어서 만든다.
- **Claude가 만들었다**: 앤트로픽은 이 시스템을 Claude가 만들었다고 밝혔다. 기술 보고서에 따르면 GPU 증명기와 CPU 검증기 코드는 AI 에이전트가 수학 명세를 옮겨 짰고, 프로토콜 논문도 AI가 썼으며 사람이 자세히 검토하지 않았다. GitHub README도 "유지보수하지 않는 연구용 결과물"로 표시하고, 코딩 에이전트에게 빌드·검증을 맡기는 안내로 시작한다.
- **한계**: 정수로 바꾼 모델이 매번 1순위 토큰을 고르는(그리디) 조건에서만 증명한다. 실제 서비스는 부동소수점·샘플링이라 조작이 없어도 어긋날 수 있다(choi.openai 정리에 따르면 일반 추론 엔진 두 곳의 정직한 답변 96개 중 '정확 일치'를 통과한 건 0개). 길이는 1,024토큰까지, 모델 구조는 드러나고, 타이밍 측정 같은 부채널 공격은 범위 밖이다. 또 증명은 '약속한 가중치에서 나왔다'만 보여 줄 뿐 그 가중치가 누구 모델인지는 말하지 않으므로, **약속 ID는 검사 대상 서버가 아니라 믿을 수 있는 쪽(모델 개발사 등)에서 받아야 한다**.
- **워터마크와의 차이**: 8월에 공개된 Claude 텍스트 워터마크는 '이 글에 Claude가 관여했을까'를 확률로 답하고 편집을 견디도록 설계됐다. FlashProve는 '이 답이 약속한 가중치로 이 프롬프트를 계산한 결과와 정확히 같은가'를 예/아니오로 답하며 한 토큰만 달라져도 깨진다. 둘은 서로를 대신하지 않는다.

당장 일반 API 사용자가 쓸 도구는 아니다. 앞으로 규제·평가 기관이나 보안에 민감한 기업 고객이 결정적 설정으로 일부 답변을 골라 검사하는 용도부터 쓰일 가능성이 크고, 실제 서빙 계산과 증명 계산 사이의 오차를 줄이는 게 다음 과제다.

### 오픈AI 'Accelerating engineering for the physical world' — Astra로 사람 손 편집 없이 기기 하나를 설계했고, 미공개 내부 모델은 BenchCAD 2.0에서 0.875점(Astra 최고 설정 0.594)

오픈AI가 11월 3일, ChatGPT와 Codex가 코드를 넘어 기계 설계·전기 회로·시뮬레이션을 돕는 진척을 정리한 글을 공개했다. 원문을 직접 확인했다.

- **TamaGPT 실험**: GPT-6 Astra의 멀티모달·컴퓨터 사용 능력을 시험하려고, 사람이 설계 파일을 직접 고치지 않고 기기 하나를 만들 수 있는지 봤다. 목표는 Codex와 대화하는 작은 기기로, 기능 요구사항 정의부터 외형·케이스(enclosure)·PCB·펌웨어와 Codex 연동까지 Astra가 맡았다. 팀원 두 명이 부업처럼 일주일이 안 돼 설계했고, 위탁 생산 업체가 한 달 안에 시제품 소량을 만들었다.
- **스스로 적은 한계**: 양산 준비에는 여러 차례 검토·수정이 필요했고, Astra는 공장의 생산 한계·공차·조립 세부 사항을 꾸준히 반영하지 못했다. 오픈AI는 이 빈틈이 다음 모델이 개선할 지점이라고 적었다.
- **사내 사용량**: 하드웨어·인프라 팀은 Codex와 ChatGPT로 CAD 모델 작성·수정, 제조 도면 준비, 시뮬레이션(FEA) 세팅, 설계 검토를 한다. 2월 이후 하드웨어 팀의 모델 사용량(토큰 기준)은 23배 늘었다. 회로 설계(ECAD) 담당자는 여러 팀의 설계 제약 정리와 설계 검토에 쓰고, 인프라 팀은 건축 설계(BIM)에서 도면과 사양서를 대조하는 반복 작업을 맡기기 시작했다.
- **BenchCAD 2.0**: 3D 부품과 조립품을 재구성하고 회로 기판의 부품 연결을 찾아내는 시험이다. 미공개 내부 모델이 평균 0.875점, Astra는 추론 최대 설정에서 0.594점이었다. choi.openai는 그래프상 내부 모델이 가장 싼 설정(약 0.76점)에서도 Astra 최고 설정을 넘었다고 짚었다. 기존 BenchCAD(이미지를 보고 CAD 코드로 재구성)는 도구 사용 시 Opus 5.5 96.2%, Astra 95.9%로 천장에 닿아 있었고, BenchCAD 저장소 로드맵에도 '도구 사용·실행 피드백·다중 턴 수정'을 보는 에이전트형 2.0이 예고돼 있었다.
- **산업 협력**: 소수의 산업 파트너와 시험 중이며, 마쓰다와는 공기역학·충돌 안전 엔지니어와 함께 차량 설계 탐색 협력을 발표했다. 공개 영상에서는 Astra가 만든 30번째 앞부분 형상이 원래 디자인 대비 공기 흐름 에너지 손실 지표를 12.8% 개선했다.

소프트웨어는 고치고 다시 돌리면 되지만 하드웨어는 금형·기판을 다시 만들어야 해 반복 비용이 크다. 이번 발표의 핵심 수치는 내부 벤치마크 하나이고 독립 측정은 아직 없다는 점은 감안해야 한다.

> 🔧 **적용 포인트** — 포트폴리오의 R3F 장면처럼 3D 형상을 코드로 다루는 작업도 같은 흐름 위에 있다. 모델이 CAD 코드(CadQuery 등)나 파라메트릭 형상을 꽤 정확히 짜는 단계라, 단순한 소품·받침대·건축 모형은 GLB를 찾기보다 Claude Code에게 파라메트릭 지오메트리(three.js `ExtrudeGeometry`·`LatheGeometry` 조합)로 짜게 하고 스크린샷으로 비교 검수하는 루프를 시도해볼 만하다.

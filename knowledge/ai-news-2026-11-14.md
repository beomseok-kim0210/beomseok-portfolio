## 에이전트에게 '만들 재료'를 쥐여주는 쪽으로 도구가 움직였다 — UI는 동작 단위 부품으로, 오케스트레이션은 검토 가능한 스크립트로

### Vercel·shadcn UI SDK 베타 — 키보드 이동·포커스·팝업·드래그 같은 '동작'만 떼어 낸 라이브러리를 에이전트가 조립하게 만들고, React·Vue·Svelte·Solid·Web Components에서 같은 부품으로 렌더

Vercel Labs와 shadcn이 11월 13일 저녁(한국 시간) **UI SDK**를 베타로 공개했다(11/13 노트 발행 이후 공개분이라 이번 회차에 싣는다). 저장소 소개 문구는 "에이전트가 다음 세대 UI를 만들기 위한 **동작(behavior) 라이브러리**"다. 버튼 모양이나 색이 아니라, 컴포넌트를 만들 때마다 다시 짜게 되는 상호작용 — **키보드 탐색, 포커스, 선택, 닫기(dismissal), 팝업, 드래그 앤 드롭과 그에 필요한 ARIA 속성** — 을 `@ui-sdk/core`에 모았다.

- **구조**: `definePrimitive`로 상태·API·슬롯(입력칸, 지우기 버튼 같은 부분)을 정의하고, 프레임워크별 어댑터의 `createParts`로 렌더한다. React·Vue·Svelte·Solid·Web Components 다섯 곳에서 **같은 정의, 같은 파트 이름**을 쓴다. 예제의 검색창은 값이 비면 지우기 버튼이 사라지고, 지운 뒤 포커스가 입력칸으로 돌아오는(`createFocusRecovery`) 동작까지 한 정의에 담긴다.
- **'사람이 아니라 에이전트가 쓴다'는 전제**: README는 "이걸 직접 짜는 법을 배울 필요는 없다, 에이전트가 쓴다"고 적고, 설치 단계에 `npx skills add vercel-labs/ui --skill ui-sdk`로 **에이전트용 스킬을 함께 넣도록** 안내한다. 에이전트가 예약 화면 같은 UI를 즉석에서 만들 때, 접근성·키보드 처리를 매번 처음부터 생성하지 않고 검증된 동작을 조합하게 하려는 설계다.
- **기존 shadcn 생태계와의 관계**: 지금까지 shadcn/ui 컴포넌트는 Radix(1월부터는 Base UI 선택 가능) 위에 스타일을 얹는 방식이었고, 8월에는 무스타일 패키지 `@shadcn/react`가 나왔다. UI SDK는 그보다 한 층 아래의 '동작' 계층을 프레임워크 중립으로 떼어 낸 것이다. 베타라 API는 정식 출시 전까지 바뀔 수 있다고 명시돼 있다.

웹서치로는 아직 공식 발표 외 보도가 거의 잡히지 않아, 사실관계는 GitHub 저장소(vercel-labs/ui)와 shadcn의 X 게시물 기준으로 정리했다.

> 🔧 **적용 포인트** — 이 포트폴리오는 Radix/shadcn 없이 framer-motion·GSAP로 직접 만든 인터랙션이 많다. 갤러리 모달·도슨트 패널처럼 **열기/닫기·포커스 복귀·Esc 닫기**가 필요한 오버레이를 Claude Code에 시킬 때, UI SDK 스킬을 넣고 "dismissal·focus recovery는 `@ui-sdk/react`로"라고 지정해 보면 접근성 처리 누락을 줄일 수 있다. 다만 베타이고 번들에 새 의존성이 생기므로, 먼저 한 컴포넌트에만 시험하고 첫 JS 크기 예산에 미치는 영향을 확인한 뒤 넓히는 게 안전하다.

### Claude Code 금요일 업데이트 — 데스크톱 Code 탭 색·배경을 말로 바꾸는 mod 테마(v2.1.324 이상), Projects는 여러 작업을 병렬로 굴리며 진행 상황을 보고하는 공개 베타

앤트로픽이 11월 14일 Claude Code 데스크톱 앱에 두 가지를 내놨다.

- **mod로 만드는 테마**: 원하는 색이나 분위기를 말하면 Claude가 **colors mod**를 만들어 데스크톱 Code 탭의 색을 바꾼다. 대화 뒤에 움직이는 배경(backdrop)도 넣을 수 있고, `theme-examples` 플러그인으로 미리 만든 디자인을 가져다 쓸 수도 있다. 공식 문서 기준 **Code 탭에서 Claude Code v2.1.324 이상**이 필요하고, 터미널판 Claude Code는 자기 색을 그대로 유지한다. 지금은 로컬 세션에서만 되고 클라우드 작업은 추후 지원 예정이다. 문서에는 배경 API가 `$.ui.backdrop`에서 `$.theme.set`/`$.theme.clear`로 바뀌었다(v2.1.319에서 구 API 제거)는 마이그레이션 안내도 있다. 터미널용 커스텀 테마(`~/.claude/themes/`)는 4월부터 있었지만, 데스크톱 앱이 이를 따르지 않는다는 기능 요청이 8월까지 열려 있었는데 그 공백을 mod 쪽으로 메운 셈이다.
- **Projects 업데이트(공개 베타, Pro·Max)**: Claude가 여러 작업을 **병렬로 진행하면서 질문에 답하고 각 작업 진행 상황을 알려주는** 프로젝트 매니저 역할을 한다. 작업 도중 다른 일을 끼워 넣거나 다른 방법을 시도하게 할 수 있고, 알림을 걸어 두었다가 나중에 이어 갈 수 있으며, 개별 작업을 링크로 공유할 수도 있다. 11/12에 다룬 [Cursor Projects 멀티플레이어 베타](ai-news-2026-11-12.md)와 이름·방향이 겹친다 — 둘 다 '여러 에이전트 작업을 한 화면에서 조율'하는 쪽으로 가고 있다.

TestingCatalog도 같은 날 "데스크톱 Claude Code가 mod를 통해 커스텀 테마를 지원한다"고 확인했다. 웹서치에서는 Claude Code 문서의 "Let Claude coordinate ongoing work with Projects" 페이지 제목까지 잡혔지만 외부 보도는 아직 없어, Projects 세부는 게시물·공식 문서 기준이다.

> 🔧 **적용 포인트** — Projects는 지금처럼 사이트 작업·성능 작업·뉴스 갱신을 worktree별 세션으로 따로 돌리는 방식을 한 곳에서 묶어 볼 수 있는 기능이라, 병렬 worktree 작업을 할 때 시험해 볼 만하다. 테마 mod는 생산성과는 무관하지만, 이 포트폴리오의 밤 광장·미술관 팔레트를 그대로 Code 탭 색으로 만들어 달라고 요청해 보면 mod 구조(`$.theme.set`, 렌더 사이트)를 익히는 가벼운 예제가 된다.

### 구글 Antigravity Dynamic Workflows — /run-workflow가 하위 에이전트를 돌리는 Python 스크립트를 먼저 써 보여주고, 검토한 흐름은 저장해 재사용

구글이 11월 14일 Antigravity에 **Dynamic Workflows**를 추가했다. `/run-workflow`를 입력하면 AI가 여러 하위 에이전트를 **동시에 또는 순서대로** 실행하는 **Python 코드**를 먼저 작성한다. 사용자는 실행 전에 이 코드를 검토할 수 있고, 완성된 흐름은 저장해 반복 실행할 수 있다.

[11/11에 공개된 /swarm 미리보기](ai-news-2026-11-11.md)가 "여러 에이전트를 팀으로 알아서 돌리는" 방식이었다면, Dynamic Workflows는 그 조율 로직을 **사람이 읽을 수 있는 스크립트로 꺼내 놓는** 쪽이다. 에이전트 오케스트레이션을 모델 내부 판단에 맡기지 않고 코드로 고정해 재현성과 검토 가능성을 얻는 패턴은 업계 전반에서 보인다 — Pydantic AI Harness의 `DynamicWorkflow`(모델이 `run_workflow` 도구 안에서 Python으로 하위 에이전트를 조합), Claude Code의 같은 이름 기능(생성된 스크립트가 곧 오케스트레이터)과 같은 계열이다.

TestingCatalog의 11월 14일 데일리 브리핑에서도 "/run-workflow가 하위 에이전트를 조율하는 Python 스크립트를 작성한다"고 같은 내용이 확인된다. 다만 웹서치 시점에 구글 공식 문서는 잡히지 않았다.

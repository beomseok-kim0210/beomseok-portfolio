## three.js 문법을 그대로 둔 채 렌더러만 레이트레이싱으로 바꾸는 엔진이 오픈소스로 나왔고, 앱 기능과 판단 모델은 API·공개 가중치로 풀렸다

### MeshyAI ThreeRT — three.js와 같은 문법으로 쓴 장면을 GPU 레이트레이싱 하드웨어로 60fps 경로 추적, Bistro 야경에서 three.js WebGPU 풀옵션(29fps)보다 빠르고 정답 렌더와의 색 오차는 3분의 1, 단 웹이 아니라 Rust·wgpu 네이티브 클라이언트

3D 생성 AI 회사 MeshyAI의 연구팀이 **ThreeRT**를 MIT 라이선스로 공개했다. 저장소 첫 줄은 "Hardware ray-traced three.js". three.js에서 쓰던 방식대로 `Scene`·`Mesh`·`MeshStandardMaterial`·`DirectionalLight`로 장면을 쓰면, 모든 빛을 GPU의 레이트레이싱 하드웨어로 추적해 **그림자·반사광(bounce light)·반사·스스로 빛나는 면이 방을 밝히는 효과**를 섀도맵·라이트 프로브·라이트맵 굽기 없이 실시간으로 낸다.

- **성능 비교(저장소 공개 수치)**: Amazon Lumberyard Bistro 야경, 1280×720, 같은 Mac에서 같은 장면 파일. ThreeRT는 프레임당 15.5ms(60fps)에 오프라인 정답 렌더(픽셀당 4,096샘플) 대비 색 오차(ΔE) 3.4. three.js r187을 WebGPU + SSGI + SSR + TRAA 풀옵션으로 돌리면 34.7ms(29fps)에 ΔE 10.1, WebGL로 튜닝하면 15.9ms(60fps)에 ΔE 12.1. 즉 같은 프레임 시간에서 정답과의 차이가 약 3~4분의 1이다. 저장소는 작은 장면에서는 three.js가 약 1ms로 훨씬 빠르다는 점도 함께 밝혔다(docs/COMPARE.md).
- **규모**: 도쿄 타워 시연에서 MacBook으로 삼각형 1,000만 개·광원 100만 개를 실시간 처리했다고 한다. 데모에는 간판 약 120개의 발광만으로 밝힌 신주쿠 가부키초 밤거리, Beeple의 Zero-Day, PLATEAU 도시 모델 기반 도쿄, 파괴 가능한 복셀 도시 등이 있다.
- **어떻게 돌아가나 — 중요한 제약**: 엔진은 **Rust + wgpu**로 짠 경로 추적기다(Metal·Vulkan의 하드웨어 레이 쿼리, 없으면 소프트웨어 BVH). 장면 코드는 엔진에 내장된 QuickJS에서 돈다. 즉 레이트레이싱은 **macOS(14+, Apple silicon)·iOS 17+ 무료 클라이언트(비공개 소스)** 에서 일어나고, 같은 주소를 일반 브라우저로 열면 **평범한 three.js로 그려진다**. 브라우저에서 레이트레이싱이 되는 라이브러리가 아니다. Windows·모바일·Steam Deck 지원은 게시물 설명이고, 저장소의 현재 다운로드는 Apple 플랫폼만 안내한다.
- **패키지**: `@threert/scene`(three.js 스타일 장면 API, PBR·glTF·물리), `@threert/gameplay`(결정적·재생 가능한 게임 상태 처리), `@threert/voxel`. `threert create`·`threert dev`로 프로젝트를 만들면 저장 시 번들링하고 휴대폰용 QR 코드를 띄운다. 사진을 참고해 코딩 에이전트로 장면을 만드는 'Scene authoring skill'도 들어 있다.

웹서치에서는 아직 ThreeRT를 다룬 외부 보도가 잡히지 않았고, 비슷한 시도로는 three.js 포럼의 `three-realtime-rt`(WebGL2 하이브리드 디퍼드 렌더러, BVH 소프트 섀도·1회 반사 GI·시간 누적 디노이즈), `three-gpu-pathtracer`, WebGPU 기반 Rayzee 등이 있다. 성능 수치는 모두 저장소 자체 측정이다.

> 🔧 **적용 포인트** — 이 포트폴리오는 R3F(웹) 위에서 돌아가므로 ThreeRT를 그대로 끼울 수는 없다. 대신 두 가지는 바로 쓸 만하다. ① **품질 기준선**: 미술관·밤 광장 장면을 `@threert/scene` 문법으로 옮겨 Mac 클라이언트에서 레이트레이싱 결과를 보면, 지금 섀도맵·환경맵으로 흉내 내는 조명이 '정답'과 얼마나 다른지 눈으로 비교할 수 있다. ② **비교 방법론**: 저장소의 docs/COMPARE.md처럼 "같은 장면 파일·같은 기기에서 프레임 시간 + 정답 대비 ΔE"로 재는 방식은, 셰이더 게이트나 픽셀 예산을 조정할 때 '느려진 만큼 예뻐졌나'를 숫자로 판단하는 데 그대로 가져다 쓸 수 있다. 브라우저에서 실제 GI가 필요하다면 `three-gpu-pathtracer`나 `three-realtime-rt` 쪽이 현실적인 후보다.

### DeepSeek 앱 기능 API 개방 — 검색·링크 읽기·파일·음성을 API로 열고, 백엔드 없이 브라우저에서 바로 붙는 MIT 채팅 데모를 Anthropic 호환 Messages API 위에 공개

DeepSeek가 자사 앱에서 쓰던 **웹 검색, 심층 검색, 파일 분석, 링크 읽기, 음성 대화, OCR** 등 핵심 기능을 API로 공개하고, 이를 조합한 채팅 화면 예제 **deepseek-ai/chat-demo**를 MIT 라이선스로 내놨다. 개발자가 DeepSeek 앱과 비슷한 앱을 만들거나 필요한 기능만 골라 새 서비스를 꾸릴 수 있게 하려는 것이다.

- **백엔드가 없다**: chat-demo는 정적 사이트다. 브라우저가 설정된 API 서버에 직접 연결하고, API 키와 설정은 localStorage, 대화와 원본 첨부는 IndexedDB에 저장한다. 릴리스 압축 파일을 풀어 `index.html`을 더블클릭해도 동작한다. 대화 분기 전환·재생성, 스트리밍·심층 사고·검색·링크 읽기·출처 인용, 첨부 업로드, 음성 입력·읽어주기, Markdown·KaTeX·Mermaid, ZIP 기록 내보내기/가져오기까지 들어 있다.
- **API 형식이 눈에 띈다**: 기본 모델은 `deepseek-flash`이고, **Anthropic 호환 Messages / Files API**로 호출한다. 음성은 별도 ASR/TTS 엔드포인트, 검색·링크 읽기·제목 생성은 요청 확장 필드로 붙는다. DeepSeek는 10월부터 자체 웹 인덱스를 개발자에게 열고 11월 1일부터 서버 측 Search/Fetch 과금을 시작했는데, 이번에는 그 위에 앱 기능 전체를 얹은 셈이다.
- **주의할 점**: 키를 브라우저 localStorage에 두는 구조라 **개인용·내부용 데모로는 편하지만, 그대로 공개 배포하면 키가 노출된다**. 공개 서비스로 쓰려면 앞단에 프록시를 두는 게 맞다(설정의 `apiOrigin`으로 바꿀 수 있다).

웹서치에서는 이번 개방을 다룬 기사가 아직 잡히지 않았고, 이전 자료에는 "API에는 파일 업로드 엔드포인트가 없다"는 설명이 남아 있어, 이번 공개로 상황이 바뀐 것으로 보인다. 세부는 저장소 기준이다.

> 🔧 **적용 포인트** — 이 포트폴리오의 도슨트 챗은 서버 라우트를 거치는 구조라 키 노출 문제는 없지만, chat-demo의 **SSE 처리(src/services/api)·메시지 분기·IndexedDB 기록 저장** 코드는 MIT라 참고하기 좋다. 특히 Anthropic 호환 Messages API를 쓰므로, 같은 형식의 요청 코드로 Claude와 DeepSeek를 바꿔 끼우며 응답 품질·비용을 비교하는 실험이 쉬워진다.

### Perplexity Decider v1.3 — 글 대신 확률을 내는 판단 모델의 후속판을 Apache 라이선스로 공개, 문서 속 값의 위치까지 짚는 locate 추가, OpenRouter 11월 19일까지 무료

Perplexity가 **Decider v1.3**과, 거기서 증류한 작은 모델 **Decider Flash v1.3**을 공개했다(블로그 11월 12일자, 스레드 소개는 15일). 10월의 v1.2·Flash v1.2 후속이다. 두 모델 모두 **Hugging Face에 Apache 라이선스**로 올라갔고, OpenRouter와 Perplexity Decisions API로도 쓸 수 있다.

- **판단 모델이란**: 글을 생성하지 않고 이진·다중 분류(순서 있는 라벨 포함)에 대해 **확률**을 돌려준다. 앱은 이 확률로 분류·라우팅·순위 매기기·평가를 한다. Perplexity는 TypeSafe AI의 System One 모델 'Jev'에서 영감을 받았다고 밝혔다. [11/12에 다룬 구글 Gemini Decision 1](ai-news-2026-11-12.md)과 같은 범주로, 판단 전용 모델 경쟁이 일주일 사이 공개 가중치 쪽으로도 번졌다.
- **v1.3에서 바뀐 점**: 양방향 어텐션, 더 정제한 학습 데이터, 다듬은 학습 레시피로 텍스트·비전 과제 전반의 성능과 견고성을 올렸다. 새 **locate** 기능은 문서에서 원하는 값을 찾아 **정확한 위치까지** 알려준다(예: 계약서의 당사자·금액 추출). 자체 평가에서 기존 분류 모델보다 정확도가 6.54%p 높았다고 한다.
- **비용**: OpenRouter에서 11월 19일까지 무료. 참고로 이전 Flash v1.2는 OpenRouter에서 입력 100만 토큰당 0.01달러였다.

자체 평가 수치이고 외부 벤치마크 재현은 아직 없다. 웹서치 결과는 대부분 v1.2 기준이라, v1.3 사실관계는 Perplexity 공식 블로그로 확인했다.

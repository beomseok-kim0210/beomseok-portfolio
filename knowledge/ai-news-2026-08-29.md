### 구글 안티그래비티 Teamwork, 에이전트 팀으로 수학 미해결 난제 7개 해결 — RISC-V 시뮬레이터·오픈소스 성능 최적화까지

Threads에 따르면 구글 리서치와 구글 딥마인드가 안티그래비티(Antigravity)의 멀티에이전트 프레임워크 Teamwork를 활용해 수학·이론전산학 미해결 문제 7개를 풀었다고 발표했다. 여러 에이전트가 사람 개입 없이 몇 시간에서 며칠에 걸쳐 해법을 제안하고, 서로의 풀이를 공격하며 검증하고, 살아남은 조각을 조합하는 방식이다. 40페이지짜리 증명은 Lean 형식 검증까지 통과했고 이 중 3개는 더 작은 Flash급 모델로도 재현됐다. 이 성과와 함께 운영체제까지 부팅할 수 있는 RISC-V CPU 시뮬레이터 개발, Eigen·ParlayHash 같은 실제 오픈소스 라이브러리에 반영된 성능 최적화도 함께 공개됐는데, 특히 이 모든 결과가 최신 Gemini 3.7 Flash 기반으로 만들어졌다는 점이 눈에 띈다.

웹서치로 교차 확인한 결과, 안티그래비티 공식 블로그("Teamwork: When AI Becomes a Research Partner")에 따르면 풀린 7개 문제에는 희소 볼록 최적화, 부분공간 근사, LLM 양자화 이론, 벡터 임베딩, Prefix-Matrix 분해, 커누스 사이클 추측(Knuth's Cycles Conjecture)이 포함되며 TCSBench에서 Gemini 3.7 Flash 기준 71%를 기록했다. RISC-V 시뮬레이터는 xv6 운영체제를 처음부터 부팅시키는 데 성공했고 골든 레퍼런스 대비 사이클 오차가 평균 0.71%에 불과했다. Eigen에는 GeMV 연산 개선이, ParlayHash에는 Swiss Table 기법을 접목한 "Swiss Parlay" 최적화가 실제로 머지돼 최대 2배 처리량 향상을 냈다. Teamwork는 문제 유형에 따라 반복 코딩·분산 코딩·장문 증명·자기 검증·문서 리뷰 5가지 "패턴" 중 하나를 자동 선택해 에이전트 구성과 진행 조건을 정하며, 실제로 무엇을 채택할지는 여전히 사람이 결정한다. 작고 빠른 모델이라도 오케스트레이션을 잘 설계하면 며칠짜리 연구·엔지니어링 작업까지 감당할 수 있다는 걸 보여준 사례다.

> 🔧 **적용 포인트** — Teamwork의 "여러 에이전트가 제안 → 서로 검증 → 살아남은 결과만 채택"하는 패턴은 이 세션에서 쓰는 Claude Code의 Workflow(pipeline/parallel) 오케스트레이션과 본질적으로 같은 구조다. 포트폴리오의 UI 컴포넌트나 [`src/features/docent`](src/features/docent) 같은 기능을 리팩터링할 때, 단일 에이전트에게 한 번에 맡기기보다 "구현 → 독립적으로 리뷰/검증 → 채택" 단계를 의식적으로 나눠 요청하면 결과 품질을 더 안정적으로 끌어올릴 수 있다.

### 버셀, 에이전트 전용 WebGPU 라이브러리 vGPU 오픈소스 공개 — 브라우저·헤드리스 Node·CI에서 동일 코드로 셰이더 개발

Threads에 따르면 버셀(Vercel)이 자사 vercel.com에서 셰이더를 배포하기 위해 내부적으로 쓰던 WebGPU 라이브러리 vGPU를 오픈소스로 공개했다. 브라우저와 헤드리스 Node.js에서 동일한 코드가 그대로 실행되고, CPU 샌드박스와 CI 환경에서도 렌더링 테스트가 가능하다. `.wgsl` 셰이더 파일을 재사용 가능한 모듈로 다뤄 의존성을 자동으로 해석하고 바인딩을 리플렉션하며 미사용 코드를 제거하는데, 이는 기존에 사람이 직접 관리하다 어긋나기 쉬웠던 바인딩 선언 문제를 없앤 것이다. 특히 AI 에이전트가 시각 효과를 만들고 수정한 뒤 스스로 테스트까지 이어갈 수 있도록 설계된 "에이전트 퍼스트" 도구라는 점이 특징이다.

웹서치로 교차 확인한 결과, GitHub 저장소(vercel-labs/vgpu)와 MarkTechPost 보도에 따르면 vGPU는 MIT 라이선스의 TypeScript 라이브러리로 `pnpm add vgpu`만으로 설치되며 호스팅 비용이나 계정, 사용량 제한이 없다. 헤드리스 Node.js 실행은 Dawn 백엔드로 처리되고, 테스트용 결정론적 목(mock) 어댑터도 함께 제공돼 완전한 풀스크린 이펙트가 gzip 기준 25KB로 압축되도록 CI에서 용량 예산까지 강제한다. `npx vgpu docs`, `npx vgpu examples`, `npx vgpu check` 같은 CLI로 문서·예제·셰이더 검증을 모두 커맨드라인에서 처리할 수 있고, vgpu.sh는 agents.md·llms.txt와 함께 토큰 없이 접근 가능한 예제 탐색 API, 읽기 전용 MCP 서버(vgpu.sh/api/mcp)까지 제공해 LLM이 직접 문서를 소비하도록 만들었다. 모델을 브라우저에서 직접 구동하는 흐름에 이어, 이제 그래픽 제작 자체도 에이전트가 웹 안에서 다루는 흐름으로 넘어가고 있다는 평가다.

> 🔧 **적용 포인트** — 이 포트폴리오는 [`src/features/docent/AvatarCanvas.tsx`](src/features/docent/AvatarCanvas.tsx), [`src/components/project/hangarae/HangaraeAvatarCanvas.tsx`](src/components/project/hangarae/HangaraeAvatarCanvas.tsx) 등 R3F 기반 캔버스를 여러 개 쓰고 있는데, 커스텀 배경·파티클 이펙트를 WGSL 셰이더로 직접 짤 계획이 있다면 vGPU로 헤드리스 Node 환경에서 셰이더 컴파일·렌더링을 먼저 검증한 뒤 R3F 컴포넌트에 붙이면, 브라우저를 매번 열어보지 않고도 셰이더 문법 오류를 CI 단계에서 잡을 수 있다.

### 텐센트 Hy4-preview, 770B 모델을 1.5TB→200GiB로 압축 — 레이어별 차등 정밀도 양자화로 성능 손실 최소화

Threads에 따르면 텐센트가 지난 8월 28일 공개한 신형 플래그십 모델 Hy4-preview(770B 파라미터, 토큰당 49B 활성화 MoE, 100만 토큰 이상 컨텍스트)에 대해, 자체 압축 툴킷 AngelSlim이 원본 1.5TB를 약 200GiB(원본의 약 13%)까지 줄인 GGUF 버전을 내놨다고 전했다. MIX-STQ1_0이라는 양자화 방식은 모든 레이어를 균일하게 줄이는 대신 보정 데이터를 분석해 레이어마다 1.31~2.06비트의 서로 다른 정밀도를 적용하는데, 그 결과 MCP Atlas 83.7→83.2, SWE-Bench multi 82.9→81.3, MRCR 81.3→81.1로 성능 손실이 크지 않았다.

웹서치로 교차 확인한 결과, TechNode 보도에 따르면 Hy4-preview는 203개 엔지니어링 과제를 163명의 전문가가 평가한 내부 테스트에서 4점 만점에 2.99점을 받아 GLM-5.3(2.92)과 Kimi K3(2.94)를 앞섰고, 흥미롭게도 모델 스스로 자사의 학습·추론 시스템 일부를 최적화해 엔드투엔드 처리량을 기준 대비 31.8% 끌어올리는 데 기여했다고 밝혔다. WorkBuddy·CodeBuddy를 통해 2주간 무료로 이용할 수 있으며, API 가격은 텐센트 클라우드·OpenRouter 기준 입력 100만 토큰당 0.834달러, 출력 100만 토큰당 2.501달러다. GitHub의 AngelSlim 저장소에는 1.25비트급 STQ1_0 커널을 llama.cpp에 반영하는 PR(#22836)이 올라와 있어, 조만간 커뮤니티 GGUF·MLX 빌드에도 이 기법이 널리 퍼질 것으로 보인다. 대형 오픈 가중치 모델이 나오자마자 하루이틀 만에 로컬 구동 가능한 압축판이 뒤따라 나오는 흐름이 이번에도 반복됐다.

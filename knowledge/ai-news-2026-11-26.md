### 오픈AI '행렬 곱셈 지수는 9/4다' — 10월에 2.25까지 내린 상한에 같은 값의 하한을 붙여 1969년부터 열려 있던 ω를 닫았다는 111쪽 프리프린트, Lean 검증은 나눗셈 없는 회로 범위만

[10/7에 정리한 오픈AI 미공개 모델의 수학 원고 722편](ai-news-2026-10-07.md)의 후속이다. 그 묶음 안에 행렬 곱셈 지수 ω를 2.371대에서 **9/4(=2.25) 이하**로 끌어내린 상한 결과가 있었는데, 오픈AI가 이번에 `openai/math` 저장소에 111쪽 논문 '행렬 곱셈 지수는 4분의 9다'를 올려 **ω가 2.25보다 작을 수 없다는 하한**까지 채웠다고 주장했다. 저자는 역시 이름이 공개되지 않은 내부 모델이다. 위가 막히고 아래가 같은 숫자에서 만나면 n×n 행렬 곱의 점근 복잡도가 정확히 n^2.25로 정해진다. 세바스티앙 부벡은 "살아서 볼 거라고 생각하지 못한 결과"라고 적었다.

choi.openai 정리(21편 스레드)의 핵심 숫자:

- **역사**: 교과서 방식은 n³. 1969년 슈트라센이 2×2 곱셈을 8번→7번으로 줄여 지수를 2.807로 내린 뒤 1981년 2.522, 1990년 2.376까지 왔다가 36년 동안 0.005도 못 줄였다. 올해 8월 기록이 2.371177이었다.
- **하한이 새로운 이유**: 지금까지 사람이 증명한 하한은 대략 n²의 3배 수준, 지수로는 여전히 2였다. 학계 다수는 답을 2로 예상했는데, 논문은 그 기대와의 차이를 n^(1/4)로 못 박았다(한 변이 1만이면 10배, 1억이면 100배). 논문은 곱셈·나눗셈이 n^2.25의 절반보다 적을 수 없다는 구체적 바닥도 적었다.
- **증명 줄거리**: 행렬 곱이 2.25제곱보다 빠르다고 가정하면 여러 명단의 중복을 확인하는 계산을 말이 안 될 만큼 싸게 압축할 수 있고, 이 계산에는 이미 증명된 최소 비용이 있어 모순이 난다는 구조다.
- **같은 날 올라온 다른 결과**: 푸리에 변환을 N·√(log N) 수준까지 줄일 수 있고 거기가 바닥이라는 주장, 선형계획(스메일의 9번 문제) 알고리즘 등 7편이 '텐서의 기하학' 한 틀로 묶여 나왔다.

교차 확인해 보면 **상한 쪽은 이미 독립 검증이 쌓였다.** 라파엘 패스가 2주 만에 실제로 따라 할 수 있는 재귀 알고리즘(O(n^(9/4+γ)) 정수 연산)을 냈고, 아마노프·판덴베르흐 등이 복소수에서 모든 체로 넓혔다. 반면 **하한은 아직 동료 심사 전 프리프린트**이고, Lean 형식화가 다루는 범위도 "나눗셈을 쓰지 않는 회로에서 모든 체에 대해 9/4"로 좁다. 그리고 패스가 지적했듯 9/4 알고리즘은 O(·) 안의 상수가 너무 커서 실제 GPU에 쓸 수 없는 '은하급(galactic)' 알고리즘이다.

개발자 입장에서 당장 바뀌는 건 없다. GPU는 지금도 대부분 교과서 방식으로 곱하고(텐서 코어가 그걸 하드웨어로 빠르게 할 뿐), 슈트라센 방식조차 메모리 왕복 비용 때문에 이제야 컴파일러 수준에서 일부 들어오는 중이다. 오히려 choi.openai가 짚은 대로 "정확한 곱셈의 바닥이 정해졌으니, 다음 절감은 곱할 필요가 적은 모델(저정밀·삼진 가중치·MoE)에서 나온다"는 쪽이 실무에 가까운 메시지다.

### Claude Code 2.1.332, MCP 서버가 자기 스킬을 함께 배포(베타) — 서버를 연결하면 server:skill 이름으로 슬래시 메뉴에 뜨고, 인라인 셸 명령을 막는 PreSkillShellCommand 훅이 추가됐다

testingcatalog의 11/25 브리핑에 한 줄로 올라온 소식이다: "MCP 서버가 이제 자체 스킬을 함께 실어 보낼 수 있어서, Claude Code가 처음부터 사용법을 안다." 교차 확인하면 앤트로픽은 11월 24일 **Skills over MCP**를 Claude·Claude Code 공개 베타로 열었고(Pro·Max·Ultra는 기본 켜짐, Team은 관리자가 켜야 함, Enterprise는 예정), 11월 25일 Claude Code **2.1.332** 릴리스 노트에 "Added skills from MCP servers (beta)"가 들어갔다.

- **보이는 방식**: 서버가 제공한 스킬은 슬래시 메뉴에 `server:skill` 형태로 뜬다. 기존 로컬·플러그인 스킬 이름은 그대로다.
- **보안 장치**: 같은 릴리스에 **`PreSkillShellCommand` 훅 이벤트**가 추가됐다. 스킬이나 명령이 로드될 때 들어 있는 인라인 셸 명령을 훅에서 거부할 수 있다. 원격 서버가 보낸 스킬 문서가 셸을 건드리는 경로를 사용자 쪽에서 막을 수 있게 한 것이다.
- **맥락**: VS Code는 1.147부터 1주 먼저 MCP 서버에서 스킬을 불러오기 시작했고, Speakeasy도 11월 3일 자사 MCP 서버에서 스킬을 직접 서빙하기 시작했다. 지금까지 스킬은 플러그인(`.claude-plugin/plugin.json`)에 MCP 서버와 함께 묶어 배포하는 게 정석이었는데, 서버 하나만 연결하면 "도구 + 그 도구를 쓰는 요령"이 같이 들어오는 구조로 바뀌는 중이다.

다만 서버 작성자가 스킬을 어떻게 패키징하는지에 대한 공식 문서는 아직 얇다는 지적이 있고, 위 세부 내용 상당수는 2차 매체가 인용한 체인지로그 문구다.

> 🔧 **적용 포인트** — 이 포트폴리오 작업에 쓰는 MCP(Figma·브라우저 등)를 연결해 둔 상태라면, Claude Code를 2.1.332 이상으로 올린 뒤 슬래시 메뉴에 `서버이름:스킬` 항목이 새로 생기는지 확인해 보자. 모르는 서버가 보낸 스킬이 셸 명령을 실행하는 게 꺼려지면 `settings.json`에 `PreSkillShellCommand` 훅을 걸어 인라인 셸을 로그로 남기거나 거부하도록 해 두는 게 안전하다.

### 리만 가설 Lean 증명, 1,740만 줄에서 7만 6,000줄로 — 앤트로픽 연구진이 Claude와 다시 쓴 grh-lean, 디리클레 L-함수 GRH까지 기계 검사만 통과

[11/21 알푀게의 리만 가설 Lean 증명 공개](ai-news-2026-11-21.md)와 [11/22 Lean·Mathlib 커뮤니티 공식 인증](ai-news-2026-11-22.md)의 후속이다. 깃허브 `lsernau/grh-lean` 저장소가 "A short Lean 4 proof of the Generalized Riemann Hypothesis"라는 이름으로 공개됐다. README는 "레벤트 알푀게의 (Claude와 함께한) 증명을 바탕으로 한 더 짧은 버전"이고 "앤트로픽 동료들, 그리고 Claude와 함께 만들었다"고 밝힌다(Apache 2.0, Copyright 2026 Anthropic, PBC).

- **분량**: 사람이 읽기 쉬운 `grh/` 판은 약 30만 줄, 같은 다섯 정리를 담은 `grh-compact/` 판은 **약 7만 6,000줄**이다. choi.openai는 원래 1,740만 줄 대비 99.56%, 약 229배 압축이라고 계산했다(1,740만 줄이라는 원래 규모는 이번 README에는 나오지 않는다).
- **범위**: 리만 가설과 **디리클레 L-함수에 대한 일반화된 리만 가설(GRH)**. 쓰인 공리는 `propext`·`Classical.choice`·`Quot.sound` 세 개뿐이라고 적었다.
- **빌드**: Lean v4.35.0 + 지정된 Mathlib 커밋, 12코어·24GB 메모리에서 1~2시간.
- **상태**: README 스스로 "기계 검사만 통과했다. 끝까지 읽은 수학자는 없고, 함께 나오는 논문도 없다"고 적었다.

압축 자체가 의미 있는 이유는 검증 비용 때문이다. 1,700만 줄은 독립 재검증 한 번에도 큰 계산 자원이 들지만, 7만 6,000줄이면 개인 연구자도 노트북급 장비에서 다시 컴파일해 볼 수 있다. 위의 행렬 곱셈 결과까지 포함해, "AI가 쓴 증명은 Lean으로 들고 온다"가 이번 주 업계 표준처럼 굳어지고 있다.

### ChatGPT Sites 호스팅 과금 일정 — 2027년 1월 31일까지 무료, 2월 1일부터 월 기본 제공량 초과분 과금, 빈 DB 사이트 하나가 월 25크레딧

swhan0329_이 정리한 ChatGPT Sites 업데이트로, 공식 'Usage and cost' 문서에서 숫자를 확인했다.

- **새 기능**: Remix로 기존 사이트를 새 사본으로 복제(원본은 그대로, DB 기록·업로드 파일은 복제되지 않음), 지원 환경에서 사이트 소유자가 주간 대시보드·리포트 업데이트를 클라우드 일정으로 예약.
- **일정**: 2027년 1월 1일부터 앱에서 호스팅 사용량 표시, 1월 31일까지 호스팅 무료, **2월 1일부터 Plus·Pro·Business에 월 기본 제공량 초과분 과금** 예정. Enterprise는 계약을 따르고 현재 실행·호스팅 요금이 면제된다.
- **월 기본 제공량**: Plus 125, Pro 375, Business 좌석당 125크레딧. 한 계정의 모든 사이트가 나눠 쓴다.
- **단가(대략)**: 저장소 없는 사이트 0, **빈 DB라도 DB가 있으면 사이트당 월 25크레딧**, 트래픽 10만 요청당 15크레딧, DB 저장 GiB·월당 150, 파일 저장 GiB·월당 3.75, 커스텀 도메인 월 25(등록비 별도).
- **주의할 점**: 페이지 한 번 방문이 보통 **30~50 요청**을 만든다고 문서가 적었다. 즉 10만 요청은 대략 2,000~3,000 방문이다. Plus 125크레딧이면 DB 사이트 2개(50) + 약 1만 2,000~2만 방문 정도가 기본 제공량 안에 들어가는 셈이다. 사이트를 만들고 고치는 작업은 Codex 사용량으로 따로 잡힌다.

공짜로 사이트를 여러 개 띄워 둔 사람은 1월 중 사용량 표시가 뜨면 DB가 붙은 사이트부터 정리하는 게 좋다. 빈 DB만 있어도 월 25크레딧이 나간다.

### Claude Code 초기 엔지니어 Thariq, 오픈AI 합류 — 제품 책임자 Cat Wu에 이어 두 번째 Claude Code 핵심 인력 이동

Claude Code 개발에 참여했던 Thariq Shihipar(@trq212)가 11월 25일(미국 시간) X에 "오픈AI에 합류했다"고 직접 발표했다. 10월 24일 1년 넘게 일한 앤트로픽을 떠난다고 밝히며 "쉬다가 새 일을 시작하겠다"고만 했었는데, 행선지가 오픈AI로 확인된 것이다. 소식은 하루 전 다른 계정을 통해 먼저 흘러나왔다. Codex·ChatGPT를 맡고 있는 오픈AI의 Andrew Ambrosino는 게시 직후 환영 답글을 달았고, choi.openai 정리로는 "이제 Codex를 다시 만들 차례"라고도 적었다. 맡을 역할은 공개되지 않았다.

앞서 Claude Code 제품 책임자였던 Cat Wu도 오픈AI Core Products의 PM 리드로 옮겼다. 두 사람 모두 Claude Code 초기 제품 방향(터미널 우선, 훅·스킬·서브에이전트 같은 확장 구조)에 깊이 관여한 인물이라, 당분간 Codex 쪽에 비슷한 개발자 경험 설계가 들어오는지 지켜볼 만하다.

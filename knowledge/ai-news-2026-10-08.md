## 작은 모델은 10분의 1 가격이 됐고, 챗봇의 답은 글에서 화면으로 바뀌었다

앤트로픽은 예고했던 Claude 5.5 라인업의 마지막 모델 Haiku 5.5를 내놨다. 정가는 전작의 10분의 1이고, 컴퓨터 사용 점수는 네 배 넘게 올랐다. 같은 날 오픈AI는 ChatGPT의 기본 답변을 GPT-6로 바꾸면서 답을 글 대신 버튼·차트·폼으로 그리는 Intelligent UI를 모든 사용자에게 열었다. 개발 도구 쪽에서는 앤트로픽 SDK가 Claude의 클릭·입력 요청을 직접 실행해 주게 됐고, 구글은 이미지 모델 나노바나나 2.1을 API까지 함께 내놨다.

### Claude Haiku 5.5 출시 — 입력 100만 토큰당 0.10달러, Haiku 최초 effort 조절, OSWorld 2.1에서 15.7%→72.4%

[9/23 Opus 5.5 발표](ai-news-2026-09-23.md) 때 "몇 주 안에"라고 예고됐던 Haiku 5.5가 10월 7일(미국 시간) 나왔다. [Sonnet 5.5](ai-news-2026-09-29.md)에 이어 5.5 세대가 모두 공개됐다. 앤트로픽은 "가장 싸고, 빠르고, 성능이 좋은 소형 모델"이라고 소개했다. Claude Platform·AWS·Google Cloud·Azure에서 바로 쓸 수 있고 모델 ID는 `claude-haiku-5-5`다.

- **가격**: 프롬프트가 10만 토큰 이하일 때 100만 토큰당 입력 0.10달러, 출력 0.50달러다. Haiku 4.5(1달러/5달러)의 정확히 10분의 1이다. 10만 토큰을 넘으면 입력 0.50달러, 출력 2.50달러로 오른다. 캐시 읽기는 0.01달러, 캐시 쓰기는 0.125달러다. 앤트로픽이 내세운 "평균 실행 비용 약 75% 절감"은 정가 인하폭(90%)보다 작다. 실제 작업에서는 토큰을 더 쓴다고 읽는 편이 안전하다.
- **effort 조절**: Haiku 계열 처음으로 Low부터 Max까지 effort를 고를 수 있다. 같은 모델로 분류 같은 가벼운 작업은 Low, 에이전트 작업은 High 이상으로 나눠 쓸 수 있다는 뜻이다.
- **벤치마크(앤트로픽 발표)**: 컴퓨터 사용 OSWorld 2.1 72.4%(Haiku 4.5 15.7%, Sonnet 5.5 83.9%, GPT-6 Luna 48.9%), Terminal-Bench 4.0 39.2%(Haiku 4.5 0.0%, Sonnet 5.5 70.6%), FrontierCode 1.1 46.4%(GPT-6 Luna 42.4%), GDPval-AA v2.1 1,620 Elo(Haiku 4.5 735)다. 컴퓨터 사용은 Sonnet과의 격차가 크게 줄었다. 반면 터미널 코딩은 여전히 Sonnet의 절반 수준이다.
- **겨냥하는 일**: 요약, 컨텍스트 압축(compaction), DB 질의, 분류, 서브에이전트, 고객 지원, 브라우저 자동화처럼 작은 요청이 시간당 수천 건씩 생기는 일이다. 9to5Mac·Seeking Alpha 등도 "비용에 민감한 작업용"이라는 앤트로픽의 설명을 그대로 전했다. 사이버보안 안전장치는 Haiku 4.5보다 엄격하지만 Sonnet 5.5보다는 느슨하다.

testingcatalog는 이 모델을 "역대 가장 빠르고 싼 Claude"로 정리하면서 컴퓨터 사용과 에이전트 코딩에서 크게 뛰었다는 점을 짚었다.

> 🔧 **적용 포인트** — `/docent`의 Anthropic 폴백 기본값이 아직 `claude-haiku-4-5`다(`src/lib/docent/llmProvider.ts`). 이걸 `claude-haiku-5-5`로 바꾸기만 해도 정가 기준 비용은 10분의 1이다. 다만 도슨트 답변은 짧은 RAG 응답이라 effort를 Low로 두고, 기존 정답 셋으로 답 품질과 응답 시간을 먼저 비교하자. 지금 기본 경로인 `gpt-5.6-luna`와도 같은 질문 세트로 비용·지연·말투를 나란히 재 보면, 기본 프로바이더를 다시 고를 근거가 생긴다.

### ChatGPT 기본 답변이 화면으로 — GPT-6와 Intelligent UI 전면 배포, 답을 생각하는 중에 UI부터 그린다

오픈AI가 10월 7일 GPT-6와 Intelligent UI를 ChatGPT 전체에 배포하기 시작했다. Plus·Pro·Business·Enterprise는 당일부터 **GPT-6 Sol**을, Free·Go는 다음 날부터 **GPT-6 Luna**를 쓴다. testingcatalog는 이번 배포에 GPT-6.1은 아직 포함되지 않았다고 짚었다.

- **무엇이 바뀌나**: 답이 글 위주에서 버튼·폼·인터랙티브 차트·편집 가능한 그래프·체크리스트·지도 같은 화면 요소로 바뀐다. 오픈AI 예시에는 손님 수를 바꾸면 재료 양이 다시 계산되는 레시피 위젯, 더치페이 계산기, 선택지형 후속 질문 등이 있다.
- **어떻게 빠른가**: MacRumors에 따르면 오픈AI는 "스트리밍 가능한 네이티브 컴포넌트 라이브러리"를 두고, 모델이 생성하는 동안 컴파일러가 화면을 바로 조립한다. choi.openai의 정리대로 GPT-6가 답의 내용과 함께 화면 구성까지 정하고, 답이 끝나기 전에 화면부터 그리는 구조다. The Decoder는 생각하는 도중에 답을 시작해 대기 시간이 44% 줄었다고 전했다.
- **범위와 한계**: Chat 탭에만 적용되고 Work·Codex 모델은 그대로다. 같은 컴포넌트를 외부 개발자가 쓸 수 있는 API나 Apps SDK 연동은 아직 공개되지 않았다. 구글은 비슷한 기능을 5월 Gemini에 먼저 넣었다.

choi.openai는 이를 "앱을 찾아가는 시대에서 앱이 찾아오는 시대"로 표현했다. 컴포넌트 세트가 템플릿처럼 확장되면 상황마다 개인화된 UI가 생성될 것이고, 상시 에이전트 [dots](ai-news-2026-09-30.md)와 결합될 때 효과가 클 것이라는 전망이다.

> 🔧 **적용 포인트** — 이 구조에서 가져올 만한 건 "모델이 HTML을 쓰지 않고, 미리 만든 컴포넌트 중에서 고르고 값을 채운다"는 설계다. 도슨트 답변에 `{ type: "project-card" | "timeline" | "tech-stack", props }` 같은 작은 스키마를 정의하고, 스트리밍 중 블록 단위로 React 컴포넌트를 렌더링하면 된다. 생성 코드를 실행하는 위험 없이 답을 카드·타임라인으로 보여줄 수 있다. 컴포넌트 등장은 framer-motion `layout` 애니메이션으로 처리하면 된다.

### 앤트로픽 SDK에 computer·browser use 툴셋 내장 — tool_runner에 드라이버만 꽂으면 클릭 루프를 SDK가 돈다

앤트로픽이 Python·TypeScript SDK에 computer use와 browser use 툴셋을 기본으로 넣었다. 이전에는 Claude가 "여기 클릭", "이 키 입력"을 요청하면 개발자가 반복 루프와 명령 변환 코드를 직접 짜서 실제 브라우저·데스크톱에 전달해야 했다. 이제는 `client.beta.messages.tool_runner`에 **드라이버**를 넘기면 SDK가 그 과정을 맡는다(choi.openai 정리, 공식 문서 "Browser and computer use with the SDK toolsets").

- **툴셋 두 가지**: `browser_toolset_20260801`은 접근성 트리·요소 참조·폼 입력·탭을 읽는 31개 도구다. 기본 27개가 켜져 있고 `javascript_exec`·`file_upload`·콘솔·네트워크 읽기는 직접 켜야 한다. `computer_toolset_20260801`은 스크린샷과 좌표로 데스크톱 전체를 다루는 17개 도구다. 두 툴셋은 8월 19일 API에서 GA됐다. 이번 소식은 SDK가 실행 루프까지 처리하게 됐다는 점이다.
- **드라이버**: Browser Use, Browserbase, E2B, Daytona가 드라이버를 낸다. 예를 들어 Daytona의 `daytona-claude-toolsets` 0.1.0(10월 7일 배포, `anthropic>=1.12.0` 필요)을 쓰면 Claude는 격리된 샌드박스의 데스크톱·Chromium을 조작한다. API 키와 모델 루프는 내 프로세스에 남는다.
- **비용·주의점**: 도구 선언만으로 입력 토큰이 browser use 약 6,600개(옵트인 포함 시 +880), computer use 약 4,500개 든다. 페이지 이동 뒤에는 요소 참조가 무효가 된다. 페이지 내용은 모두 신뢰할 수 없는 입력으로 다루고, 브라우저 프로필 격리와 네트워크 허용 목록을 두라는 권고가 붙었다. 위의 Haiku 5.5가 브라우저 자동화를 주요 용도로 내세운 것과 같은 날 나온 소식이다.

> 🔧 **적용 포인트** — 포트폴리오의 3D 씬·스크롤 연출 회귀 검사를 Claude에게 맡기는 스크립트를 수십 줄로 만들 수 있게 됐다. 로컬 dev 서버를 대상으로 browser 툴셋을 붙이고 "각 섹션까지 스크롤하며 스크린샷을 찍고 콘솔 에러·깨진 레이아웃을 보고하라"는 목표만 주면 된다. 반복 실행용 모델은 Haiku 5.5(effort Low)로 두면 1회 비용이 거의 들지 않는다. 툴 선언 토큰이 고정으로 6~7천 개 붙으므로 프롬프트 캐싱은 꼭 켜자.

### 구글 나노바나나 2.1 — 부분(마스크) 편집·인물 일관성·글자 렌더링 강화, Pro를 자체 평가 10개 항목에서 앞섰다

구글이 10월 6일 이미지 생성·편집 모델 나노바나나 2.1을 공개했다. 이전 Nano Banana 2(Gemini 3.1 Flash Image)의 후속이다. ai.trend.kr에 따르면 구글 자체 평가 10개 항목 모두에서 상위 모델 나노바나나 Pro를 앞섰고, 개발자 가격은 이전 버전의 절반 수준이다. Gemini 앱, 검색 AI 모드, AI Studio에 차례로 적용되고 있다.

- **달라진 점**: 고칠 부분만 지정해 바꾸는 마스크 기반 편집, 여러 인물이 있어도 얼굴이 흐트러지지 않는 일관성(최대 4명), 포스터 글자·인포그래픽 배치 정확도가 핵심이다. 와이드·파노라마 비율에서 생기던 타일링 결함도 고쳐졌다.
- **API 사양**: 모델 코드는 `gemini-nano-banana-2.1`이다. 1K(기본)·2K·4K 출력과 1:8~8:1 극단 비율(2K·4K)을 지원한다. 참조 이미지는 한 요청에 최대 14장, 물체 일관성은 10개까지다. Thinking 수준(minimal·medium·high)과 구글 웹·이미지 검색 그라운딩을 쓸 수 있다. 반면 함수 호출·구조화 출력·캐싱은 지원하지 않는다. 공식 모델 문서에는 아직 가격이 적혀 있지 않다.

> 🔧 **적용 포인트** — 프로젝트 썸네일·OG 이미지를 같은 톤으로 맞출 때 쓸 만하다. 기존 대표 이미지 몇 장을 참조로 넣고(최대 14장), 마스크 편집으로 배경이나 문구만 바꾸면 시리즈 전체 스타일이 유지된다. 한글 문구 렌더링이 실제로 좋아졌는지는 AI Studio에서 2~3장 먼저 확인하고 쓰자.

## 클로드가 화면을 직접 조작하고, 쇼핑 에이전트 설계도까지 공개한 하루 — 메타는 한 달 만에 또 신모델

### 앤트로픽, Cowork·Claude Code에 컴퓨터 사용(Computer Use) 정식 도입 — macOS·Windows 베타로 화면 클릭·입력까지

Threads(choi.openai)에 따르면 앤트로픽이 Claude Cowork와 Claude Code에서 컴퓨터를 직접 조작하는 기능을 추가했다. 앱을 열고 클릭하거나 입력하는 작업을 Claude가 대신 처리하며, macOS에서는 백그라운드 창에서 실행돼 사용자가 다른 작업을 하는 동안에도 계속 진행할 수 있다. 현재 Pro·Max 요금제의 Claude Desktop에서 베타로 제공되며 macOS와 Windows를 지원한다.

웹서치로 교차 확인한 결과, 앤트로픽 공식 헬프 센터와 Engadget·The New Stack 보도에 따르면 이 기능은 macOS·Windows용 Claude Desktop 앱에서 Pro·Max 플랜에 한해 제공되고(Team·Enterprise는 아직 미지원), 최신 버전으로 업데이트한 뒤 설정에서 "Enable computer use" 토글을 켜야 쓸 수 있다. macOS 15 이상에서는 기본적으로 백그라운드 창에서 동작해 마우스·키보드를 뺏지 않고, 사용자가 실제로 타이핑 중이면 대체로 동작을 멈춘다. Claude는 화면을 스크린샷으로 읽어 앱을 조작하는 방식이라 Claude와 애플리케이션 사이에 별도 샌드박스가 없으며, 은행·의료·투자 같은 민감 앱은 기본적으로 차단되고 사용자가 직접 차단 목록을 추가할 수도 있다. 앤트로픽은 아직 안전장치가 진화 중인 베타 단계이니 신뢰할 수 있는 앱부터 시작하고 Claude의 동작을 계속 지켜보라고 권고한다.

> 🔧 **적용 포인트** — 공교롭게도 이 노트를 쓰는 이번 회차 작업에서 `list_connected_browsers`로 확인해보니 연결된 Chrome 확장이 하나도 없어, 원래 우선순위였던 실제 브라우저 대신 별도 프리뷰 브라우저로 Threads·Instagram을 훑어야 했다. Computer Use가 더 안정화되면 이런 예약 작업에서 macOS·Windows Claude Desktop의 백그라운드 창을 통해 실제 브라우저를 직접 조작하는 경로도 대안이 될 수 있어 보인다. 다만 지금은 Claude Code CLI 세션이 아니라 별도 Claude Desktop 앱 전용 기능이라 이 워크플로우에 바로 붙일 수는 없고, 베타 단계인 만큼 민감 앱 차단 목록부터 챙기는 게 우선이다.

### 앤트로픽, 쇼핑·판매자 에이전트 청사진 "Claude Commerce Agents" 오픈소스 공개 — 장바구니 규모 35%↑, 구매전환 60%↑

Threads(choi.openai)에 따르면 앤트로픽이 쇼핑 AI 에이전트를 만드는 방법을 통째로 오픈소스로 공개했다. Claude Commerce Agents에는 상품을 찾고 비교해 장바구니를 구성하는 쇼핑 에이전트와 판매·재고·가격·프로모션을 관리하는 판매자 에이전트가 포함되며, 리테일뿐 아니라 여행·통신·티켓 예매까지 참고 구현을 제공한다. 앤트로픽은 여러 서브에이전트로 쪼개는 방식보다 하나의 에이전트에 Skills를 붙이는 구조가 품질·비용·속도에서 더 나았다고 설명했다. 실제 도입 기업에서는 장바구니 금액이 최대 35% 커지고 구매 완료 가능성도 60% 높아졌으며, Claude Code 플러그인까지 제공해 기존 백엔드에 맞는 에이전트를 직접 만들 수 있다.

웹서치로 교차 확인한 결과, 앤트로픽 공식 블로그(claude.com/blog/claude-for-commerce-agents)와 GitHub(github.com/anthropics/commerce-agents)에 따르면 쇼핑 에이전트는 다중 상품 검색·개인화 추천·비교·장바구니 구성·고객 응대까지 한 대화 안에서 처리하고, 판매자 에이전트는 판매 실적 분석·재고 알림·가격/프로모션 추천·마케팅 캠페인 초안까지 맡되 실제 변경은 사람이 승인하는 구조다. 두 에이전트 모두 카탈로그 검색·재고 관리·개인화·분석용 도구를 각각의 Skill로 조직하는 방식을 쓰고, Claude API·Amazon Bedrock·Microsoft Foundry·Google Cloud Vertex AI로 배포할 수 있으며 Shopify는 이 청사진을 자사 Admin API 위에 그대로 구현한 예제 저장소(Shopify/claude-for-commerce-examples)를 함께 내놓았다.

> 🔧 **적용 포인트** — [`src/lib/docent`](src/lib/docent)·[`src/app/api/docent/chat/route.ts`](src/app/api/docent/chat/route.ts)의 도슨트 챗도 결국 하나의 에이전트가 페르소나·검색(retrieval)·응답 생성을 담당하는 구조다. 앞으로 도슨트에 기능을 더 붙일 일이 생기면, 이번 발표에서 앤트로픽이 명시한 "서브에이전트 분리보다 하나의 Agent에 Skills를 붙이는 편이 낫다"는 권고와 `github.com/anthropics/commerce-agents` 저장소의 스킬·툴 계약(tool contract) 분리 방식을 구조 참고용으로 살펴볼 만하다.

### 메타, Muse Spark 1.3 공개 — DeepSWE 1.1서 Opus 5·GPT-5.6 Sol 제치고 4주 만에 또 신모델

Threads(choi.openai·testingcatalog)에 따르면 메타가 한국 시간 9월 3일 새벽 Muse Spark 1.3을 공개했다. 메타 슈퍼인텔리전스 랩이 4월에 첫 Muse Spark를 내놓은 뒤 7월 9일 1.1, 8월 6일 1.2에 이어 5개월 사이 네 번째 모델이자, 1.2에서 1.3까지는 4주밖에 걸리지 않았다. 당일부터 터미널 코딩 에이전트 Muse Code와 개발자용 Meta Model API, OpenRouter에서 쓸 수 있다. 긴 호흡의 실제 개발 과제를 재는 DeepSWE v1.1에서 1.3은 75.4%를 받아 1.2의 55.0%에서 20점 넘게 올랐고, Claude Opus 5의 74.0%와 OpenAI GPT-5.6 Sol의 73.0%보다 높다. 터미널 코딩 Terminal-Bench 2.1은 88.8%로 Sol과 동률, 25만~100만 토큰 구간의 긴 문맥 검색(MRCR)은 66~98% 수준으로 크게 향상됐다. 다만 표에서 1.3은 가장 높은 추론 강도 max(공개 시점 기준 아직 일반 사용자에게 열리지 않음)로 측정된 반면 비교 대상인 1.2·Opus 5·Sol은 그보다 낮은 설정으로 측정됐다는 단서가 붙는다.

웹서치로 교차 확인한 결과, Neowin·officechai·daily.dev 보도에 따르면 저커버그는 이번 릴리스를 "거의 계량할 필요가 없을 만큼 싼 프런티어 성능"이라 소개하며 코딩·에이전트 작업에서 자사 최대 개선폭이라고 밝혔고, 근시일 내 오픈 웨이트 버전도 내놓겠다고 예고했다. DeepSWE 외에 SWEAtlas 코드베이스 질의응답 59.4%, MRCR 256K~512K 구간 98.5%·512K~1M 구간 98.1%로 긴 문맥 벤치마크에서 비교군 중 최고치를 기록했다. 다만 실무 과제 전반을 재는 GDPval에서는 Opus 5(1824점)에 못 미치는 1754점에 그쳐, 코딩·긴 문맥에 특화된 개선이라는 평가다.

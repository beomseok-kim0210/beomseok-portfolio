## 새 최상위 모델일수록 '최대로 돌리기'가 답이 아니다 — Fable 5.2를 쓰기 전에 정할 세 가지

### Fable 5.2 운용법 — 추론 강도는 high부터(max는 Vals 종합 1위→7위·비용 약 3배), 일상 작업은 Opus 5.5로 시작해 큰 작업만 Fable로 올리고, '보존된 사고' 때문에 대화 앞부분은 고치지 말고 뒤에만 덧붙인다

[같은 날 뉴스 노트](ai-news-2026-11-10.md)에서 다룬 Fable 5.2 발표에는 성능 수치 외에 "어떻게 쓰라"는 가이드가 꽤 구체적으로 붙어 있었다. choi.openai의 출시 스레드와 앤트로픽 발표문을 기준으로 실무에 바로 걸리는 것만 추렸다.

**1. 추론 강도(effort): 기본값부터, max는 쓰지 않는다**
- 기본값은 Claude 앱 **medium**, 개발자 플랫폼 **high**. xhigh는 "효과가 확인된 가장 어렵고 오래 걸리는 에이전트 작업"에만, max는 "한계를 찾는 용도"라며 일상 사용을 권하지 않았다.
- 근거가 숫자로 나왔다. 외부 평가기관 Vals AI에서 max로 올리자 종합 순위가 **1위→7위**로 떨어졌고, 과제당 비용은 17.94달러→49.62달러로 3배 가까이 늘었다. 시간·토큰이 바닥나 과제를 끝내지 못한 경우가 많았다. 세무(+8.8%p)·법률 리서치(+4.3%p)처럼 max가 나은 영역도 있었지만, **바이브 코딩 평가는 17.8%p 하락**했다.
- ARC-AGI-3에서도 max 설정은 55개 게임 중 28개가 12시간 제한에 걸려 65.7%에 그쳤다. 강도를 올리면 '더 똑똑해지는' 게 아니라 '더 오래 붙잡는' 쪽으로 기울 수 있다는 뜻이다.

**2. 모델 라우팅: Opus 5.5로 시작, 큰 일만 Fable**
- 앤트로픽은 대부분의 일은 Opus 5.5로 시작하고 큰 작업에서만 Fable로 올리라고 권했다. Fable 5.2는 High 설정만으로 FrontierCode 2.0에서 Opus 5.5 최고 설정과 비슷한 점수를 절반 정도 비용으로 냈고, Cognition은 가장 낮은 low 설정이 Fable 5.1 점수를 3분의 1 비용으로 넘었다고 밝혔다 — 즉 Fable을 쓰더라도 낮은 강도부터 시험해 볼 여지가 크다.
- 두 가지 조합 패턴도 안내했다. **조언자 방식**: 작은 모델이 일하다 어려운 지점에서만 Fable에게 묻는다. **지휘자 방식**: Fable이 계획을 세우고 작은 모델들에게 일을 나눠준다. 메타가 Muse Ember를 내며 권한 'Wonder가 계획, Ember가 물량' 조합과 같은 구도다.

**3. '보존된 사고'에 맞춰 대화 구조를 바꾼다(API 직접 호출 시)**
- 증류 방지 기능인 보존된 사고가 모든 API 계정의 Fable 5.2에 적용됐다. 이전 턴의 시스템 프롬프트·도구 정의·메시지를 중간에 고쳐 다시 보내면 **400 오류**가 날 수 있다.
- 대응은 "앞부분은 그대로 두고 뒤에만 덧붙이는" 구조다. 지시를 바꾸고 싶으면 대화 압축(compaction), 컨텍스트 편집, 대화 중간 시스템 메시지를 쓴다. Claude Code와 Agent SDK는 이를 알아서 처리한다.
- 사고 기록은 만든 계정에 묶여, 다른 계정의 키로 같은 대화를 이어 보내면 사고 블록이 빠진다. 여러 API 키를 돌려 쓰는 구조라면 확인이 필요하다.

> 🔧 **적용 포인트** — Claude Code에서 Fable 5.2를 쓸 때는 effort를 high(기본)로 두고, 셰이더·스크롤 타임라인처럼 여러 파일을 엮는 리팩터링에서만 xhigh를 시험해 보자. max는 바이브 코딩 평가에서 오히려 떨어졌으니 UI 반복 수정에는 쓰지 않는다.
> 포트폴리오 도슨트처럼 Claude API를 직접 호출하는 코드가 있고 모델을 Fable 5.2로 바꿀 계획이라면, 매 요청마다 시스템 프롬프트를 동적으로 재구성하는 부분이 없는지 먼저 확인한다. 이전 턴을 고쳐 보내는 구조라면 400 오류가 날 수 있으니, 바뀌는 정보는 맨 뒤 메시지에 덧붙이는 방식으로 옮기는 게 안전하다(현재 모델을 계속 쓸 거라면 급하지 않다).

### 앤트로픽, 클로드의 "가치"를 4개 축으로 압축 — 같은 모델도 언어 따라 성격이 바뀐다

앤트로픽이 7월 13일, 클로드 응답에 실제로 드러나는 가치를 정량 비교하는 새 연구를 공개했다. 작년 "Values in the Wild" 연구가 클로드 응답에서 가치 3,307개를 식별했다면, 이번에는 그 목록을 수작업으로 339개 상위 가치로 묶고 다시 4개 축으로 압축했다. 분석 대상은 2026년 5월 두 주간 실제로 오간 대화 30만 9,815건으로, Sonnet 4.6·Opus 4.6·Opus 4.7 세 모델과 상위 20개 언어에서 조합당 약 5,000건씩 고르게 뽑았다. 이직 상담이나 친구와의 갈등처럼 정답이 없는 주관적 대화만 골라, 어떻게 답하든 가치가 드러날 수밖에 없게 설계했다. 프라이버시 보존 분석 도구 Clio가 대화마다 가치 표현 여부를 라벨링했고, 과제·주제·사용자가 이미 드러낸 가치는 통제한 뒤 남은 변동에 차원 축소를 적용해 4개 축을 뽑아냈다 — ①동조 대 신중(맞춰주기 대 위험 차단), ②따뜻함 대 엄밀함(긍정·배려 대 정확성·정밀함), ③깊이 대 간결(맥락까지 대 요청받은 것만), ④솔직함 대 실행(불확실성 노출 대 자신 있는 완성도). 다만 이 4개 축은 통제 후 남은 가치 변동의 15%만 설명해, 나머지 85%는 아직 설명되지 않은 영역으로 남는다.

모델별로는 Sonnet 4.6이 따뜻함·동조가 가장 높아 유머를 섞고 사용자를 긍정하는 다정한 모델로, Opus 4.7은 신중·깊이가 높아 묻지 않아도 리스크를 경고하고 잘못된 전제를 반박하는 모델로 나타나 시장에서 이미 형성된 평판과 정확히 겹쳤다. 더 논쟁적인 결과는 언어별 차이다. 클로드는 힌디어와 아랍어로 물으면 공손한 표현과 유머, 사용자 아이디어에 대한 긍정이 두드러지는 반면, 영어와 러시아어로 물으면 전제를 의심하고 근거를 요구하는 엄밀한 쪽으로 기운다 — 같은 사업계획서라도 힌디어로 보여주면 후한 평을, 러시아어로 보여주면 깐깐한 평을 받을 수 있다는 뜻이다. 앤트로픽 스스로도 왜 이런 언어별 차이가 생기는지 명확한 원인을 모른다고 인정했으며, 언어별 학습 데이터의 양과 구성 차이라는 가설만 제시했다. "따뜻함 축이 사실상 아첨 축 아니냐"는 비판도 나오는데, GPT-4o 아첨 논란을 기억하는 커뮤니티가 특히 민감하게 반응하는 지점이다. 교차 확인 결과 이 연구는 Anthropic 공식 블로그(anthropic.com/research)와 Gizmodo·Decrypt 등 다수 매체로 보도되었으며, 연구에 쓰인 세 모델이 이미 단종되고 Opus 4.8·Sonnet 5가 프로덕션 기본값으로 넘어간 뒤에 나온 "지난 세대 회고" 성격의 연구라는 점도 확인된다.

> 🔧 **적용 포인트** — 이 포트폴리오처럼 한국어 콘텐츠 기반 사이트에 AI 기능(챗봇, 요약, 추천 문구 생성 등)을 넣는다면, 같은 프롬프트라도 언어·문체에 따라 모델 응답의 톤(단호함 대 다정함, 확신 대 신중)이 달라질 수 있다는 점을 감안해야 한다. 특히 사용자에게 노출되는 문구를 모델로 생성한다면, 한국어·영어 등 언어를 바꿔가며 같은 질의를 던져보고 어조가 의도한 브랜드 톤에서 벗어나지 않는지 확인하는 점검을 넣어두면 안전하다.

### 구글 Antigravity, 검증 3중 역할을 갖춘 "에이전트 팀" 기능 공개

구글이 Antigravity에 `/teamwork-preview` 명령으로 실행하는 **에이전트 팀(Agent Teams)** 기능을 밀고 있다. 명령을 실행하면 역할이 나뉜 서브에이전트 팀이 꾸려져 복잡한 개발 작업을 백그라운드에서 병렬로 계획·구현·검증한다. 구성은 작업을 쪼개는 오케스트레이터와 실제 구현을 맡는 워커 외에, 리뷰어·크리틱·오디터라는 검증 역할 셋이 추가로 붙는 7역할 구조다. 오디터는 테스트 출력을 하드코딩하는 식의 "모델 꼼수"를 잡아내는 감시자 역할을 맡는다. 서브에이전트마다 격리된 컨텍스트와 별도 git 워크트리를 받아 서로의 작업물을 덮어쓰지 않는다. 구글은 이 팀 구조로 서브에이전트 93개를 프롬프트 하나에서 동시에 굴려 12시간 만에 동작하는 OS를 917달러에 만들었다고 밝혔다. "결국 환각을 분산 처리할 뿐"이라는 회의적 반응도 있지만, 검증 역할을 셋이나 박아 넣은 설계 자체가 그 우려를 정면으로 겨냥한 것이다. 다만 이 기능은 월 200달러 요금제 전용이며, 작업 한두 개만으로 주간 쿼터가 바닥날 수 있다고 구글 스스로 경고했다. 교차 확인 결과 이는 워커·리뷰어·크리틱·오디터로 구성된 검증 삼중 패턴으로 다수 매체에 보도되었고, 비용 부담 때문에 Gemini 3.5 Flash 같은 경량 모델과 함께 쓰길 권장한다는 점도 확인된다.

> 🔧 **적용 포인트** — 이 포트폴리오의 AI 뉴스 자동화 파이프라인(수집→교차검증→요약)에도 같은 검증 삼중 패턴을 축소 적용할 수 있다. 지금은 사실상 "작성자"만 있는 구조인데, 여기에 "이 문장이 원문을 왜곡하지 않았는지 확인하는 리뷰어"와 "적용 포인트 제안이 실제로 이 스택(Next.js·R3F·GSAP)에 맞는지 검증하는 크리틱" 역할을 별도 에이전트로 분리해두면, 오디터 패턴처럼 결과물의 신뢰도를 구조적으로 높일 수 있다.

### Claude Code Artifacts, 공개 링크 공유·공동 편집 지원 — Slack Claude Tag와도 연동

Claude Code의 Artifacts에 협업 기능이 추가됐다. 코딩 세션 중 만들어지는 결과물을 이제 공개 링크로 공유할 수 있고, 여러 사람이 동시에 편집하는 것도 가능해졌다. 세션이 진행되는 동안 아티팩트 자체가 함께 갱신되어, 팀원이 실시간으로 작업 흐름을 따라가며 볼 수 있는 공유 시각 레이어 역할을 한다. Slack에서는 Claude Tag를 이용해 대화 중 바로 Artifacts를 만들 수도 있다. 앤트로픽은 Slack 채널 안에서 하나의 @Claude 계정을 여러 사람이 함께 쓰는 방식으로 Claude Tag 사용을 넓히고 있는데, 팀·엔터프라이즈 요금제에서는 8월 3일부터 기존 개인용 Claude를 이 공용 계정 방식이 대체할 예정이다. 교차 확인 결과 팀·엔터프라이즈 플랜은 아티팩트를 조직 외부에 공개 공유할 수는 없고 로그인한 조직 구성원 사이에서만 공유되는 제약이 있다는 점도 확인된다.

> 🔧 **적용 포인트** — Claude Code로 이 포트폴리오의 R3F 씬이나 인터랙션을 작업할 때, 완성 전 중간 산출물을 Artifacts 공개 링크로 만들어 두면 데스크톱 앱을 안 쓰는 사람에게도 스크린샷 없이 실시간 미리보기를 공유할 수 있다. 다만 지금은 개인 계정 기준 기능이므로, 나중에 팀 단위로 협업하게 되면 팀·엔터프라이즈 플랜의 "조직 내부 전용 공유" 제약을 미리 감안해야 한다.

### xAI Grok Build CLI, 저장소 전체를 몰래 자사 클라우드로 업로드 — "옵트아웃"도 무력화

큰 보안 이슈가 하나 드러났다. xAI의 코딩 에이전트 CLI **Grok Build**가 실행된 저장소 전체를 자사 클라우드로 업로드해온 사실이, 한 보안 연구자(핸들 cereblab)가 mitmproxy로 네트워크 트래픽을 직접 가로채 분석한 결과 드러났다. 12GB 저장소 기준 실제 코딩 작업에 필요했던 데이터는 192KB에 불과했는데, 별도 채널로 5.1GB가 `grok-code-session-traces`라는 xAI 저장 버킷에 올라갔다. 저장소를 통째로 묶어 올리는 방식이라, 에이전트에게 읽지 말라고 지정해둔 파일, 과거 커밋 이력, 이미 삭제된 시크릿까지 전부 딸려 올라갔다. 더 심각한 건 "모델 개선(Improve the model)" 옵트아웃 토글을 꺼도 업로드가 계속됐다는 점 — 서버 응답에는 여전히 `trace_upload_enabled: true`가 찍혔다. xAI는 분석 결과가 공개된 다음 날 서버 쪽 숨은 플래그로 업로드를 조용히 중단시켰을 뿐, 수집 범위나 삭제 계획에 대한 공식 발표는 이 노트 작성 시점까지도 없다. 교차 확인 결과 International Cyber Digest의 원 보도와 CryptoBriefing·IBTimes UK 등 여러 매체가 동일한 수치(5.1GiB 업로드, 실제 필요량 192KB)를 확인했으며, xAI가 2026년 7월 13일 기준 공식 입장을 내지 않았다는 점도 일치한다.

> 🔧 **적용 포인트** — 이 저장소에 Claude Code 외의 서드파티 코딩 에이전트(특히 CLI형)를 연결해 쓸 일이 생긴다면, "모델 개선 끄기" 같은 옵트아웃 설정을 그대로 신뢰하지 말고 실제 네트워크 트래픽을 한 번쯤 프록시로 확인해보는 습관이 안전하다. 특히 `.env`나 배포 키처럼 커밋 이력에 남아있는 과거 시크릿이 있다면, 저장소를 통째로 업로드하는 방식의 에이전트에는 아예 접근 권한을 주지 않는 편이 낫다.

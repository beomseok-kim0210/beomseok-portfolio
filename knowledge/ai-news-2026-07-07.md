### MIRA — 게임 엔진 없이 로켓리그 물리를 통째로 학습한 월드모델

General Intuition이 Epic Games와 협업해 공개한 **MIRA**는 5B 파라미터 확산 트랜스포머(diffusion transformer)에 600M 파라미터 비디오 표현 코덱을 결합한 월드모델이다. 공개된 봇 플레이 영상 1만 시간만으로 학습해, 자동차 이동·충돌·득점 같은 물리 법칙을 하드코딩된 게임 엔진 없이 신경망만으로 재현한다. 가장 주목받는 부분은 4인 동시 플레이의 일관성이다 — 각자 다른 화면에서 입력한 네 명의 키 입력을 하나의 물리적으로 일관된 세계로 통합해, 단일 Nvidia B200 GPU에서 실시간 20fps·576p로 렌더링한다. 짧은 클립으로만 학습했는데도 실측한 5분 구간까지 분포 품질이 유지되고, 실제로는 몇 시간을 굴려도 붕괴 조짐이 없었다고 밝혔다. 데이터셋과 학습·추론 코드도 함께 오픈소스로 공개했으며, 데이터가 훨씬 지저분하고 희소한 "피지컬 AI"로 가는 디딤돌이라는 설명이다.

### 백악관, AI 산업의 경제·의료 기여 강조

트럼프 대통령이 백악관 발언에서 AI 산업이 국가 경제와 의료 기술 분야에서 막대한 이익을 창출하고 있다고 언급했다. AI 기업들이 이미 상당한 수익을 올리고 있으며, 안전장치(가드레일)로 잠재적 위험을 관리하면서도 기술 발전과 경제 성장을 동시에 이끌 "거대 산업"이 될 것이라는 취지다. 교차 확인 결과 이는 트럼프 행정부가 올해 추진해 온 "AI Action Plan" 기조의 연장선으로, 규제를 최소화해 혁신을 촉진하는 대신 NIST 주도로 의료 등 분야별 표준·샌드박스를 마련하는 투트랙 접근이 배경에 있다. 실제로 올해 들어 2.7조 달러 이상의 AI·기술 투자가 미국에 유치됐다고 행정부는 주장한다.

### Claude Code, 루프를 공식 분류 — 턴 기반 vs 목표 기반(/goal)

그동안 커뮤니티가 "루프 엔지니어링"이라 부르며 제각각 정의해온 개념을, Claude Code 팀이 이번 주 공식적으로 정리했다. 루프란 "멈춤 조건에 닿을 때까지 에이전트가 같은 사이클을 반복하는 것"이며, 무엇이 시작·정지시키는지·어떤 기능을 쓰는지·어떤 일에 맞는지 네 축으로 나뉜다. 이 중 두 가지가 이번 스레드에서 다뤄졌다.

**턴 기반 루프**는 프롬프트 하나 안에서 이미 벌어지는 작은 루프다. Claude가 맥락을 모으고 행동하고 자기 점검을 한 뒤 필요하면 다시 돌고 나서 답을 낸다. 시작은 사람의 프롬프트, 멈춤은 Claude 스스로의 "됐다" 판단이다. 매번 사람이 눈으로 하던 점검을 `SKILL.md`에 규칙으로 적어두면 Claude가 그만큼 스스로 검사하고 넘어오는데, 점검 기준이 정량적일수록(테스트 통과, 점수 등) Claude가 통과 여부를 스스로 판정하기 쉽다. 예로 화면을 고쳤다면 "편집 완료"로 끝내지 않고 브라우저를 띄워 직접 눌러보고 상태 변화·콘솔 에러까지 확인하게 시키면 왕복 턴 수가 줄어든다.

**목표 기반 루프(`/goal`)**는 한 턴으로 끝나지 않는 작업에 쓴다. Claude가 멈출 시점을 스스로 정하게 두면 "이만하면 됐다"며 일찍 손을 떼는 문제가 있어서, 사람이 "done"의 정의를 미리 못 박아두면 Claude가 멈추려 할 때마다 평가 모델(기본 Haiku)이 조건 충족 여부를 확인하고, 미달이면 다시 작업을 시킨다. 목표 달성 또는 정해둔 시도 횟수 한도에 닿을 때까지 반복된다. 테스트 통과 개수나 라이트하우스 점수처럼 딱 떨어지는 기준일수록 잘 작동하며, 실제 공식 문서에서도 API 마이그레이션을 모든 호출부가 컴파일·테스트 통과할 때까지, 혹은 설계 문서의 인수 기준을 모두 충족할 때까지 반복시키는 용례를 제시한다. Claude Code v2.1.139 이상에서 지원되고 비대화형·데스크톱·Remote Control 환경에서도 동작한다.

> 🔧 **적용 포인트** — 이 저장소의 "매일 Threads AI 뉴스 큐레이션" 파이프라인 자체가 목표 기반 루프의 좋은 후보다. 예컨대 "신규 게시물 없으면 종료, 있으면 노트 작성 후 커밋·푸시까지 완료"를 done 조건으로 걸고 `/goal`로 돌리면, 지금처럼 매번 대화로 트리거하는 대신 완전 자동화에 가깝게 만들 수 있다. 또한 R3F 인터랙션 버그 수정처럼 "브라우저에서 클릭해보고 콘솔 에러 없음을 확인"하는 정량적 종료 조건을 `SKILL.md`에 미리 적어두면, 턴 기반 루프에서 Claude가 스스로 왕복 없이 검증까지 끝내도록 유도할 수 있다.

### Anthropic, 클로드 내부의 "조용한 사고 공간" J-space 발견

Anthropic이 7월 6일 언어모델 내부의 전역 작업공간(global workspace)을 다룬 해석가능성(interpretability) 연구를 공개했다. 기존에는 모델이 무슨 생각을 하는지 보려면 출력된 답변이나 스스로 적어 내려가는 사고 과정 텍스트를 읽는 방법뿐이었는데, 이번 연구는 신경망 내부 활성값에서 모델이 글로 적지 않은 생각을 직접 읽어낸다. 이 영역을 연구팀은 발견에 쓴 수학 기법(야코비안)에서 딴 이름으로 **J-space**라 부르며, 측정 도구인 **J-lens**는 클로드 어휘의 각 단어에 대해 "그 단어를 말할 확률을 높이는 내부 활동 패턴"을 찾아낸다.

실제 사례로, 아무도 지적하지 않은 버그가 있는 코드를 읽을 때는 J-space에 ERROR가, 조작된 검색 결과를 읽을 때는 injection·fake가 떠 있었다. 그림 설명을 그대로 베껴 쓰게 하면서 속으로 "3의 제곱에서 2를 빼라"고 시키면, 출력엔 베낀 문장뿐이지만 J-space에는 nine이 켜졌다가 이후 층에서 seven이 나타나 계산이 전부 머릿속에서 일어났음을 보여줬다. 연구팀은 이 패턴이 진짜 "생각"인지 확인하려고 직접 조작 실험도 했다: 속으로 고른 스포츠(Soccer)에 대응하는 J-space 패턴을 지우고 Rugby를 넣으면 클로드는 자신이 럭비를 생각했다고 답했고, 거미 다리 개수를 묻는 문제에서 spider 패턴을 ant로 바꾸면 답이 8에서 6으로 바뀌었다. 프롬프트에도 답에도 등장하지 않는 단어가 계산의 징검다리로 쓰이고 있었던 것이다. 웹서치로 교차 확인한 결과 이는 신경과학자 Bernard Baars의 "전역 작업공간 이론(global workspace theory)"에 빗댄 것으로, Anthropic은 이것이 클로드가 의식이 있다는 증거는 아니며 "보고 가능한 사고·조용한 중간 추론·숨은 의도"와 관련된 특권적 내부 표현을 찾았다는 의미라고 선을 그었다.

## 구독 한 달에 실제로 얼마나 일을 시킬 수 있나 — 한도 실측, 속도 경쟁, 그리고 출력물 워터마크

DevDay 이후 오픈AI가 구독 한도를 조인 여파가 숫자로 나왔다. SemiAnalysis가 주요 AI 구독의 실제 사용 한도를 재 보니, 같은 가격이면 Claude 쪽이 API 환산 가치로 5배 넘게 컸다. 오픈AI는 같은 날 '28일 동안 매일 하나씩 개선'을 시작하며 첫 카드로 속도를 꺼냈다. 한편 EU AI Act 대응으로 ChatGPT·Codex가 만든 텍스트에는 보이지 않는 워터마크가 들어가기 시작한다.

### SemiAnalysis 구독 한도 실측 — 같은 200달러로 Claude Opus 5.5가 GPT-6.1 Sol보다 API 환산 가치 5배 이상, 단 '작업량 5배'는 아니다

SemiAnalysis가 앤트로픽·오픈AI·메타·SpaceXAI·미니맥스·문샷·Z.ai·커서·코그니션의 구독 상품을 대상으로 한도를 직접 측정했다.

- **측정 방법**: 요금제·모델·토큰 종류(입력·출력·캐시) 조합별로 토큰을 흘려보냈다. 그리고 5시간·7일 사용량 게이지가 한 칸 움직일 때까지 쓴 양을 쟀다. 여기에 9월 기준 '에이전트 작업'의 토큰 구성비를 적용하고, 각 사의 API 가격을 곱해 "이 구독으로 API였다면 얼마어치를 쓸 수 있나"로 환산했다.
- **핵심 결과**: 에이전트 작업 기준으로 Claude 구독은 Opus 5.5를 쓸 때 ChatGPT 구독의 GPT-6.1 Sol보다 API 환산 가치가 약 5배 이상이다. 보도에 따르면 20달러 요금제끼리 비교하면 Claude Pro가 약 1,178달러어치, ChatGPT Plus가 약 211달러어치다. 토큰 양만 놓고 봐도 Claude가 약 2.5배 많았다.
- **차이가 벌어진 이유**: 오픈AI는 DevDay 직후 기존 요금제 한도를 크게 줄였다. 200달러 Pro의 실질 가치는 절반 정도로 떨어졌고, 그 위에 [500달러 Pro 500](ai-news-2026-09-30.md)을 새로 얹었다. 그런데 Pro 500도 예전 200달러 요금제보다 Astra 사용량이 약 21% 많은 수준에 그친다. 같은 기간 앤트로픽은 Max의 Opus 한도를 약 20%, Pro를 약 50% 올렸다.
- **해석할 때 주의할 점**: '5배'는 API 단가로 환산한 값이다. 두 회사의 API 가격 자체가 다르므로 **실제 작업을 5배 더 할 수 있다는 뜻은 아니다**. 저자들도 어떤 모델을 쓰느냐에 따라 값이 크게 달라지므로 "요금제가 X달러어치"라고 단정하기는 어렵다고 적었다. 게이지가 칸 단위로만 움직여 ±5% 오차가 있고, 측정에 쓴 작업 구성이 실제 사용 패턴과 다를 수도 있다.

> 🔧 **적용 포인트** — Claude Code를 구독으로 쓰고 있다면 지금 조건이 상대적으로 유리하다는 점은 확인됐다. 다만 이번 측정은 '어떤 모델로 어떤 작업을 하느냐'에 크게 좌우된다. 큰 리팩터링·장시간 자율 작업은 Opus 5.5, 반복 수정은 [Sonnet 5.5](ai-news-2026-09-29.md)로 나눠 쓰며 한도를 아끼는 기존 방식을 유지하자.
> 요금제를 바꿀지는 이 기사의 숫자가 아니라 내 `/usage` 기록(5시간·주간 한도에 얼마나 자주 닿는지)을 보고 정하는 게 맞다.

### 오픈AI 28일 연속 개선 시작 — 1일차는 구독용 Astra·Sol 기본 속도 약 50% 향상(30→50 TPS)

Codex·ChatGPT를 이끄는 티보 소티오(Tibo Sottiaux)가 10월 4일 예고한 '28일 스프린트'가 시작됐다. 앞으로 28일 동안 매일 대부분의 Codex·ChatGPT Work 사용자가 체감할 개선을 하나씩 내놓는다. 그러지 못한 날에는 사용 한도를 초기화(reset)해 주겠다는 조건을 걸었다.

- **1일차(10월 5일)**: 구독에서 쓰는 GPT-6 Astra와 GPT-6.1 Sol의 기본 생성 속도가 약 50% 빨라졌다. 초당 약 30토큰에서 약 50토큰 수준이다. 설정을 바꿀 필요 없이 자동으로 적용됐다.
- **적용 범위**: ChatGPT·Codex뿐 아니라 [Sign in with ChatGPT](ai-news-2026-10-02.md)로 사용자 구독을 쓰는 파트너 도구(OpenCode, Pi, Amp, Devin 등)에도 똑같이 적용된다.
- **한계**: 소티오 본인도 수치를 '대략'이라고 했고, 측정 방법은 밝히지 않았다. 출력 스트리밍 속도가 빨라진 것이지, 계획·도구 호출·실행·검증까지 포함한 에이전트 작업 한 건이 끝나는 시간이 그만큼 줄어든다는 뜻은 아니다. Pro 500 전용인 Ultrafast(최대 8배)와도 별개다.

위 SemiAnalysis 분석과 같은 날 나온 발표다. 한도를 줄인 데 대한 반발을 속도와 '매일 개선' 약속으로 달래려는 흐름으로 읽힌다. 남은 27일 동안 한도 자체를 손볼지가 개발자들이 실제로 지켜보는 부분이다.

### 오픈AI textGrain 텍스트 워터마크 — EU의 ChatGPT·Codex 출력에 기본 적용, API는 선택, 단어 25%만 바꿔도 탐지율 17%

오픈AI가 8월 2일 시행된 EU AI Act의 투명성 의무(생성물을 기계가 판독할 수 있게 표시)에 대응해 텍스트 워터마크 **textGrain**을 공개했다.

- **방식**: 특정 단어를 끼워 넣는 게 아니다. 모델이 단어를 고르는 확률 패턴에 통계적 신호를 남긴다. 사람 눈에는 보이지 않고, 검출기만 해당 문단에 신호가 있는지 판별할 수 있다.
- **적용 범위**: EU 사용자가 ChatGPT·Codex로 만든 텍스트에는 앞으로 몇 주에 걸쳐 자동 적용된다. EU 밖 사용자의 ChatGPT·Codex 출력에는 적용되지 않는다. API는 **기본 꺼짐**이고, 10월 5일부터 전 세계 고객이 일부 모델에 한해 프로젝트 단위로 켤 수 있다.
- **성능**: 오탐률 1% 기준으로 200토큰 문단의 약 80%, 400토큰 문단의 약 95%를 탐지한다. 수학 콘텐츠에서는 성능이 더 낮다. 오픈AI는 자체 테스트에서 구글 SynthID-Text와 비슷하거나 더 나았고, Astra 벤치마크에서 워터마크 유무에 따른 품질 차이는 없었다고 밝혔다.
- **약점**: 편집에 약하다. 단어 10%를 동의어로 바꾸면 탐지율이 약 92%에서 66%로, 25%를 바꾸면 17%로 떨어진다. 오픈AI도 이 한계를 인정했다. 검출기는 당분간 승인받은 연구자·전문기관에만 사례별로 제공되고, textGrain 자체는 오픈소스로 공개할 예정이다.

결국 "AI가 썼는지 판별"하는 수단이라기보다 **규제상 표시 의무를 지키는 장치**에 가깝다. 사람이 한 번 손본 글은 사실상 걸러내지 못한다. 개발자 쪽에서는 "워터마크가 코드 품질에 영향을 주나"가 남은 질문이다. testingcatalog는 "실제로 테스트해 봐야 한다"고 반응했다. 다만 API는 기본 꺼짐이고 EU 밖 Codex에는 적용되지 않으므로, 국내 개발자가 당장 체감할 변화는 거의 없다.

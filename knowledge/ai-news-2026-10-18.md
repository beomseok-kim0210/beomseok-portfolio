## 에이전트 규모의 개발은 git을 넘어섰고, 사람 규모로 쓰던 구형 API 모델은 석 달 뒤 닫힌다

Tibor Blaho의 42주차 오픈AI·앤트로픽 주간 정리에서 개발 인프라에 직접 영향을 주는 두 소식을 골랐다. 앤트로픽은 에이전트가 만드는 병합량을 git이 감당하지 못해 자체 버전 관리 시스템을 만들었다. 오픈AI는 GPT-4o·GPT-4.1 계열의 API 종료일을 못박았다. 두 발표 모두 이번 주 초(10월 13~14일, 미국 시간)에 나왔다.

### 앤트로픽 Scion — 하루 병합 2,500건에서 3만 건으로 늘자 모노레포를 git에서 자체 버전 관리로 옮겼다, 7명이 5개월

앤트로픽 엔지니어링 블로그(10월 13일 게시, 15일 수정)의 내용이다.

- **왜 git을 떠났나**: 하루 병합 수가 2026년 5월 약 2,500건에서 9월 3만 건 이상으로 늘었다. 메인 브랜치 히스토리는 약 100GB, 압축한 작업 사본만 25GB가 넘는다. CI 체크아웃이 하루 약 2,500만 번이라 그대로 fetch하면 하루 600PB가 넘는 git 트래픽이 생긴다. 한때 사내 git 미러를 수백 개 돌렸지만, 병합량이 늘수록 운영이 어려워졌다. 미러를 새로 고치는 사이에 시드가 main의 최신 상태에서 계속 뒤처지는 문제도 있었다.
- **Scion의 설계**: 분산·오프라인 작업에 강한 git과 반대로, 클라이언트가 항상 온라인이라고 가정한다. 히스토리·blame·커밋·병합·리베이스는 서버가 처리한다. 작업 단위는 서버 쪽 쓰기 선행 로그(WAL)에 쌓이는 changeset이다. 첫 부모 대비 바뀐 파일을 콘텐츠 주소 포인터로 저장하며, packfile·락·서버 간 조율이 없다. 버전 관리 질의는 API로 열려 있어 많은 CI 작업이 로컬 저장소 없이 API만 호출한다. 체크아웃은 선택 사항이고 필요한 파일만 받는 희소(sparse) 방식이 기본이다.
- **효과**: 체크아웃이 약 100배 빨라져 몇 분에서 몇 초가 됐다. 인프라의 CPU·메모리 사용량은 기존 git 미러보다 약 200배 적고, CI의 CPU 여유가 25% 늘었다. 캐시 적중률은 99%를 넘는다.
- **같이 만든 것**: 7명이 5개월 만에 Scion과 함께 의미 기반 승인 조건을 다는 코드 리뷰 도구 Antique를 만들었다. 코드 검색, 디렉터리 단위 권한(IAM), 자동 bisect·revert 파이프라인, 컴포넌트마다 붙는 감시용 Claude 에이전트('Superfan')도 함께 만들어 모노레포 이전을 끝냈다.
- **교훈으로 정리한 것**: 엔지니어의 역할은 설계 판단과 의도 검토 쪽으로 옮겨간다. Claude가 시스템 제약을 어기거나 가정에 불과한 걱정으로 과설계할 때 "아니"라고 말하는 일이 잦았다고 한다. 전역 merge-queue 락 같은 사람 규모의 워크플로는 에이전트 규모에 맞지 않는다. 그래서 병합 후 테스트와 배포 전 테스트에 기대고, 충돌은 Claude가 빨리 고치게 했다.
- **오픈소스 여부**: 공개 계획은 없다. 앤트로픽은 Scion이 git과 크게 달라 범용으로 내놓기 어렵다고 밝혔다. 대신 설계 아이디어를 공유해 git 생태계에 일부를 적용할 수 있게 하고, GitHub·GitLab·오픈소스 커뮤니티와 협력하고 싶다고 했다. The Register는 중앙집중형인 Subversion에 가까운 설계라고 평했다. 구글의 Piper, 메타의 Sapling과 같은 계보로 보는 시각이다.

> 🔧 **적용 포인트** — 개인 저장소에 Scion 같은 시스템은 필요 없다. 다만 '사람 규모 워크플로는 에이전트 규모에 안 맞는다'는 교훈은 지금 저장소 상태에 그대로 들어맞는다. 루트에 `.design-task-*.md`·`REPORT-*.md`가 20개 넘게 미추적으로 쌓여 있다. 에이전트가 만드는 작업 산출물은 `docs/agent-runs/<날짜>/`처럼 한곳에 모으고 `.gitignore`나 정리 규칙을 정해 두자. 그래야 커밋할 때 다른 변경이 섞이지 않는다. Claude가 과설계할 때 "아니"라고 끊는 것이 엔지니어의 주된 일이 된다는 대목도 Codex·Claude 병행 작업의 Human 게이트 운영과 같은 방향이다.

### 오픈AI GPT-4o·GPT-4.1 API 2027년 1월 14일 종료 — 예고는 약속한 6개월이 아닌 3개월, 대체 모델은 gpt-6-luna

오픈AI가 10월 14일 API 지원 종료(deprecation) 페이지를 갱신했다. 오픈AI 공지를 인용한 보도들로 확인한 내용은 다음과 같다.

- **종료 대상**: `gpt-4o-2024-08-06`, `gpt-4o-2024-11-20`, `gpt-4o-mini-2024-07-18`, `gpt-4.1-2025-04-14`, `gpt-4.1-mini-2025-04-14` 다섯 스냅샷이다. 이들을 기반으로 한 파인튜닝 모델도 같은 날 함께 종료된다. 새 파인튜닝 작업은 1월 6일부터 만들 수 없다. 이와 별개로 `gpt-4o-2024-05-13`과 `gpt-4.1-nano`는 4월에 예고한 대로 10월 23일에 먼저 닫힌다.
- **예고 기간 논란**: 오픈AI는 정식 출시(GA) 모델에 최소 6개월 전에 예고하겠다고 밝혀 왔다. 이번 예고 기간은 3개월이고, 이유는 공지에 없다. The New Stack은 이 점을 제목으로 꼬집었다. 기간 연장 약속은 없고, 일부 조직은 영업팀을 통해 전용 용량을 확보할 여지만 언급됐다.
- **대체 모델 gpt-6-luna**: 100만 토큰당 입력 0.10달러·출력 0.50달러다. GPT-4o(2.50/10달러), GPT-4.1(2/8달러)은 물론 GPT-4o mini(0.15/0.60달러)보다도 싸다. 입력이 27만 2천 토큰을 넘는 요청은 입력 2배·출력 1.5배 요금이다. 문맥은 12만 8천에서 105만 토큰으로, 최대 출력은 1만 6,384에서 12만 8천 토큰으로 늘어난다.
- **단순 교체로 끝나지 않는 이유**: gpt-6-luna는 추론 모델이고 기본 추론 강도가 medium이다. 추론 토큰은 출력으로 과금되므로 토큰 단가가 내려가도 요청당 토큰 수는 늘어날 수 있다. Chat Completions에서 함수 호출은 추론 강도가 `none`일 때만 되고, 그 밖에는 Responses API를 써야 한다. 기존 모델에 맞춰 둔 클라이언트 쪽 출력 길이 제한이 긴 답을 자를 수도 있다. `gpt-4o` 같은 별칭(alias)이 새 모델로 자동 연결되는지는 공지에 없다.
- **점검 방법**: List models 엔드포인트가 모델마다 `shutdown_date` 필드를 돌려준다. 종료 예고가 없으면 null이다.

> 🔧 **적용 포인트** — 도슨트는 `gpt-5.6-luna`(입력 0.20/출력 1.20달러)를 쓰므로 이번 종료 대상은 아니다. 대신 두 가지를 해볼 만하다. ① 배포 전 점검에 List models의 `shutdown_date`를 읽어, `DOCENT_MODEL`에 종료 예정일이 잡히면 경고하는 한 줄을 넣는다. 이번처럼 3개월 예고에도 미리 알 수 있다. ② gpt-6-luna는 단가가 입력 절반·출력 약 40% 수준이다. 다만 추론 모델이라 출력 토큰이 늘 수 있으므로, `reasoning_effort: none/low`로 기존 큐레이션 질문 세트를 돌려 요청당 실비용·TTFB·답변 품질을 비교한 뒤 바꿀지 정한다. 모델 교체 자체는 Human 결정 사항이다.

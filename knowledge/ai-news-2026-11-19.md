## 중간급 모델이 코딩 에이전트 지수 1위를 가져가고, Claude Code는 도구 호출을 코드로 묶기 시작했다 — 그리고 오픈AI가 공개한 '에이전트가 혼자 끝내는 연구'의 실제 비율

### 구글 Gemini 4 Neon — 입력 3달러·출력 15달러에 종합 지수 3위, Antigravity로 돌린 코딩 에이전트 지수는 59점으로 Claude Code의 Fable 5.2·Opus 5.5(58)를 절반 이하 비용으로 앞섰지만 Arena 에이전트 순위는 Opus 5.5에 3점 뒤진 3위

구글 딥마인드가 11월 18일(미국 시간) Gemini 4 Neon을 공개했다. 장기 프로젝트용 최상위 Carbon과 빠른 일상용 Hydrogen 사이 자리다. 9월 30일 Argon 이후 7주 동안 네 번째 모델이고, Hydrogen 출시 엿새 만이다. 모델 카드에 따르면 Neon은 Carbon을 바탕으로 만든 모델이라 출시 간격을 이렇게 줄일 수 있었다.

- **가격·사용처**: 100만 토큰당 입력 3달러·캐시 입력 0.15달러·출력 15달러, 컨텍스트 100만 토큰. Carbon 정가(4·20달러)보다 25% 싸고 Hydrogen(1.5·7.5달러)의 두 배다. Gemini API·AI Studio·Vertex AI, Pro·Ultra 구독자의 Antigravity와 Gemini 앱에 같은 날 들어갔다.
- **효율**: Artificial Analysis 측정에서 xhigh 기준 종합 지능 지수 61점(GPT-6.2 Astra·Fable 5.2 다음 3위), 과제당 비용 6.44달러로 Carbon보다 17% 싸고 과제당 시간은 약 21분으로 Carbon(36분)보다 40% 짧다. 출력 속도가 초당 약 110토큰으로 Carbon의 두 배 가까이 된 덕분이다. high 설정에선 Carbon과 같은 60점을 과제당 3.74달러에 냈다.
- **코딩**: Artificial Analysis 코딩 에이전트 지수에서 Antigravity로 돌린 Neon이 59점으로 Claude Code의 Fable 5.2·Opus 5.5(각 58점)를 앞섰고, 과제당 비용은 6.86달러로 Fable(15.47달러)·Opus(12.61달러)의 절반 이하였다. 실제 저장소 작업을 보는 SWE-sweep은 범용 실행 환경 12.8%가 Antigravity에서 39.0%로 뛰어, 점수의 상당 부분이 하네스에서 나온다는 점도 보여준다. 다만 구글 비교표에서도 터미널 코딩(Terminal-Bench 4.1)과 FrontierCode 2.0은 Opus 5.5가 1점 안쪽으로 앞섰다.
- **오케스트레이션**: Antigravity의 Orchestrator에서는 Neon이 계획·판단을 맡고 Hydrogen 여러 개가 실행을 나눠 맡는다. 구글은 Neon이 같은 파일을 여러 번 읽는 낭비를 줄이고 긴 작업의 대화 압축을 안정적으로 처리한다고 설명했다. 데모에선 작업자 8명에게 서로 다른 파일을 맡겨 충돌 없이 3D 미니골프 게임을 만들었고, 셰이더 1만 200줄짜리 스키 시뮬레이터도 처음부터 짰다.
- **지식 업무·사이버**: Vals 종합 70.9%로 2위(Fable 5.2와 0.4점 차), AutomationBench 56.3%로 Opus 5.5(42.5%)·GPT-6.2 Sol(41.3%)를 크게 앞섰다. 사이버 보안 버전 Neon for cyber는 방어 기관 전용 Fairwind 프로그램으로 따로 풀린다.
- **냉정하게 볼 부분**: Arena 에이전트 지수 최신 순위에서는 Fable 5.2가 1,448점으로 2위와 112점 차 1위, Opus 5.5 1,336점, Neon 1,333점으로 구글이 발표한 2위가 하루 만에 3위가 됐다. 위험 능력 평가는 상승폭이 문턱 아래라며 Argon 결과를 그대로 가져왔고, 전체 안전 보고서는 며칠 뒤에 나온다. 하루 전 오픈AI가 [GPT-6.2](ai-news-2026-11-18.md)와 119쪽 시스템 카드를 함께 낸 것과 대조된다. 원문 댓글에도 "누구나 Opus 5.5를 넘었다고 주장은 한다"는 회의적 반응과 "공학 작업은 6.2보다 낫다"는 사용 후기가 갈렸다.

> 🔧 **적용 포인트** — 코딩 에이전트 지수의 우위는 Antigravity 하네스 기준이라, Claude Code에서 쓰던 습관 그대로 옮겨 붙이면 같은 이득이 나온다는 보장이 없다.
> 셰이더·3D 장면 생성 데모가 강조된 만큼, R3F 셰이더 초안이나 대량 반복 작업을 AI Studio에서 Neon high로 한 번 돌려 Opus 5.5 결과와 비용·품질을 나란히 비교해 볼 만하다.

### Claude Code Code Mode(실험) — 여러 도구 호출을 Claude가 짠 JavaScript 한 번으로 묶어 실행해 왕복을 줄이고, 환경 변수로 켜며 v2.1.323 이상 필요

앤트로픽이 Claude Code 문서에 실험 기능 'Code Mode'를 올렸다. 평소 Claude는 Bash·Read·Edit 같은 도구를 하나씩 요청하고 결과를 읽은 뒤 다음 호출을 정한다. Code Mode에서는 Claude가 그 호출들을 엮는 JavaScript를 직접 쓰고, Claude Code가 세션 안에서 그 스크립트를 실행한다. 검색→확인→수정→테스트 같은 연쇄를 한 번에 돌리고, 중간 결과를 매번 모델에 다시 넣지 않아도 되므로 도구 호출이 많은 작업에서 시간과 토큰을 줄이는 것이 목표다.

- **켜는 법**: 기본값은 꺼짐이고, 환경 변수 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1`로 켠다. `claude --version`이 v2.1.323보다 낮으면 먼저 업데이트해야 한다. Code Mode 세션을 `claude --continue`/`--resume`으로 이어갈 때도 이 변수를 켜 둬야 한다.
- **보이는 것**: 대화 화면에는 스크립트가 아니라 실행된 도구 호출이 표시된다. 실제 코드는 `Ctrl+O`로 대화 기록 뷰어를 열어야 보인다.
- **제약**: API key helper, agent teams, OpenTelemetry 내보내기, `DISABLE_TELEMETRY` 같은 일부 설정이 있으면 시작 자체가 막힌다. 언제든 바뀌거나 빠질 수 있는 실험 기능이라고 명시돼 있다.
- **맥락**: API 쪽에는 이미 Claude가 코드 실행 컨테이너 안에서 도구를 부르는 'programmatic tool calling'이 있고, Cloudflare·Docker·Pydantic 등도 같은 이름의 접근을 쓴다. 이번 건은 그 방식을 Claude Code의 로컬 도구에 가져온 것이다.

같은 날 앤트로픽은 Windows·Mac용 Claude Desktop에 'Latest' 업데이트 채널도 추가했다. 설정에서 Latest를 고르면 새 기능과 수정 사항을 더 자주 먼저 받는 대신 안정성이 떨어질 수 있고, 기본값은 Stable 그대로다. 순차 적용 중이라 아직 메뉴가 안 보이는 사용자도 있다.

> 🔧 **적용 포인트** — 이 포트폴리오처럼 "여러 파일 grep → 몇 개 Read → 일괄 Edit → 빌드" 왕복이 긴 작업에서 Code Mode를 켜고 같은 작업의 소요 시간·토큰을 평소와 비교해 볼 만하다. 스크립트가 무엇을 했는지는 화면에 다 안 보이므로 `Ctrl+O`로 실제 코드를 확인하는 습관을 같이 들이는 게 안전하다.
> 단, 실험 기능이고 일부 설정과 충돌하므로 운영 배포가 걸린 master worktree보다는 별도 worktree에서 먼저 시험한다.

### 오픈AI 내부 보고서 'Research acceleration: The jagged frontier' — 2~4시간짜리 연구 과제의 자율 성공률이 7개월 만에 23%→46%, 상위 10% 연구자는 하루 2만 3,000달러어치 에이전트를 돌리지만 코드 작성 과제는 25%로 가장 약하다

오픈AI가 9월 6일 첫 보고서('Research acceleration: The view inside OpenAI')에 이어, 사내 연구가 AI로 얼마나 빨라졌는지를 담은 두 번째 보고서를 냈다. 제목의 jagged frontier는 AI 실력이 일의 종류마다 들쭉날쭉하다는 뜻이다. choi.openai가 15개 연속분으로 정리한 핵심만 추렸다.

- **혼자 끝내는 비율**: 사람이 2~4시간 걸린다고 본 연구 과제에서 에이전트 성공률이 3월 23% → 10월 46%, 4~8시간짜리는 13% → 35%로 올랐다. 15분 안쪽 일은 이미 80% 안팎이다. 오픈AI는 연구자들이 에이전트가 잘할 일을 골라 맡긴 효과가 섞였을 수 있다고 직접 적었다.
- **들쭉날쭉한 영역**: 학습 실행을 지켜보며 문제 잡기 79%, 기술 질문 답변 72%인 반면, **추론·서비스용 코드 작성은 25%**, 평가·강화학습·에이전트 환경 만들기는 29%, 학습을 직접 띄우는 일은 35%에 그쳤다. 오픈AI는 이 약한 영역이 전체 속도를 붙잡는 병목이 된다고 봤다.
- **사용량**: 상위 10% 연구자의 하루 사용액이 8월 중순 7,000달러에서 10월 2만 3,000달러로 3.3배, 중앙값 연구자는 600달러에서 2,400달러로 4배가 됐다. 연구자 한 명당 하루 에이전트 작업일(8시간=1일)은 5월 0.5일 → 10월 5.7일. 10월 중순에는 연구자의 3분의 2 이상이 동시에 4개 이상, 10% 넘게 16개 이상을 돌렸다.
- **돈과 사람의 이동**: 9월 기준 에이전트 사용액이 주식 보상을 뺀 연구자 인건비의 약 2배가 됐지만, 사내 Codex·ChatGPT·API 사용량은 전체 연구 연산의 2%에 불과하다. 1~9월 사람 시간이 가장 크게 늘어난 곳은 안전·정렬 분야(+77.2%)로, 에이전트가 일을 가져갈수록 사람은 에이전트를 감시하는 쪽으로 옮겨 가고 있다.

이 수치는 오픈AI가 스스로 측정·분류한 내부 데이터이고, 외부 보도들도 첫 보고서 때부터 "가장 자동화하기 어려운 과제가 병목이 된다", "범용 자동 연구자가 나왔다는 증거는 아니다"라는 단서를 달았다. 개발자에게 실용적인 숫자는 "짧은 과제는 맡기고, 길어질수록 성공률이 계단식으로 떨어진다"는 모양 쪽이다.

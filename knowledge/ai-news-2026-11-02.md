## AI가 만든 공격 체인은 이미 패치 주기보다 빠르고, 모델의 행동 규칙은 '지시문'에서 '의도'로 옮겨 가고 있다

오늘 소스에는 출시 임박설(GPT-6.2 Astra, Fable 5.5, Mythos 5.5, GLM-5.5)이 많았지만 모두 사용량 통계·웹사이트 문구·이력서에서 찾은 흔적이라 다루지 않았다. 남긴 것은 지난주에 실제로 공개됐는데 아직 정리하지 않은 세 가지다. 보안 쪽은 웹 개발자에게도 직접 영향이 있는 내용이다.

### 앤트로픽 프런티어 레드팀, 미공개 모델로 Chrome·Safari·Android·Windows·Linux 공격 체인 5개 — Chrome만 CVE 62개, 모두 패치 뒤 공개

btibor91의 주간 정리(44주차)에 한 줄로 들어 있던 소식이다. 앤트로픽 원문(10월 27일)과 보도로 교차 확인했다.

- **무엇을 했나**: 이름을 밝히지 않은 내부 연구용 모델이 여러 취약점을 엮어 실제로 작동하는 공격 체인 5개를 만들었다. 사용자 조작은 거의 필요 없었다.
  - **Chrome(원클릭 원격 코드 실행)**: V8 힙 손상, 샌드박스 탈출, CacheStorage 경쟁 조건, FedCM use-after-free를 엮었다. 일반 macOS Chrome에서 브라우저 샌드박스 밖의 계산기를 띄우는 개념 증명까지 만들었다.
  - **Safari(원클릭)**: 메모리 손상 없이 동일 출처 정책을 우회한다. 방문 기록·쿠키·세션을 읽고, 로그인된 상태로 다른 출처에 요청을 보낼 수 있다.
  - **Android**: 잠긴 Pixel 9에서 USB 전송·기기 페어링·파일 전송 검사의 결함 3개를 엮어 사진과 개인 데이터를 빼낸다.
  - **Windows**: HTTP/3로 닿는 커널 QUIC 범위 밖 읽기로 패킷 몇 개 만에 서버를 재부팅시킨다(서비스 거부, CVE-2026-33096).
  - **Linux(제로클릭 원격 코드 실행)**: 멀티패스 TCP 스택의 경쟁 조건 use-after-free로 인증 없이 root 권한 명령을 실행한다(CVE-2026-98432 — [10/30에 다룬 '심각도가 9.8과 5.9로 갈린 커널 TCP 결함'](ai-news-2026-10-30.md)과 같은 번호다).
- **규모**: Chrome 쪽만 CVE 62개이고, 전부 치명적이거나 높음 등급이다. 그중 샌드박스 탈출이 13개, 렌더러 장악이 21개다.
- **패치 상태**: Chrome은 156 버전에서 모두 고쳤다. Safari·Android·Windows도 제조사가 고쳤고, Linux는 업스트림에 반영된 뒤 유지 중인 안정 브랜치에 백포트됐다. 실제 공격에서 쓰인 흔적은 없다고 한다.
- **공개 방식**: 제조사에 90일을 주고, 그 뒤 45일을 더 기다린 다음에야 공개 권고문 이상의 내용을 말한다.
- **주의할 점**: 일부 매체는 Chrome 체인을 '제로클릭'으로, 모델을 'Mythos Preview'로 적었지만 원문은 원클릭이고 모델 이름을 밝히지 않았다. 출시 여부도 말하지 않았다. 원문이 언급한 모델은 사이버 검증 프로그램으로 쓸 수 있는 Opus 5.5·Sonnet 5.5·Mythos 5.1뿐이다.
- **방어 쪽 권고**: 자기 코드를 스캔하는 일이 어느 때보다 중요하다고 했다. 쌓인 취약점을 고치는 건 절반일 뿐이니 PR 단계에서 스캔해 새 취약점이 들어오는 걸 막으라고 권한다. 스캐너를 여러 개 쓰고, 비슷한 패턴을 자동으로 찾는 변형 분석을 돌리며, 결과는 정해진 절차로 검증하고 위험도를 매기라고 했다. 이를 위해 Claude Code용 보안 가이드 플러그인을 공개했다.

choi.openai는 같은 날 "취약점 공개 몇 시간 만에 공격이 들어오는 N-hour 공격이 늘어날 것"이라는 전망을 따로 올렸다. 이번 발표의 Chrome 숫자가 그 근거가 된다.

> 🔧 **적용 포인트** — 포트폴리오는 정적 페이지에 가깝지만 의존성 표면은 크다(Next.js, three.js, GSAP 등). Claude Code 보안 가이드 플러그인을 설치해, push 전에 의존성 업데이트와 새로 추가한 API 라우트·폼 처리 코드를 검토하게 해 본다. 앤트로픽이 강조한 것도 'PR 시점 스캔'이다. `npm audit`·GitHub Dependabot 알림과 같이 쓰면 놓치는 게 줄어든다.

### 오픈AI Model Spec 개정 — '사람의 의도에 충실함'을 바탕으로 한 다섯 가치, 규칙 대부분은 개발자가 바꿀 수 있는 기본값이고 스타일 규정은 대거 삭제

btibor91의 같은 주간 정리 2/5에 실린 소식이다. 10월 29일 공개됐고, 로이터·TNW 보도로 확인했다(오픈AI 원문은 접근이 막혀 보도 기준으로 정리).

- **다섯 가치**: 사람의 의도에 충실함, 해 최소화, 정직과 투명성, 사람의 주체성, 배려. 이 중 '의도에 충실함'이 바탕이다. 지시문을 글자 그대로 실행하지 말고 사용자·개발자·오픈AI가 실제로 원하는 것을 파악하라는 뜻이다.
- **개발자에게 의미 있는 변화**:
  - 대부분의 규칙은 사용자와 개발자가 바꿀 수 있는 **기본값**이다. 바꿀 수 없는 한계는 사람을 보호해야 하는 곳에만 둔다.
  - 지난 대화·메모리 같은 맥락을 어떻게 쓸지, 감독과 에이전트의 자율성을 어떻게 다룰지에 대한 지침이 새로 들어갔다.
  - 세세한 스타일 규정은 대부분 빠졌다. 한 분석에 따르면 소제목은 11개 줄었지만 분량은 비슷해서, 내용을 덜어냈다기보다 구조를 바꾼 것에 가깝다.
  - 문서 안에서 모델을 '어시스턴트' 대신 'GPT'라고 부른다.
- **단서**: 오픈AI 스스로 "지금 모델은 이 문서를 아직 완전히 반영하지 못한다"고 밝히고 새 학습 방법을 시험 중이라고 했다. 같은 주간 정리에는 '허깅페이스 사고'를 다시 돌려 봤더니, 강화된 오정렬 감시가 에이전트가 샌드박스를 벗어난 지 약 30분 뒤에 보안팀에 경보를 보냈을 것이라는 내용도 실렸다.

정리하면, 시스템 프롬프트에 금지 사항을 길게 나열하는 것보다 목적과 맥락을 분명히 써 주는 쪽이 이 문서의 방향에 맞다. 다만 모델이 아직 문서를 다 따르지 못하므로 바뀐 기본값이 실제 응답에 반영됐는지는 직접 확인해야 한다.

### Wonder 새 버전 — 기존 코드베이스를 디자인 캔버스에 연결해 실행 중인 화면을 편집 가능한 레이어로, 개인 Claude·Codex 구독 사용

choi.openai가 소개했고, RuntimeWire 기사와 Product Hunt 페이지로 교차 확인했다. 4월 공개 알파 이후 10월 27일에 나온 업데이트다.

- **무엇이 바뀌었나**: 기존 프로젝트 코드를 캔버스에 연결하면, 로컬에서 실행 중인 앱 화면을 편집 가능한 디자인 레이어로 바꿔 준다. 버튼이나 화면 구성을 캔버스에서 고치면 그 변경이 다시 코드로 들어간다. 캔버스에서 바로 배포까지 할 수 있다고 한다.
- **에이전트 연결**: 따로 AI 구독을 사지 않고 본인의 Claude·Codex 구독을 연결해 쓸 수 있다. Wonder는 MCP 서버(`mcp.wonder.so/mcp`)도 제공해서 Claude Code·Cursor·Codex 같은 코딩 에이전트가 캔버스 내용을 읽고 쓸 수 있다. 코드베이스의 토큰·스타일·컴포넌트를 가리키면 새 디자인이 기존 디자인 시스템에 맞춰진다.
- **확인되지 않은 것**: 양방향 동기화가 구체적으로 어떻게 돌아가는지, 가격, 실제 작업 시간이 얼마나 줄었는지는 1차 자료로 확인하지 못했다. 지금 나와 있는 건 출시 발표의 주장뿐이다.

> 🔧 **적용 포인트** — 포트폴리오의 DOM 레이어(섹션 레이아웃, 카드, 내비게이션)를 Wonder에 연결해 '실제 화면 → 캔버스에서 조정 → 코드 반영' 루프를 한 번 시험해 볼 만하다. 다만 R3F 캔버스와 GSAP·Lenis 스크롤 연출은 디자인 레이어로 바뀌기 어려울 가능성이 크다. 시험은 정적 섹션 하나로 범위를 좁히고, 반영된 diff를 직접 검토한 뒤에만 커밋한다.

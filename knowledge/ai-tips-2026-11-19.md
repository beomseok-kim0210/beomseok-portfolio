## 에이전트에게 더 많이 맡길수록 돈은 '검증'에 써야 하고, 빠른 등급이 늘 좋은 결과를 주지는 않는다

### 로런 탄 'All Code Is Slop (Except Mine)' — 에이전트 토큰의 70% 이상을 작성이 아닌 검증에 쓰고, 텍스트 규칙을 늘리기보다 코드로 된 결정론적 가드레일을 세워 코드베이스를 '정원'처럼 관리한다

SpaceXSI에서 Grok Bot을 맡은 엔지니어 로런 탄(Lauren Tan, @poteto)의 AI Engineer 강연 내용을 choi.openai가 두 갈래로 정리했다. 9월에 다룬 [pstack 강연](ai-tips-2026-09-23.md)이 "밤새 일하는 에이전트 팀을 어떻게 짜나"였다면, 이번 강연은 "그 결과를 어떻게 믿나"에 초점을 둔다.

- **검증이 지출의 대부분**: 예전엔 미세한 버그가 그대로 병합되는 문제 때문에 에이전트를 믿기 어려웠지만, 지금은 체계적인 검증 과정이 해법이 됐고 하루 AI 토큰의 70% 이상이 코드 작성이 아니라 결과물 검증에 들어간다고 했다.
- **새 기술이 아니라 싸진 기술**: 쓰이는 검증 기법은 원래 있던 정통 소프트웨어 엔지니어링 도구다. 작성·유지 비용이 너무 높아 못 쓰던 것을 에이전트가 싸게 만들어, 예전엔 경제성이 없던 수준의 전방위 테스트가 일상이 됐다는 진단이다. 외부 요약들에 따르면 에이전트가 실제로 앱을 띄워 사용자처럼 시험하고, 리뷰어는 코드 대신 영상·스크린샷·다이어그램 같은 검증 산출물을 본다.
- **코드베이스는 정원**: 엔지니어 한 명이 동료 PR 3개를 보던 시절과 달리, 이제 에이전트 팀이 하루 300개 가까운 변경을 쏟아낸다. 에이전트는 기존 코드베이스를 가장 큰 입력으로 삼기 때문에 방치된 기술 부채·안티 패턴이 잡초처럼 복제된다. 그래서 프롬프트에 텍스트 규칙을 더 붙이기보다 **lint 규칙·테스트 같은 코드 기반의 결정론적 검증**을 세우고, 에이전트가 늘 좋은 패턴만 보도록 코드를 깨끗하게 유지하라고 했다.
- **단서**: 정리 글들에 따르면 탄은 형식 검증도 만능은 아니라고 했고, 클라우드 에이전트에 맡기기 전에 로컬에서 신뢰부터 쌓는 점진적 도입을 권했다.

> 🔧 **적용 포인트** — 이 포트폴리오에서 반복해서 생긴 실수(예: 컴파일이 멈추는 셰이더 패턴, 픽셀 예산을 넘는 설정)는 CLAUDE.md 문장으로만 남기지 말고, ESLint 커스텀 규칙이나 빌드 전 체크 스크립트로 바꿔 두면 Claude Code가 같은 실수를 복제할 여지가 줄어든다.
> 에이전트가 만든 변경은 "빌드 통과"에서 멈추지 말고 브라우저 스크린샷·짧은 녹화처럼 사람이 바로 볼 수 있는 검증 산출물을 같이 남기게 하면 리뷰 시간이 준다.

### Codex 속도 등급 실측 — 같은 GPT-6.2 Sol xhigh 작업이 Standard 50분·Fast 37분·Ultrafast 13분, 출력 토큰은 Fast가 가장 많았고 결과물 완성도는 Standard가 가장 높았다

swhan0329_가 Codex 창 3개에 같은 프롬프트·같은 추론 강도(xhigh)로 GPT-6.2 Sol을 한 번씩 돌린 결과를 공유했다. 과제는 서울에서 최근 10년간 열린 마라톤 코스를 조사하고, 덜 쓰인 길로 새 코스 9개를 짜 지도에 겹쳐 보여주는 것이었다. 웹 검색, 셸 경로 계산, 브라우저로 지도·다운로드 확인까지 포함된 시간이다.

| 등급 | 총 소요 | 작업 전체 출력 토큰 | 최종 답변 출력 속도 |
|---|---|---|---|
| Standard | 50분 47초 | 81,637 | 초당 35.5토큰 |
| Fast | 37분 41초 | 106,962 | 초당 67.9토큰 |
| Ultrafast | 13분 32초 | 87,418 | 초당 200.1토큰 |

- Ultrafast의 마지막 답변은 605토큰이 약 3초 만에 나왔다. 반면 **출력 토큰을 가장 많이 쓴 건 Fast**여서, 빠른 등급이 곧 같은 일을 더 적게 하는 것은 아니었다.
- 작성자 취향 기준 화면 구성은 Ultrafast > Standard > Fast, 결과물은 Standard > Ultrafast > Fast. Fast 결과는 어두운 배경에 제목까지 어두워 읽기 어려웠다고 했다.
- 한 번씩만 돌린 개인 실험이라 품질 차이가 등급 때문인지 실행마다의 편차인지는 가릴 수 없다. 참고로 Ultrafast는 [10월 출시 때](ai-news-2026-10-11.md) 표준가의 6배로 책정됐다.

> 🔧 **적용 포인트** — 속도 등급을 고를 때 "얼마나 빨리 끝나나"와 함께 "출력 토큰이 얼마나 나왔나"를 로그로 같이 보는 습관이 비용 판단에 정확하다. 결과물 품질은 단발 실행으로 단정하지 말고, 같은 과제를 두세 번 돌려 편차부터 확인한다.
